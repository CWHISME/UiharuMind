# 工具纪律段按需写，不再挂了工具就得有

ADR 0017 起的口径是「挂了工具就得有纪律段」。改为**按需**：只有单个工具的描述装不下的东西才写纪律段——
跨工具的分工（这件事归哪个工具、先搜后读、先读后改），或者实机见过、工具边界又兜不住的误用。
工具自己做什么、怎么填参数，归工具描述与参数说明，纪律段不再复述一遍。

## 为什么改

「一条规则只放一层」与「挂了工具就得有纪律段」是打架的：一个工具若没有跨工具的策略可讲，
它的纪律段只能把工具描述换个说法再说一遍，每轮付两遍钱，改了一处另一处还会走样。
联网、识图两段就是这样被注释掉的——联网那段只说了「先 `WebSearch` 再 `WebFetch` 取正文」，
两个工具的描述各自已经说清；识图那段复述的是工具描述，后来工具改名，它还指着旧名 `AnalyzeImage`。
生图、看图从挂上起就没有纪律段，也没见因此用错。

命令行纪律段是按需的正例：它补的是文件工具清单里根本没有的移动、改名、删除（ADR 0017 第七节），
不写的话模型会拿 `Write` 重写全文去做一次挪动。

## 后果

- 联网、识图两段连同正文与标题常量一并删除；新挂的工具默认不配纪律段，要配先说清它讲的是哪条跨工具的事。
- 「纪律段里指名的工具判据取装配结果」那条不变量不受影响：它管的是写了的段，不管该不该写。
