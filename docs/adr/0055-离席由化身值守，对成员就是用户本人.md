# 离席由化身值守，对成员就是用户本人

> **状态**：accepted，**已实现**（2026-10-02 拷问定稿、当天落地；实现时补定的见文末「实现时定下的」）。起因见
> [2026-10-02 真实档案五段长跑实测](../perf/2026-10-02-真实档案五段长跑实测.md)「问题三」。

成员按场景段的规矩把拍板留给用户（ADR 0049 / `GroupTranscript.BuildScene`），用户不在时每段后半程都在空转
——每人说一句「等他回来拍」就收住这一波。智能体群加一个可选的**离席**：用户显式打开后，由**化身**
（用户卡 + 智能体能力的一份会话，挂在群壳上、每群一份）在**每一波结束时**醒来，替用户拍板，并对照目标决定接着推还是停下。

## 决策

1. **化身代表用户，不是又一位成员**。它不进在场名单；它说的话进群流水、对成员**就是用户说的**（投递标用户名，
   唤醒按用户发言算），「化身」标记只画给用户看。场景段与「方案由用户拍板」一字不改。
2. **只管拍板与要不要接着做**。派活、点名仍归主持人与成员；化身不吞掉主持人，也不改唤醒边界。
3. **叫醒时机**：离席期间每一波结束都叫醒一次（包括用户本人开的那波），另外成员遇到审批时叫醒做一次**旁路判断**
   （在它自己的会话上下文里做，不算一轮、不进历史，只在回执与成员会话里留痕）。
4. **结束离席走专用工具**（达成 / 需本人 + 摘要），不靠文字标记；正文就是一条群发言，开下一波。
   **其余结局都不结束离席**：没给出下文（`[沉默]`、空回复、撞轮数上限、只说「先这样」）、出错、空推（它开的波没人接话）
   统称**没进展**——`# 化身` 段明说「只有推进或调工具结束两种结局」，没进展后的那次投递末尾再点一次上次的情况；
   兜底是**延迟唤醒**，间隔逐次翻倍、有封顶（起点与上限放设置），一有进展归零。审批旁路判断失败则那条当场拒绝并记账。
5. **权限与群一致，不另加机械限制**。成员的审批与化身自己的审批都由化身点，**越界写入除外**——化身不替用户点，那一条当场拒绝并记账，离席照常；
   硬规则要守的是「工作区外的盘模型不能自己动」，拒绝已经守住，不必为一条（常是路径写坏）停掉整个离席。
   真非写不可，由化身调工具按「需本人」结束。
6. **目标走群发言，不进系统提示**。开离席时用户那句话标「离席目标」发进群；改目标就再说一句。
   化身系统提示里的 `# 化身` 段只放永远不变的规矩（拍板前核实读数与 diff、不按多数意见盖章、用户最新的话优先、用工具结束离席），
   开关离席、改目标都不重建装配。
7. **只能手动关**。用户发言算追加指示、不结束离席；离席中点群「停止」只停这一波，按固定延迟（默认 5 分钟、放设置）再唤醒化身，
   倒计时里可立即唤醒或结束离席，用户一发言就取消；三道保险丝（时长、化身出手次数、连续没有新产物的波数）放设置、默认很大；
   停下就停在原地，出离席回执，通知只走托盘角标与应用内提示。离席状态只在内存，**重启即结束**。
8. 只在智能体群里有；串行、并行都支持（挂在「一圈 / 一波」结束点上）。

## 考虑过的

- **代拍（只填留给用户的决定）**：碰到「没人提问但活没做完、人人回 `[沉默]`」照样停住，达不到持续流转。
- **推进负责人（每波由它派活、判断进度）**：与主持人重叠，要重写唤醒边界。
- **对成员明示是化身**：成员会回「这是化身拍的，等本人确认」，又回到空转；场景段还得为它开例外。
- **目标与备注进系统提示**：每次开关、改备注都让化身整段历史的前缀缓存失效；只投给化身则让它沦为传话筒，成员不知道往哪干。
- **离席白名单 / 只读化身**：用户要它能动手收尾，且「权限与群一致」就够；硬限制的代价是 AutoEdit 下成员连提交都过不去。
- **空闲检测自动接手 / 用户一发言就结束离席**：前者会在用户倒杯水的工夫替他拍板；后者被否，用户要的是离席中能顺手追加指示。
- **没进展就停下等用户**：用户要的是持续流转；提示词单靠不住（成员的 `[沉默]` 实测一次没用上），
  退避兜底既能等过 429，又压得住模型反复回空的花销。
- **离席中点停止 = 结束离席**：用户多半只是想插手看一眼；不关离席又不唤醒则多出「离席但没人值守」的半状态，故改为固定延迟唤醒。
- **离席落盘、重启续跑**：等于没人点过开始时群在自己花钱；与 `_interrupted` 只在内存同口径。

## 后果

- 协调器要新开一个「一波结束」的事件（现在没有，挂点在 `GroupChatCoordinator.RunEpisodeAsync` 收尾之后）。
- 化身复用成员会话的投递、游标、裁剪与 `GroupMemberTurnGate`；离席中可以私聊它。
- 用户回来看到的是离席回执：为什么停、替他拍了哪几次（可跳到原发言）、点了哪些审批、自己做了什么；推翻就像平时一样在群里说。

## 实现时定下的（2026-10-02）

1. **化身的身份载体是内部智能体卡 `GroupAvatarAgent`**，不是用户卡本身：用户卡开不了会话、也没有工具配置。
   卡上开「注入用户卡」（`InjectUserCard`），于是「用户是谁」照旧来自用户卡；卡的人格正文就是 `# 化身` 的规矩（决策 6）。
   会话标 `IsGroupAvatar`，也挂 `GroupId`——轮次闸、权限、工作区、草稿目录、级联删除照成员走；名单、场景段、发群工具另算。
2. **化身的场景段是专门一份**（`GroupAvatarTranscript.BuildScene`）：在场成员全列、不列「（用户）」，「你是谁」写成替用户坐着；
   成员那份的「只说新的」「拍板归用户」不给它。
3. **新建或再次离席时，化身至多补最近 30 条群发言**（`GroupAvatar.InitialBacklog`）：老群流水可能很长，第一份投递不能撑爆上下文。
4. **审批的旁路判断用化身自己的系统提示、不带它的会话历史**（`AvatarApprovalJudge`）：系统提示就是化身卡的规矩加注入的用户卡，
   末尾交代「替用户点一次审批」；上下文给用户离席以来亲口说过的话（从最近一句离席目标起，后说的优先）与群里最近 20 句——
   拍过的板已经在群里，不必为一张审批把它整段历史再发一遍。模型答「批准」开头才算批；判不出、超时一律拒绝。
   连着三批一条都没批，收掉那位成员这一轮（与等用户点时同口径）。
5. **「一波结束」事件**是 `GroupChatCoordinator.EpisodeEnded`，在群报空闲之后发，带开波来由、群流水区间与是否被停；
   空推 = 化身那句开的波、成员一句没说。化身一轮跑在协调器里（`RunAvatarAsync`），群的「停止」也停它。
6. **化身跑着时又有一波收场**（多半是它自己那句开的）：记下，跑完立刻再叫；延迟唤醒到点时群若正在跑，等那一波收场再叫。
7. **离席回执是群流水里一条只给人看的记录**（`_groupAwayReceipt` 标记，内容是回执 JSON），投递与审批判断的上下文都跳过它；
   界面画成旁白。「跳到原发言」没做：回执里只列了化身说过几句，原发言在群流水里本来就带「化身」署名。
8. **化身的入口在右栏离席块**（「打开化身」），没有在成员列表里另占一行；离席结束后照样点得开、可以私聊。
9. **倒计时里用户一发言就取消**：协调器在用户本人发言时先通报 `UserPosted`（化身替用户说的不算），离席取消倒计时，
   由他那一波收场时叫醒化身，没进展的提示留着随那次带上。
10. **停止优先于化身已说出的话**：化身一轮被停就按「被停」算（排固定延迟），被停之后它再说完的话不进群，不让一句迟到的话绕过停止再开一波。
11. **进展 = 成员接了话或落了新产物**，退避据此归零；被用户停下的那一波不算「没有新产物」。
12. **离席结束要等化身那一轮停稳才出回执**：结束时化身还在跑，就先摘掉登记、取消它，回执等它停下再出——免得边读它的历史边被追加。
13. **授权范围**（2026-10-02 补）：开离席时可另填一段只给化身看的话（如「原语级改动可以替我拍」），成员看不到、⛔ 不进群流水。
    起因是长跑实测：目标会发给全群，写进目标的授权被成员读成给自己的（「黑猫离席，这两格我代拍」），写「交给我拍」又被化身照字面读成用户本人。
    它**每一轮都附在化身投递末尾**（没进展的提示之前），不只第一轮：化身的历史跨离席保留，只发一次的话换一次离席就分不清哪份作数，长离席里那一条还可能被压缩折掉。
14. **两处没做**：
    - 托盘不为「离席结束」另出一态：要新做几套图标资源，而化身与成员在跑时托盘本来就亮着「运行中」；离席结束只发应用内提示，回执落在群里。
    - 离席开始前已经卡在等用户点的审批不转给化身：能点「开始离席」说明用户此刻就在，那几张卡顺手点掉；离席期间新冒出的审批都归化身。
