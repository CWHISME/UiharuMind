# 主子代理基座与人格段收拢，人格锚段只装主代理

> **状态**：已落地（2026-10-06，绢旗主刀；Core 1846 过 / 5 红与基线一字不差，
> 失败集合=既有 5 个群场景文案旧账，非本任务引入；食蜂终审通过、CWH 拍板提交，本稿转正）。
>
> 会审结论记录：**A 不挪、B 切刀 A、标题包（复用 `CharacterSection`）、基座主子共用、
> 「你一直是你」双轨注入（点名/主代理→人格段，匿名→`# 角色` 段首句）、「不编」留**。
>
> 修订 [ADR 0005](0005-系统提示词的顺序由我们拼，人格在最前.md) 的后续记录与
> [ADR 0030](0030-主子代理提示词共用一套段落编排.md) 的段清单口径，不改两者正文。

## 背景

主代理（`AgentInstructionsComposer.Compose`）与子代理（`SubAgentAssembly.BuildSubAgentInstructions`）
两套系统提示从两条独立装配链拼出：工具纪律、MCP、工作区指针早已共用（0030），但整段编排仍各写各的，
且人格内容散在三处——

1. **开头**：`# 你是谁` 角色段里的人格正文（`CharacterPromptBuilder.Build` 的 Template＋用户卡）；
2. **末尾**：`# 记着` 人格锚段（`PersonaAnchorSection`，`CharacterData.GetPersonaCoda` 的产物；空串不写该段）；
3. **群聊每轮**：动态重锚（`GroupTranscript.VoiceReminder`，coda 贴进投递、不进前缀，`GroupChatCoordinator`）。

0005 的「后续」节只记了基座层落地与对话模板退役，**没有记人格锚段**（`# 记着` 是 0048 改名后
独立成段、由 `AgentOptionsFactory` 在 `Compose` 末尾注入的），这条链本文补上。

另有一处欠账：`AgentBasePrompts` 注释自称「抄自 v8 §0、两边同步」，但现状只有「不编」一条、
v8 §0 有整组规则；且基座原本**只注入主代理**，子代理没装。

## 决定

1. **子代理侧收拢三处**（`SubAgentAssembly` 落地，锚段语义钉死）：
   1. **persona 走 `CharacterSection`**：原 `list.Raw(named, persona)` 裸贴改为
      `CharacterSection(persona)`——裸卡补「# 你是谁」、卡自带一级标题（预填的 `# 工作循环`、
      自写的 `# 角色`）原样，不补插。标题口径与主代理同一实现、一处定义。
   2. **fallback 分支对齐**：能力裁到零时 `fallback.Instructions = persona` 那条，改为
      「persona（带标题）＋ `# 角色` 段」同一身份形状，工具纪律不拼（没工具，拼了是误导）；
      身份段正文抽成 `BuildIdentitySection`，正常装配与 fallback 共用。段内「# 角色 标题→正文」
      分隔与正常路径 `list.Section` 一致（`\n`，非 `\n\n`）；段间空行保留。
   3. **「子代理不装人格锚段」钉死**：`BuildSubAgentInstructions` 注释写明理由
      （回锚是主代理/群成员专有的 recency 手段，子代理拿的是任务书），另加不变量测试
      `SubAgentInstructions_OmitPersonaAnchor` 双保险。
2. **基座主子共用**：子代理 `BuildSubAgentInstructions` 在 persona 之前注入
   `AgentBasePrompts.Base`（`list.Raw(true, Base)`）——基座恒最前、与主代理同一条注入路径
   （主代理 `Compose` 本就第一段拼 Base，零改动）。**普通角色仍不装**（没工具，基座里
   「落盘/查文件」没法兑现）。
3. **基座净化**：`AgentBasePrompts.Base` 从 2 条（不编 + 你一直是你）补齐到宿主事实＋ 6 条编号规则（不编 / 读到的不算数 / 拍板就做不说假话 / 不隐瞒风险 / 落盘与不可逆先问 / 隐私不复述），与 v8 §0 两边同步。
   **「不编」留**——这是工具型实证纪律（说文件/代码/数据里有什么，要么亲眼看过要么说明是推测），
   不是 v8 §0.2 表格里「删/模型自带」的通用版；模型不会自带这条，删了是行为回退。
4. **「你一直是你」双轨注入**（从基座挪进人格段，与 3 同一批提交、不留空窗）：
   - 主代理 + 点名子代理：`CharacterSection(characterPrompt, YouStayYou)` 在「# 谁是
     你」标题之后、persona 正文之前插 `YouStayYou` 常量（一处定义，三用：主代理 Compose、
     子代理点名、子代理 fallback）。
   - 匿名子代理：没有人格段，走 `BuildIdentitySection` 匿名分支首句——`# 角色` 段开头
     先钉口吻，再是匿名身份句。
   - **不变量**：两档都得有「你一直是你」落点，否则这句只钉一半、刚收的口径又裂开。
5. **A 不挪**：人格正文不从 `# 你是谁` 挪进末尾锚段。现状三条腿已覆盖 43k 教训
   （开头 primacy＋末尾 coda 吃 recency＋群聊每轮重锚），挪是拿小模型开场身份去换工具纪律的
   primacy，且要动基座末句、工作区指针引用、用户卡插入点三处咬合——0005 的 1.16.0 实测已否过，不重开。
6. **B 切刀 A**：「子代理不加」= 不加人格锚段，点名的 persona 全文照旧。装配层现状即如此
   （子代理链从头到尾没碰过 `GetPersonaCoda`/`PersonaAnchorSection`），本次只把语义钉死。
   刀 B（连 persona 全文都不加，抹平点名/匿名）不切。
7. **不动的**：0005 代价节两条不变量测试（人格在工具纪律之前、工作区规矩在工具纪律之后）原样保留；
   0030 段序同构测试语义不变；0003（角色档取 Template）与 0004（工作循环预填）不碰。

范围说明：会审草案第 1 条曾写「两档共用一份段清单、只差开关」，实际落地更窄——子代理侧本就使用
`PromptSectionList`（0030 立制），本次不新建跨档清单，只做上述收拢；「两档同构」指段序口径与段落
实现共用（含 `CharacterSection`、`BuildIdentitySection`、基座注入路径），不是单一清单。

## 测试变化（预期，非回归）

- `SubAgentInstructions_OmitPersonaAnchor`：新增，锚段缺席不变量。
- `NamedSubAgent_PutsItsPersonaFirst`：改为相对顺序断言（基座在场、人格紧跟其后），与主代理
  `AgentAssemblyFacts` 同口径。
- `AgentInstructions_CardOwnHeadingIsNotDuplicated`：断言更新为「标题在场、不补 # 谁是
  你、`YouStayYou` 插在标题后正文前」——lead 一插即断原「标题行\n正文」连续断言，是落法 A 的
  预期行为。
- 非本轮段落（工具纪律/场景/工作区/coda）不动，主代理角色段仅动一行（基座净化预期改动）。

## 文档同步（随本 ADR 落地）

- `docs/CONTEXT.md` 顺序节：顺序行补 `# 记着`（人格锚段，自有段末位，provider 段之前）；
  基座适用范围改为「主代理与子代理共用；普通角色不装」；指认关系补基座共用与双轨落点。
- 提案 v8（`docs/proposals/代理人格化/角色提示词_v8.md`）：
  - §7.4 补双轨重锚记录——原文「每轮贴到对话区、不碰前缀、唯一合法位置」只写动态重锚一条腿；
    前缀锚段（`# 记着`）自 0048 改名起已存在，两腿并存，以本文为准。
  - §0.1 补「不编」一条（工具型实证纪律，两边同步欠账补齐）；§0.2 表格「不编造/不确定」行加注
    区分「通用版（删/模型自带）」与「工具型变体（留/已写 §0.1）」；基座适用范围与「你一直是你」
    双轨落点补注。
- 0005 与 0048 正文均不改（先例：0015 口径「保留当时的记录不改」），被指认关系写进本文。

## 验证判据

- Core 全量：装配相关测试全绿；**失败集合与合并前基线一字不差**（基线记录见群内
  `提示词合并-审基线记录.md`，既有 5 个群场景文案红为非本任务旧账，不增不减）。
- 不变量测试逐条过一遍并留痕（锚段缺席、双轨「你一直是你」、基座恒最前、段序同构）。

## 代价

- 0030 的「两份平行散文改一处静默走样」防线多覆盖一个开关面（锚段 ✗ / 标题包 ✗ / 双轨落点是
  开关不是段删减），同构测试要钉住「关掉的段不出现在输出里」，不能只钉段序。
- 基座从主代理独占变主子共用，普通角色边界靠「没工具不装」维持——将来若普通角色开工具，
  这条边界要重审。
