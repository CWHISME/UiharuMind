# 目录提示词不写绝对路径，正文简写由界面按会话解析

> **状态**：accepted（2026-10-10）。修订 [ADR 0017](0017-提示词散文改中文，搜索失败改结构化.md) 第二节落地时留下的「工作目录段写明绝对路径」，
> 以及草稿目录段「正文链接用完整 `file://` 前缀、不认简写」的口径。

## 背景

工作目录、草稿目录、记忆目录原是三段，各说各的：工作目录段写绝对路径；草稿与记忆只教 `$DRAFT` / `$MEMORY` 简写，
但草稿段又给出一条完整的 `file://` 前缀，要求回复正文里引用文件时写全路径。

实机看到的是：提示词里给了绝对路径，模型就照抄它去操作。与 `AgentPathResolver.ToPortable` 回显简写是同一个道理——
给什么，它就抄什么。而当初写明工作目录，是为了治「编出 `root: "/path/to/project"`」，那个病根是提示词对路径只字未提，
「路径默认相对」这句补上之后，根在哪模型并不需要知道。

## 决定

**一、三段合成一个「目录」段，不写任何绝对路径。**
工作目录只说「命令和文件工具以它为基准，默认写相对路径」；`$DRAFT`、`$MEMORY` 统一说一次「已注入的环境变量，
工具参数和命令行里直接写简写，工具结果里也是简写」；草稿与记忆各留一条自己的事实。三条仍按原条件各自出现。
shell 关掉时模型查不到绝对路径，这是有意的：只有文件工具时它用不着。

**二、回复正文里也写简写或工作区相对路径**，图片 `![说明]($DRAFT/x.png)`，其他文件 `[说明]($DRAFT/x)` 或 `[说明](src/a.cs)`。
正文的简写固定写 `$DRAFT`，不随 shell：它是给界面解析的，`%DRAFT%` 写进 markdown 地址会被当成百分号转义。

**三、由界面在显示时按会话解析，历史原样存简写。**
- 会话的 `AgentPathResolver` 经继承附加属性 `MarkdownPaths.Resolver` 挂在消息流外层，气泡顺着树拿到。
- 链接：点击时解析（`SimpleMarkdownViewer.OnLinkClick`）。目录照旧交系统打开。
- 图片：渲染库只会把相对地址与 `ImageBasePath` 拼接。基准给草稿目录下一个**永不存在的哨兵目录**，
  拼出的路径由自家本地文件加载器（`MarkdownPathImageLoaderHandler`）还原成真实路径；落在哨兵外面的（写了绝对地址的旧消息）原样用。
  哨兵挂在草稿目录下，拼出的地址每个会话不同，图片缓存不会串。
- 只用渲染库公开的扩展点（`ImageBasePath`、`AsyncImageLoader.Handlers`），**不改库**。加载器经样式挂上，
  而库在图片进树前就设了地址，所以加载器换上时要把地址重设一次触发重载。

## 否决的方案

- **落盘时把简写展开成 `file://`**：模型下一轮在历史里看到的就是全路径，又会去抄。
- **落盘展开 + 发送时投影回简写**（仿 [ADR 0053](0053-ViewImage发送时投影，历史只存路径.md)）：可行，但要动历史与发送两条主线，
  只为了换来少见场景（换工作区、复制出去）的正确性，不值。
- **给渲染库加一个地址解析钩子**：要自己维护一份分叉。

## 代价

- 会话中途换工作区，草稿目录跟着变，旧消息里的 `$DRAFT/…` 指到新房间，原文件点不开、图显示不出。
- 复制出去的正文里是简写，在别处没有意义。
- `$MEMORY` 不在正文里给用户看，提示词不教。
