# 远程模型候选来源改用运行时模型目录，做成通用能力

> **状态**：accepted（2026-10-26）。

## 背景

远程模型预设（Agnes / DeepSeek / Sensenova / 智谱）把模型 ID 候选写在
`BaseRemoteModelConfig.ModelIdVariants`（变体表）里，经 `RemoteModelConfigRegistry` 登记。
服务商模型一多（如 Command Code Provider API 有 90+ 个模型、还在持续增减）写死就不可行：
目录天天变，写死即过期，编辑窗口里看到的候选永远落后于现实。

Command Code 的模型目录是公开的：`GET https://api.commandcode.ai/provider/v1/models`
无需鉴权即返回 200（实测 93 个模型），每个模型带 `id`（请求时原样发送）、`name`（显示名）、
`context_length`、`supported_endpoints`（该模型答在哪条线：`/chat/completions` 或 `/messages`）。
带 key 请求（用户免费 key 实测）返回同样的五字段，没有能力标记。

## 决定

1. **新增「模型目录」机制**：编辑窗口切到支持目录的服务商时，从 `/v1/models` 拉候选填充模型 ID
   下拉。映射：`id → ModelId`、`name → 显示别名`、`context_length → 上下文预填`。其余能力
   （视觉、输出预算等）目录不给，维持现有表单手填。
2. **通用能力而非专用预设**：自定义配置新增可选「模型目录地址」字段 + 「拉取」按钮；
   CommandCode 预设只是预填了该地址。OpenRouter、SiliconFlow 等同样有 `/v1/models` 的服务商
   以后免写代码。
3. **本地缓存优先**：拉到的目录落盘（`Cache/ModelCatalogs/`，语义同 `McpToolCatalogs`：
   可再生、用户可随手删、离线可读）。进入编辑窗口先读本地缓存展示，再后台自动拉一次：
   成功则覆盖缓存与列表，失败则保留缓存并提示；「拉取」按钮随时手动覆盖。
4. **候选下拉随输入过滤**：按 id / 显示名忽略大小写子串过滤，空输入显示全量；仍允许手输任意
   ID（现有路径不变，手输不经过候选）。
5. **wire 字段预留**：`BaseRemoteModelConfig` 增加序列化的 `ApiFormat`（默认 `ChatCompletions`），
   目录解析时按 `supported_endpoints` 写入；v1 只实现 chat/completions 线，
   只有 `/messages` 的模型（Claude 系）先过滤不显示。二期接 Anthropic 时数据模型不动。
6. **不做能力补表**：目录接口不携带视觉/推理等能力标记，v1 视觉走现有的 `IsVision` 手动复选框，
   不维护「已知模型能力」小表。

## 取舍

- **专用预设 vs 通用能力**：选了通用。拉目录本来就是一个独立小类，表单多一个可选地址字段
  成本很低，却能一次消灭「下一家服务商又来找你加预设」这类需求。代价只是改动面略大。
- **接不接 Claude（Anthropic 线）**：v1 不接。Anthropic Messages 是另一条传输线，
  app 侧请求改写、SSE 清洗、响应修复、限流闸整条都是 chat/completions 口径，双线并行是
  另一坨工程。wire 字段先留好，二期接时数据模型不动。
- **能力小表补视觉**：否。补表又回到写死，模型一更新表就过时；复选框足够。
- **目录缓存 TTL**：否。按用户口径「优先读本地保存记录，下一次点拉取覆盖」，不做自动过期。

## 已知代价

- 编辑窗口多一次网络请求与本地缓存读写；自动拉取失败且无缓存时，候选下拉为空、靠手输兜底。
- 本地缓存可能留着已下线的模型（目录变动后未点拉取），以手动拉取为准。
- 思考档位参数（`thinking`/`reasoning_effort`）在 Command Code `/chat/completions` 上是否被
  接受**未验证**——用户免费 key 余额为 0，连免费模型也报 `400 insufficient credits`
  （文档要求账户至少 $1 余额）。验证代价：一次带 key 且有余额的请求。
- 免费模型（`*:free`）与付费模型在同一目录里，不区分展示；是否区分留给后续。

## 本期不做

- Anthropic Messages 线（Claude 模型）。
- 视觉/能力小表与目录条目的能力标记。
- 目录缓存 TTL、自动过期、按计划过滤（Go/GOAT/Pro 各有 per-model 配额，目录不区分）。
