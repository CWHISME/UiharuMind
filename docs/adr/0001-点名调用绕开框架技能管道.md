# 点名调用绕开框架的技能管道

Agent Framework 的 `AgentSkillsProvider` 只实现了一条触发链路（模型读广告列表 → 调 `load_skill`），
没有「用户显式点名」这一条。我们决定**自建点名调用，把 SKILL.md 正文直接注入本轮对话**，
而不是注入一句「请使用 X 技能」让模型去调框架的 `load_skill`。

## 为什么（框架事实，都是逐个 decompile 验过的，1.16.0）

1. **过滤即隐藏，且隐藏即不可加载。** `AgentSkillsProvider.ProvideAIContextAsync` 每轮只调一次
   `GetSkillsAsync`，拿到的那份列表**同时**被广告文本生成与 `load_skill` 的闭包捕获。
   于是被 `FilteringAgentSkillsSource` 滤掉的技能，`load_skill` 也会返回
   `Error: Skill 'X' not found.`。想「藏起来但仍可点名」，就不能依赖 `load_skill`。
2. **广告列表没有逐技能开关。** `SkillsInstructionPrompt` 的 `{skills}` 只能整段替换，
   每个技能一行 `name` + `description` 由框架拼死。
3. **未知顶层 frontmatter 键被静默丢弃。** 解析器顶层只认 `name`、`description`、`license`、
   `compatibility`、`allowed-tools`，外加一个 `metadata:` 缩进块；`disable-model-invocation`
   写在顶层会被匹配到、然后落空丢掉——技能照常加载，只是标记消失，不报任何错。
   而生态（Claude Code 及其技能市场）**一律写在顶层**，没有人写在 `metadata:` 下。
   因此 `SkillCatalog` 两处都读，顶层那份自己从 `GetContentAsync()` 的原文里捞
   （文件技能原文已在内存，该调用同步完成、零 IO，可用在同步的过滤谓词里）。
   只读 `metadata:` 会让别处拿来的「仅点名」技能悄悄失去声明、照常被模型自选。
4. **附件与脚本工具同样受限。** `read_skill_resource` / `run_skill_script` 只在
   `AgentSkillsProvider` 挂着、且技能在 source 列表里时才管用。被藏起来的技能靠它们一个也拿不到——
   所以注入的正文要附上技能目录绝对路径，让模型用通用文件工具与 `run_shell` 自己读、自己跑，
   并明确要求它别去调技能工具。
5. **`GetContentAsync()` 返回的不是纯原文**，而是原文后追加了 `<available_resources>` 与
   `<available_scripts>` 两个块。注入时保留它们：那正是模型需要的附件与脚本索引，
   且与 `load_skill` 的返回一致。

推论：一旦决定支持「仅点名可达」的技能，框架那条链路就必然够不着它。自建注入不是绕远，是唯一直路；
顺带它还完全不碰 `HarnessAgentOptions`，因此不影响「角色扮演档零注入」那条不变量。

## 考虑过并否掉的方案

- **注入「请使用 X 技能」让模型自己调 `load_skill`。** 被藏起来的技能它找不到（见事实 1），
  两类技能行为不一致；且多费一个往返，本地小模型可能干脆不调。
- **给「仅点名可达」的技能自建 `AgentSkillsSource` 并自拼广告文本。** 在「点名也走 `load_skill`」
  的前提下才需要，而注入正文之后这层管道就是纯多余。
- **正文只管一轮（带 `_attribution` 注入、不落盘）。** 最省 token，但多轮流程型技能第二轮就失效。

## 后果

- 正文**常驻会话历史**并每轮回灌，技能因此持续生效；长历史交由现有 token 预算修剪兜着。
- 需要一个**与 `_attribution` 无关的新渲染标记键**。`_attribution` 现在双职：
  `SessionChatHistoryProvider.IsOwnedByUs` 用它判定「不落盘」，UI 的 `IsFrameworkInjected`
  用它判定「不渲染」。复用它会让技能正文不落盘，恰好与本决策相反。
  「要不要落盘」与「怎么渲染」是两个正交轴，得分开。
- 点名调用在**机制上**于角色扮演档同样可行（那边框架技能管道全关也不影响它）。
  我们仍然**只在 `ECharacterKind.Agent` 会话开放**：技能正文多在指挥工具，
  而角色扮演档工具集为空，注入过去只会让模型去调不存在的工具。
