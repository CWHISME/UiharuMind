# 群场景段进系统提示，协议留首次投递

群成员的整段系统提示新增一段 `# 场景`（群名 + 在场名单 + 你是谁），**建群时一次定好、之后永不变**；
群协议（发言格式 `[名字]: 内容`、SendMessage 用法）仍随第一次投递给出，不进系统提示。
取代「场景随第一次投递放历史开头」的骨架口径（ADR 0046「骨架做了什么」），治它压缩裁掉开头后场景就没了的问题。

> **状态**：已实现（2026-09-26，提前到 Hello World 之前：并行群聊加主持人后发言更密，10 圈很可能碰到压缩）。
> 实现时修订了两处——**协议也进场景段**、**主持人进场景段且可改**，见文末「实现时的修订」。

## 决策

1. **场景进系统提示，协议留首次投递。** 场景段最小形态：群名 + 在场名单（用户 + 其他成员，按建群顺序）+「你是{自己}」。
   群协议——「群里的发言会按 `[名字]: 内容` 的格式交给你；你每次说完（助手消息有正文、不带工具调用）的正文就是你在群里说的话」、
   SendMessage 发群用法——仍随第一次投递给出。两类东西分开：场景段回答「我在哪、有谁在」，是环境事实；
   协议回答「怎么在这个群说话」，是操作说明。
2. **建群时一次定好、之后永不变**（人格稿 v8 §6 场景层的原口径）。群名与成员名单建群时定死，
   场景段因此在一次会话内逐字不变，前缀稳定、缓存不失效。
   将来名单变化（方案 §6.6b 单聊升级成群、拉人）走**一次显式装配重建**——这是让所有成员拿到新名单的时机，
   是正确行为而非缺陷（本地模型重新 prefill 一次、远程模型丢一次 prompt 缓存，成本可控）。
   **动态状态**（谁在发言、当前进度、轮次）绝不进场景段：那是每轮改前缀，违反 v8 硬约束 2。
3. **两条装配路径都做，统一层在 plan。** 智能体成员走 `AgentInstructionsComposer.Compose`
   （新增 `EPromptSection.Scene`，插在角色段之后、工具纪律之前）；普通角色成员走纯提示词档
   （场景段拼进 `Instructions` 末尾）。普通群只有普通角色，不做这条，普通群成员就丢场景——比现状（首次投递）更差。
   场景正文由**同一个 builder** 生成（群信息 → 文本），`AgentBuildProfile.FromSession` 经 `GroupId` 解析群信息；
   分叉只剩插入点，不引入第二套生成逻辑。普通角色**不**改走 `Compose`：那会把它没有的基座与工具纪律一起带出来。
4. **群场景指纹入装配快照。** `AgentAssemblyFacts` 新增群场景字段（群名 + 有序成员名单 + 自己是哪个）；
   普通角色档因场景段拼进 `Instructions` 自然入账（`Instructions` 本就是快照字段）。改了群名/成员名单，下次挂接即重建。

## 取舍

- **为什么不是「留首次投递」（ADR 0046 骨架口径）**：压缩把开头裁掉后场景就没了，群聊变长后成员会忘了「在场有谁」。
  骨架的对话长度碰不到这一点，Hello World 也碰不到，所以排在它之后做。
- **为什么不是「每轮/每几轮注入进度小结」**：改前缀 = 和增删工具同一种失效（v8 §4.7、决策 21），
  v4 砍掉的「阶段软提示」就是同款。动态进度要走对话区（系统消息/用户消息）或 UI，不进系统提示。
- **为什么普通角色也要**：场景是「我在哪、有谁在」的环境事实，与有没有工具、开不开 harness 无关。

## 实现时的修订（2026-09-26）

1. **协议也进场景段**（修订决策 1）。发言格式（「直接说，不要自己加 `[名字]:` 前缀」）、@ 用法、SendMessage 发群用法
   和场景一样建群后不常变，留在首次投递就和场景一样怕压缩：开头一被裁，模型又开始自加前缀——正是 `StripSpeakerPrefix`
   一直在剥的那个毛病。「环境事实 / 操作说明」的区分仍在，只是体现为同一段里的两小节，不再是两个投放位置。
   还加了一句「私聊的消息开头标着『私聊』」，与每条私聊前的说明对上。
2. **主持人进场景段，右栏可改**（修订 ADR 0049「实现时定下的」第 5 条）。那条不给改的理由是「身份写在首次投递里，
   改了老主持人的历史还说自己是主持人」；身份挪进系统提示后，改主持人就是改一次场景段 → 各成员下一轮开跑时重建装配，
   整段系统提示换新。老投递里残留的冷启动提示只说当时那一刻，不算错。
3. **动态提示不进这里**，仍随消息给：主持人冷启动提示（附在投递末尾）、私聊说明（附在私聊正文前）。
4. **落点**：正文只有一个 builder `GroupTranscript.BuildScene`；`GroupSceneSource.For` 从成员会话解析群信息，
   经 `AgentBuildProfile.FromSession` 进 `AgentBuildProfile.GroupScene`，同一份进 `AgentAssemblyFacts.GroupScene`（改群名、名单、
   主持人即重建）。agent 档由 `AgentInstructionsComposer.Compose` 插在人格之后、工具纪律之前（`EPromptSection.Scene`）；
   纯提示词档经 `AppendScene` 接在角色提示末尾。
5. **能力面板**（原未定第 3 条）：两档都单列一段「群场景」，合计并进角色那一档。
6. **旧数据**：已落盘的首次投递里那段「（这是群聊…）」不动（送达即不可改），与系统提示说法一致；渲染器照旧认它画旁白。

7. **拍板归用户**（2026-09-27 实测后补）。动得了工作区的成员（智能体形态、开着文件或命令行，与草稿目录那句同一判据），
   场景段多一条：用户明确说定或点名让他做之前，只讨论、查证，草稿写草稿目录，不改工作区文件、不跑会改东西的命令；
   拿不准就问。实测：用户一句「我感觉可以，你们还有什么看法吗」被成员读成拍板，没等回应就改了约十个 C++ 文件、
   跑了回归，自动编辑档下连审批卡都没弹。系统仍不解析用户那句话（方案 v6 §2.6③ 不做状态机），判断交给模型；
   要硬拦，就把成员权限档临时设成只读，每次写工作区都在待审批条上等用户点。
8. **过程话群里看不到**（2026-09-27）：「调用工具时顺手写的话只留在你这里」，见 ADR 0049 第 11 条。
9. **群里说话的尺度 + 每轮重锚**（2026-09-27 实测后补）。实测三位成员开场都在人格里，一进正题就趋同成同一种报告腔：
   加粗小标题、成段论证、同一套行话，连卡上明写的「超过五句」「不用分节标题」都破了——系统提示末尾的人格锚点离开口处
   隔着几十条群友的长发言，拉不住；场景段此前的几条全是流程，没有一条讲群里怎么说话，发言被当成交付物写，一人写长、别人跟着学。
   两处补：
   - 场景段加一条：群里像平常聊天，一次两三句、说自己的看法、不写成报告；有草稿目录的，长材料写成草稿文件，群里只说结论附路径。
   - 投递末尾贴一句 `GroupTranscript.VoiceReminder`：本人的人格锚点（`GetPersonaCoda`，与系统提示末尾同一来源）加群里的说话尺度，
     即提案 v8 §7.4 的动态重锚。它随投递落盘、之后不改，前缀缓存不受影响，每次唤醒只多一行；中途插话不贴，一轮只贴一次。
     界面拆投递时按开头 `VoiceReminderOpening` 认出它、不画。临时贴、下轮摘的做法被否：摘掉就改了上一条，缓存从那里断，
     之后整轮的工具往来都要重算。
   同批把内置原作角色卡开头的「照下面写的做——它优先于原作里的任何设定」改成「性子和说话的样子照原作；下面写的是你在这里
   怎么做事，写明了的以下面为准」：旧句把原作印象整个压掉，卡上只剩职能描述，没写到的地方模型用默认助手腔补。
   婚后光子、初春饰利、一方通行三张的样本句与锚点按原作口吻重写（婚后光子此前正文写成「先跑起来」的推进者、锚点却是
   高傲大小姐，两层打架），其余几张见第 10 条。
10. **系统提示的格式**（2026-09-27，同批）。骨架顺序不变，改的是读起来像什么：
    - 标题去工程味：「# 人格」→「# 你是谁」，「# 人格锚点」→「# 记着」（`AgentPromptHeadings`）。「下面是你的人格配置」「这是锚点」
      本身就在把模型往「扮演一套设定」推——日志里成员的思考写的是「作为初春，我说话风格……」。`AgentPromptHeadings.Base`
      对齐成实际用的「# 法则」（此前常量是「# 基座」，与正文不符）。
    - 「谁覆盖谁」在法则末尾说一次（「下面写的是你是谁：它决定你怎么说话、在乎什么，但不改变这两条」），
      卡上删掉「以上性格描述不改变上面这几条」：跨着一级标题往回指，初春那张的「职责」还写在它上面，指代说不清。
    - 内置原作卡统一成：开头三句（出处 / 在这里 / 照原作）→ 一段散文（原作里是什么样的人、在这里的活）→ 三句原作口吻的样本
      → 触发表 → 不做的事（删掉与触发表重复的条目）→ 边界段（「你不是基拉」这类故意设的界线靠它，照原作的「写明了的以下面为准」保住它）。
      此前卡上几乎全是箭头触发表加禁令清单，与工具纪律同一种规章文体，读下来是第三份行为规范而不是一个人。
      九张原作卡（魔禁五位、凤凰院凶真、鲁路修、千空、夜神月）一起按原作人设改写，锚点同步写成口吻指令。白露卡里的
      「# 协作原则」降为二级，不再从人格段里脱出去成为顶级段。
    - 场景段的规矩一条一行（此前八条挤在三四行里连排）。

## 修订：协议引述的口径（2026-09-28）

决策 1 引述的「你这一轮最后的回复正文就是你在群里说的话」是 ADR 0046 决策 4 的原口径，两层都已过时：

- **投放位置**：「协议留首次投递」已由本文件「实现时的修订」第 1 条改为协议也进场景段。
- **措辞**：「这一轮最后的回复正文」早在 2026-09-26 就改为「每次说完都是一条群发言」（0049 第 11 条）；
  2026-09-28 又修订 SendMessage 口径（0046 同名修订）：带 SendMessage 那条以工具发的为准，之后每次说完照常进群。
  正文已按新口径改写，以 CONTEXT.md「群发言」与 0049 第 11 条为准。
