# 停止补存按原始内容落盘，思考不再丢

> **状态**：accepted（2026-11-19）。取消/失败收尾从「取渲染落点的正文本气泡」改为
> 「驱动侧攒原始流式内容 + 内容级去重重建」，半截回复的思考与正文一起按原样补进历史。
> 取代旧实现里 "只补正文、思考无出口、无头轮次整段丢" 的行为。

## 起因

用户报告：停止生成时，最新一条流式回答里的**一部分对话正文和思考记录消失**（重开会话后看不到）。

查下来是三条路一起断：

1. 框架（Microsoft.Extensions.AI 的 Agent 库）在取消/失败时**不落响应消息**——
   `SessionChatHistoryProvider.InvokedCoreAsync` 只补请求消息（`SessionChatHistoryProvider.cs`）；
2. 响应侧由 `TurnDriver.SettleInterruptedTurn` 手动重建，旧实现从渲染落点
   `ITurnSink.TakeStreamingText` 取「当前正开着的**正文**气泡」——思考（结构化
   `TextReasoningContent` / 本地模型正文里的内联 think 标签）没有任何出口；
3. 正文气泡被 `CloseText` 收掉（停在第二思考段/工具执行中）时取回 null，那一整段
   已流完的正文也不补；无头轮次（群/唤醒/定时任务，sink 为 null）则整段都不补。

## 事实

- 正常完成不丢：框架 `ResponseMessages` 整体落盘（`SessionChatHistoryProvider.StoreChatHistoryAsync`
  的 `AppendOwned` 保留 `TextReasoningContent` 与内联标签），取消/失败时 `ResponseMessages`
  为 null。
- 落盘信号（`MessageBoundaryContent`）由 `HarnessCharacterRunner` 在**落盘完成时刻**异步塞进流
  （`HarnessCharacterRunner.cs` 类注释记载极端可达十几秒），实测会晚于下一次调用的首条内容——任何
  「按落盘信号清缓冲」的做法都会误删下一发刚流出的首段。
- 请求侧改写（`LazyChatClient` / `ChatCompletionMessageBinder`）明区分 `TextReasoningContent`
  （走独立字段/补丁）与 `TextContent`（进正文段）：把思考落成内联标签文本会让远程模型的
  请求体分叉、前缀缓存整段失效——所以「统一形状」的方案不可行，落盘形状必须**逐案一致**
  （远程=结构化、本地=内联标签，与正常完成时的消息相同）。

## 决定

1. **驱动侧攒原始缓冲**：`TurnDriver` 在消费循环里按到达顺序攒「可落盘文本」
   （`TextContent` / `TextReasoningContent`，非空），只按 `StreamRestartContent`（整段重发）清空，
   **不按服务调用边界清空**（信号迟到，清了丢首段）。
2. **收尾做内容级去重**：`SettleInterruptedTurn` 取缓冲快照 →
   `InterruptedStreamSaver.TrimContents`（投影拼接 → 按历史削已落盘前缀 → 按偏移重建剩余单元）
   → 原样 Contents 落盘。失错方向是「多写不丢」。
3. **共享实现**：去重逻辑收成单一 internal 工具 `InterruptedStreamSaver`
   （`UiharuMind.Core.AI.Chat`），`GenerateCompletionStreamingContent`（瞬态提示词路径）
   与主轮用同一套语义。
4. **旧取正文链路移除**：`ITurnSink.TakeStreamingText` 接口成员与全部实现删除，
   `SubAgentTurnSink._streaming` 一并移除；UI 落点回归纯渲染职责。

## 代价与边界

- 文本级去重是启发式：模型在末尾逐字复述旧正文时可能判「整段已落盘」而丢新内容
  （既有行为，测试 `TrimVerbatimRepeatAtTheEnd_IsTreatedAsAllPersisted` 显式钉住）。
- 加密思考（`EncryptedReasoningContent` / `ThinkingNotReturnedContent`）不是文本，不进缓冲：
  取消时那一段「思考未返回」信号卡不落盘（旧实现连正文都丢，非回归）。
- 无思考的单文本文档：行为与旧实现兼容（历史单测全部保留）。

## 修订（2026-11-19）

- 评审后补充：瞬态路径改为与主轮同款 `TrimContents`（最初只复用了 `IsPersistableText`，
  仍按落盘边界清缓冲——边界迟到问题在瞬态路径同样存在）。
- 群成员取消补存剥 `[名字]:` 前缀（与正常路径 `SessionChatHistoryProvider` 同款），
  避免取消后重开会话看到带前缀的发言且下一轮供给模型「学得更起劲」。
