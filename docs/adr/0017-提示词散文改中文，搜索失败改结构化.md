# 提示词散文改中文，搜索失败改结构化

两件事，一次做完，因为它们撞在同一批文件上。

## 一、我们自己写的提示词散文一律中文，**只留一份**

- `AgentToolPrompts` 七段正文、`AgentInstructionsComposer` 的段落标题、`SubAgentAssembly` 的
  子代理体例、内置卡 `WorkspaceAgent.json` 的 `# Task` 与内嵌的工作循环副本，全部中文。
- 标题一并中文（`# 工具` / `## 工作目录` / `## 文件操作` / `## 图像` / `## 知识库` / `## 委派` /
  `# 角色` / `# 做法` / `# MCP 服务器` / `# 工作区规矩（来自项目的 AGENTS.md）`），
  出处收进新增的 `AgentPromptHeadings`。
- **工具与参数的 `[Description]` 保持英文**，不在本次范围内。
- 新增护栏句 `AgentToolPrompts.LanguageNeutrality`，挂在 `# 工具` 之下第一行、
  以及子代理的 `# 角色` 段里。

### 为什么中文

主力跑的是中文语料为主的本地小模型，英文纪律段它「读得懂但不照做」；而这批文本的另一个读者
是在编辑器里看它的人，仓库注释通篇中文，提示词却是英文，两头都别扭。

### 为什么标题也译

正文中文、标题英文等于每一节开头都切一次语言，而语言混排正是这次要消掉的东西。还有一条硬约束：
`# 工具` 与角色段的 `# 工作循环` 必须同级（`AssemblyInvariantsTests` 按位置钉着），
一个中文一个英文会让语义上的「同级」在视觉上断掉。

### 为什么只留一份、不跟界面语言切换

双份意味着每次调措辞要改两处，而**没有任何测试能校验中英两版说的是同一件事**——
不变量测试只校验得了反引号与工具名。本仓刚为「抄两份迟早走样」付过代价。
用户要英文，改角色卡或片段库即可，那两处本来就是可编辑的。

### 为什么必须有护栏句

这一大段中文每轮都发、体量压过用户那几句话，模型的输出语言会被它拽走。
`MemoryContextProvider` 早就为记忆块钉过同一句话，harness 段先前漏了。
护栏句刻意**不放在工作循环段**：那段会落进用户存档、用户删得掉，而这是系统级不变量。
挂在 `# 工具` 之下则与漂移源同生共死——有中文纪律段才有它。

## 二、工作目录段明确表态「默认给相对路径」

`BuildWorkingDirectory` 原先有一条自我约束：刻意不表态该用相对还是绝对，
理由是「文件纪律段与工作区 AGENTS.md 都可能有自己的主张，多一句偏好就会打架」。**本次推翻它。**

推翻的理由是那个前提已经不成立：两个搜索工具的目录参数统一叫 `directory`，
失败时还会回显解析后的绝对路径。此时**缺一句明确默认反倒才是模型乱编路径的来源**——
绝对路径要求模型「知道」一个它其实不知道的前缀（实机见过它编出 `root: "/path/to/project"`），
相对路径它靠 `Glob` 就能查到。相对路径也更省 token，本仓路径很深。

这句话**只在工作目录段出现一次**，文件纪律段不重复表态——原注释真正想避免的是那个。

## 三、搜索失败改结构化，不再混进结果列表

`SimpleGlobber` / `SimpleGrepper` 改为返回 `GlobOutcome` / `GrepOutcome`：命中与失败原因分开。
面向模型的措辞由 `SearchFailureRenderer`（工具边界）渲染，面向用户的文案由 `SearchViewModel` 渲染。

修掉的三个实机症状，共同点是**工具骗了模型**，不是模型不会用工具：

1. **Grep 目录不存在时静默返回空列表**，与「这个词确实没有」完全无法区分。模型于是换个关键词
   在错目录里反复搜——这就是「搜索工具试几次才找到正确用法」的机制。这一条是「AI 老是误会路径」
   的头号成因：Glob 的失败至少可见（有 `[Error]`），Grep 的失败连信号都没有。
2. **失败以字符串混进结果**（`"[Error] ..."`、`FileName = ""` 的假命中、`FileName = "[truncated]"`
   的哨兵）。模型分不清「这是一处命中」和「这是一句话」；界面的快速搜索更是把
   `[Error] 目录不存在` 当成一个文件名显示成一条结果。
3. **`SearchService` 的 `catch (Exception) { }`** 把真异常静默吞成「0 结果」。

失败措辞里的路径**全是当次真实的路径**：

```
Directory not found. You passed directory "src", which resolves to
"/…/UiharuMind/src". The working directory is "/…/UiharuMind".
Give directory relative to it, or omit directory to search the whole working directory.
```

这同时给了示例、暴露了解析结果、还避免了占位符——**这正是不把调用示例写进系统提示的原因**：
提示词里的通用示例会被小模型照抄（`/path/to/project` 就是这么来的），且常驻付费；
错误消息里的示例由真实入参拼成，无可抄，且只在出错那一次付费。

## 四、`isRegex` 不再靠选默认值，改成归一化 + 降级

实测（Glacier.Grep 走 .NET `Regex`）：

```
'*Globber'      regex=False -> 0 hits
'*Globber'      regex=True  -> THROW  Quantifier '*' following nothing
'Glob.*Search'  regex=True  -> 2 hits
'SearchAsync('  regex=True  -> THROW  Not enough )'s
'SearchAsync('  regex=False -> 5 hits
```

结论：**这个旋钮选不出赢家**，两类输入的需求相反。此前把默认值调成 `true` 是误归因——
`*XXX` 在 `true` 下并没有生效，它抛异常然后被包成一条假命中，看起来「有 1 条结果」。

改法：默认仍是 `true`，但加两步补救。① glob 味归一化，把无从量化的前导 `*` 补成 `.*`
（`*Globber` → `.*Globber`）；② 编译不过则降级为字面串重搜，**并把降级这件事回报给模型**——
不说一声，它对「为什么少了几条命中」会推错。归一化只动首尾：中间的 `*` 前面总有东西可量化，
那是合法正则，动它会改掉一个本来写对了的表达式。

`Glob` 的 `root` 也统一改名 `directory`：`root` 这个词诱导模型往里填「项目根」样子的东西。

## 五、搜索结果的路径改按工作区根算

`SimpleGlobber` / `SimpleGrepper` 回的路径从前是**相对本次搜索根**的，而 `Read` / `Edit` 按
**工作区根**解析。于是 `Grep(directory: "Core")` 回来的 `AI/Foo.cs` 喂给 `Read` 会找不到。

**模型倒向绝对路径不是幻觉，是理性**：在这个矛盾下，绝对路径是唯一跨工具通用的形式。
所以这件事修不了在提示词里——第三节那句「默认给相对路径」是在跟一个真实的歧义对抗，对抗不过。
改成按工作区根算（`SearchRoot.ToPortablePath`，搜索根在工作区之外时退回绝对路径），
搜索结果才第一次可以直接当 `Read` 的入参，相对路径也才第一次成为不吃亏的选择。

另一个症状是**首轮就传绝对 `directory`**：工作目录段亲手把绝对路径交到模型手里，
`Glob` 又开了个 `directory` 槽，它手上只有这一个目录形态的值。这一条与上面无关（首轮没有工具
输出可抄），治在 `[Description]`：从描述省略的*效果*（"Omit to search the whole working
directory"）改成给行为指示（"Omit this … pass it only to narrow the search to one subdirectory"）。

顺带修掉 `SearchService` 的一处陈旧根：两个搜索器从前在构造时就按当时的历史首项建好并长期持有，
用户切目录后根就过期了；而路径既然是相对根算的，根一旦陈旧，界面拼出的完整路径就是错的。

## 六、内置智能体卡拆出 `# 风格` 一节

`WorkspaceAgent.json` 从前把人格和职责挤在 `# 任务` 的同一句里。`AgentToolPrompts` 的注释里
写着「与角色卡里的 Task、Style 两节同级」——Task/Style 是既有体例，这张卡没照着来。

挤在一句是有后果的：模型分不清「卖萌」约束的是说话还是产物，弱模型会把颜文字写进文件内容或
命令。拆开之后 `# 风格` 明确「只管对人说话的口气，写进文件的内容、命令、路径里一律不出现」。
`# 任务` 补一条边界（只做任务要求的改动）——这句子代理侧本来就有，而真正动手改文件的主 agent
反倒缺着。

**没有给这张卡加 `{{$lang}}`**，虽然 `Assistant.json` 有。`{{$lang}}` 解析成**界面语言**，
而护栏句说的是「用对话本身所用的语言」，两条直接对打。护栏是系统级的、覆盖面更广，
所以语言口径只由护栏一处说。

## 七、补上命令行纪律段

shell 是唯一挂了工具却**零指示**的能力：`BuildToolDisciplines` 按能力挂了文件操作、图像、
知识库、委派四节，`EnableShellExecution`（默认开）一节都没有。

后果实机见过：模型要把一个文件挪个位置，却用 `Write` 把 587 行内容重新输出了一遍。
它事后自称「是思维惯性，不是提示词问题」——**那是事后合理化**，模型对自己为何选了某个工具
并没有特权视角。真实原因在代码里查得到：文件纪律段那份清单只有
Glob/Grep/Read/Edit/Write，**移动、改名、删除在清单里根本不存在**，它只能从有的东西里凑。
缺口在清单上，是我们没写。

「文件系统操作用 `Shell`」这句刻意**不写进 `FileAccessDefault`**：shell 可以被关掉，
而那一段在 shell 关掉时照样发出去，等于给模型指一个不存在的工具——违反「关掉的工具绝不出现」。

段落正文由 `BuildShell(fileAccessMounted)` 拼，因为前两条讲的是「这件事该归 `Shell` 还是归
文件工具」、会指名 Read/Edit/Write，而那三个只随 `EnableFileAccess` 出现。
主 agent 与完全自动档的子代理共用同一份正文（子代理拿的是同一个 `Shell`）。

写这一段时不变量测试逮到三处，都记下来：

1. **子代理侧判据用错了对象**：我按 `config.EnableShellExecution` 判断，而工具实际随
   `input.ShellTool` 挂。改成 `hasShell = canMutate && input.ShellTool != null`，
   与既有的 `hasVision` 同一口径——**判据取装配结果，不取配置意图**。
2. **`ToolDisciplines_AreOmittedEntirely_WhenNothingIsMounted` 的 fixture 漏了一项**：
   `EnableShellExecution` 默认 `true`，所以那份「什么都没挂」的配置其实挂着 shell。
   从前看不出来，正是因为 shell 没有纪律段。
3. **段落讲命令行却可能一次不提 `Shell`**：工具名原先写在会被整块跳过的前两条里。
   挪进无条件那条。

第 3 条另加了一条不变量（`ShellDiscipline_NamesFileTools_OnlyWhenFileAccessIsMounted`）。
主 agent 做不了「按真实工具集校验反引号」的通用版——装配真工具集要一个 chat client，
而本套测试的助手只拼提示词；子代理那侧有通用版。

## 八、没有动 `limit` / `offset` 的参数说明

一次实机观察里模型主动填了 `limit: 30`（读太少，正是纪律段那句刹车要防的），
一度想按 `directory` 的同一改法治它。**实测否掉了**：绝大多数模型是省略 `limit` 读全文的，
只有个别会填。为一个少数派行为改常驻 schema 不划算。

## 九、命令行纪律段去掉了 POSIX 假设，并告诉模型它在哪种 shell 上

框架按平台解析 shell（`ShellKind` 有 `Bash` / `Sh` / `PowerShell` / `Cmd` 四种）。初版那一段举了
`cat`/`sed`/`awk` 与 `rm -rf`/`git reset --hard`，**在 Windows 上全不成立**（cmd 下前三个不存在，
PowerShell 下只有 `cat` 是别名，`rm -rf` 也要写成 `-r -fo`）。举错例子比不举更糟，改成描述性质：
「不要用命令行去打印或就地编辑文件内容」、「递归删除、批量覆盖、丢弃未提交的改动」。

同时加一句「你的 shell 是 X」，取自 `LocalShellExecutor.ResolvedShellBinary`（实测构造后即可读，
不必等 `InitializeAsync`；读不到就不写那一句——宁可不说，也不能告诉模型一个错的 shell）。
模型从前对自己跑在哪种 shell 上一无所知，只能先试 `ls` 再试 `dir`，白烧一次调用。

**删掉了两条**：「不要把多条命令塞进一行来绕过审批」预设了模型有规避意图，而它通常没有，
`a && b` 在很多场合是正当且更省的；「批准放行的是同类命令（按前两个词）」是给**用户**看的机制，
模型知道了并不改变行为。真正有价值的「一条命令做一件事，失败时分得清哪一步」已经单独立着。

## 十、Glob 的每个文件都标大小，Read 截断时报文件总大小

纪律段要求模型「绝不要把一整个大文件拉进上下文」，却**从来不给它判断依据**——它不知道哪个文件大。
这是那句要求唯一缺的东西。

**一度只想标超阈值的文件（256 KB），被否掉了**，两个理由：没有标注会变成歧义，模型分不清
「这个小」和「这个没测」；而且一堆小文件全无标注就**没法排序**，选不出该先读哪个。
统一一列反而更好推理。成本一条约 4 token，而一次误读大文件是上万 token。目录不标（没有意义）。

`Read` 截断时也报文件总大小：光说「续读 offset=31」，模型不知道是再翻一页就完还是要翻六十页，
也就无从判断该继续翻还是改用 `Grep` 定位。总行数会更贴（`offset`/`limit` 按行算），
但那要读到文件末尾才知道，正好违背这个工具存在的意义；文件大小是 O(1) 的代理值。

**其余属性都没加**，判据是「这条信息会不会改变模型的下一步动作」：修改时间几乎免费但通常不改变
下一步，而模型没有「现在几点」这个锚；是否二进制靠扩展名判断本来就不准，而扩展名模型自己看得见；
权限与符号链接只在失败时有意义，那时错误消息会说。

`GlobOutcome.Entries` 因此从 `IReadOnlyList<string>` 改成了 `GlobEntry`（路径 / 是否目录 / 字节数）。
**这是必须的**：它有两个读者，模型那侧要 `[FILE] path (12.3 KB)`，界面那侧只要路径去打开文件。
第一版把大小追加进同一个字符串，当场打断了界面剥 `"[FILE] "` 前缀取路径的那段代码——
正是本 ADR 第三节要清的那个毛病（把信息编码进字符串给两个消费者各自解析）差点原地复发。
渲染现在各自在自己那一层做，`StripGlobPrefix` 退役。

## 十一、Glob 回给模型的条目：文件在前，目录在后

搜索器给的是纯路径字典序，于是**同一层**的 `[FILE]` 与 `[DIR]` 逐行交替：

```
[FILE] appveyor.yml (1.8 KB)
[DIR]  cmake
[DIR]  data
[FILE] default.nix (395 B)
[DIR]  docs
[FILE] flake.lock (3.4 KB)
```

分组之后文件成块、目录成块。文件才是**可行动**的东西——拿到路径下一步就是 `Read`/`Edit`，
而 `**/*` 里的目录多数时候只是结构信息。

排序**只在工具边界做**，搜索器那层保持稳定的路径序（可测、规范化），界面保留自己的习惯——
与第十节把渲染拆到各自那一层是同一条口径。

一度想用「文件排前面能让 300 条上限截掉目录而不是文件」当理由，**那是错的**：截断发生在排序
之前（枚举到 300 条就 break，然后才 sort），所以排序影响不了谁被留下。要让文件优先存活得改
枚举逻辑，没做。

## 十二、数组参数接受标量字符串

实机报错：

```
Grep(query: "wayland|Wayland", contextLines: 3, fileGlobs: "*.cpp")
→ Error: The JSON value could not be converted to System.String[].
  Path: $ | LineNumber: 0 | BytePositionInLine: 7
```

`fileGlobs` 是 `string[]`，模型给了标量字符串，死在反序列化上。回给模型的是一句框架异常——
它既看不懂、也无从改正，**连哪个参数错了都没说**。

「schema 说要数组、模型给了标量」是模型的通病，不是这一个参数的毛病，所以治在序列化层：
`LenientStringArrayConverter` 接受标量或数组，挂在 `AIFunctionFactoryOptions.SerializerOptions`
上（`ToolJson.Lenient`，基于 `AIJsonUtilities.DefaultOptions` **复制**后加转换器——
直接改那份默认会波及所有工具与结构化输出）。同类的 `SchedulerTools.preAuthorizedCommands`
一并挂上，那是仓里另一个面向模型的 `string[]`。

一个标量里塞多项时按逗号拆开（`"*.cpp,*.h"`），但**带花括号的一律不拆**：
glob 的分组语法本身就用逗号（`*.{cpp,h}`），拆了会毁掉一个写对了的表达式。

测试**走真实的工具调用路径**（`AIFunction.InvokeAsync`），不是只测转换器：
转换器接对了但没挂到工具上，实机照样炸，而单测转换器发现不了那种漏接。
这条测试顺带消掉了「取舍」里那个悬着的风险——带 `Notice` 的包装类型走反射序列化没问题，
`InvokeAsync` 正常回一个 `JsonElement`（字段名是 camelCase：`entries` / `notice`）。

## 取舍

- **存量英文不迁移。** 片段库里那条「智能体工作循环」、可能存在的
  `CharacterOverrides/WorkspaceAgent.json`、用户自建智能体的 `Template`，改常量都不会跟着变，
  需要手动处理。写迁移得靠「正文等于旧默认值」来识别，而那个判据区分不了「用户没动过」和
  「用户改过又改回来」，误判会**静默吞掉用户手写的提示词**。为一台机器上三处文本
  把这个风险永久留在启动路径里，不划算。内置角色本身每次启动从嵌入资源读，没有迁移问题。
- **工具返回形状变了。** `Glob`/`Grep` 从 `List<string>`/`List<FileSearchResult>` 改为带
  `Notice` 字段的包装类型。框架的 JsonContext 只注册了 `FileSearchResult`/`FileSearchResultList`，
  这里靠反射序列化。曾把这条挂着当"只有实机能确认"的风险，**第十二节的测试已经证实它没问题**：
  `AIFunction.InvokeAsync` 正常回一个序列化好的 `JsonElement`。
- **搜索根在工作区之外时回绝对路径。** 硬凑相对路径会得到一串 `../../`，比绝对路径更难用。
- **失败措辞是英文**，与它紧邻的工具 schema 保持一层。真要中文，改
  `SearchFailureRenderer` 一处即可。
