# 拖选重整形的账，先记下不修

决定：**不改 LiveMarkdown，继续用 NuGet 的 `LiveMarkdown.Avalonia 2.4.3`。**
成因已经查清、代价已经量准，但两次改动都带来了更糟的回归，且无头里复现不出来、归因不了。
账记在这里，等条件成熟再动。

## 现场

一个跑了 30 分钟的进程，在子代理弹窗里选了一段文字之后界面卡了一下，`phys_footprint`
冲到 **7.8GB**（vmmap 里是一万七千块 256KB 的 `VM_ALLOCATE`），而同期 gcdump 测得活对象
始终只有 **206MB**、累计分配 19.5GB。不是泄漏，是生出来立刻就死的**字形整形垃圾**。

## 成因：两处，叠在一起

**一、Avalonia 12.1.2 `SelectableTextBlock.OnPropertyChanged`**：选区变化走
`InvalidateTextLayout()`，而那个方法会 `_textRunCache?.Invalidate()`，把整形结果丢掉。
可选区**不影响整形**——翻 `CreateTextLayout`，它唯一参与排版的地方是
`length > 0 && SelectionForegroundBrush != null` 时塞一个前景笔刷，只改颜色；
选中框是 `RenderTextLayout` 现画的，重绘也早由 `AffectsRender` 管住。
同文件里就有现成的 `InvalidateTextLayoutKeepCache()`，偏偏这里没用上。

**二、LiveMarkdown `MarkdownTextBlock.CreateTextLayout`**：构造 `TextLayout` 时
**没把 `TextRunCache` 传上**，而 Avalonia 原版 `TextBlock.CreateTextLayout` 是传的。
于是这个控件从来没有过整形缓存，而 `ArrangeOverride` 每趟都无条件重建 `TextLayout`
（它自己的注释写着「保留 TextRunCache 让整形结果复用」，承诺一直没兑现）。

拖选时每一次指针移动都改一次 `SelectionEnd`，上面两条一叠，就是整块文本一秒被从零整形上百次。

## 量准的数（`TextSelectionCostTests`，无头真实控件）

32KB 正文，拖选 100 步：

| | |
|---|---|
| Avalonia 裸 `SelectableTextBlock` | 526 MB |
| `MarkdownTextBlock`（NuGet 原版） | **23,748 MB**，每步 237MB |
| 补上 `TextRunCache` 之后 | 129 MB（184×） |
| 再加「选区不重排」近路 | 0 MB |

代价随**整块文本长度**线性涨，与选中了多少字无关——「重新整形整块」而非「重画选区」的指纹。
一次两三秒的拖选是两三百个指针事件，在一条长回复上就是好几个 G。现场的 7.8GB 对得上。

## 为什么最后没改

**「选区不重排」的近路**判据建立在「`OnMeasureInvalidated` 被调用」上，而
`Layoutable.InvalidateMeasure()` 只在 `IsMeasureValid` 为真时才回调它——近路把 measure
停在「已失效」，后续真正的内容变化再调 `InvalidateMeasure()` 就成了空操作。
这个判据从原理上就不可靠，撤。

**补 `TextRunCache`** 本身看起来无害（fork 自带 170 条测试全绿，其中
`Selection_DoesNotChangeMixedRunLayout` 专门守着选区语义，中途还真拦下过一次错误实现），
但实际使用中仍然出现**流式输出中断与渲染异常**。无头里两次复现尝试都失败——
第一次量错了指标（块在 `ScrollViewer` 里被拉伸，`Bounds.Height` 恒等于视口高度），
第二次走真实 `MarkdownRenderer` 的版本**在未打补丁的库上也一样冻住**，
说明是异步 producer 在无头里没被驱动，测试本身无效。

**改不动、又证不清，就不改。** 退回 NuGet 版本。

## 顺带查清的字体问题

调查途中还查清了两个字体缺陷（族名写错导致全应用没有粗体、markdown 让中文走字符回退），
与本 ADR 的拖选问题无关，单独记在
[0040-字体单点到底，别让中文走字符回退.md](0040-字体单点到底，别让中文走字符回退.md)。

## 还留着什么

- `TextSelectionCostTests`：两条，量上游代价、记住这笔账。数字在测试输出里，
  重做时不必从头量一遍。
- `IdleMemoryReclaimer` 的第二条触发判据（已提交 − 堆实际大小 ≥ 256MB）——
  这一处与 LiveMarkdown 无关，独立有效，保留。

## 什么时候可以重做

上游 Avalonia 那两行是**正解**（把选区那一支的 `InvalidateTextLayout()` 换成
`InvalidateTextLayoutKeepCache()`，并把它从 private 放开），一修，
`MarkdownTextBlock` 连同本仓所有可选中文本块一起受益，不需要任何 fork。
提 PR 是成本最低、收益最广的一条路。
