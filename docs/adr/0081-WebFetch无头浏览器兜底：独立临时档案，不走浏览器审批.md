# WebFetch 无头浏览器兜底：独立临时档案，不走浏览器审批

> **状态**：accepted（2026-10-10）。补充 [ADR 0078](0078-浏览器：接管交给用户，审批卡说人话，读正文与截图.md)：浏览器工具本身不变。

## 背景

WebFetch 的读取链是 Firecrawl → 直连 → llms.txt。Firecrawl 限额耗尽或熔断时，只靠 JS 渲染的页面直连只拿到空壳，
模型要么放弃，要么改用浏览器工具——后者每次导航都要审批，还会弹出用户的 Chrome 窗口。

## 决定

**一、链上加一环本机无头浏览器，排在直连之后、llms.txt 之前**：Firecrawl → 直连 → 无头浏览器 → llms.txt。
起浏览器要一两秒，只在便宜的两环都失败时才走到；llms.txt 内容常不是页面正文，降为浏览器不可用或也读不到时的托底。

**二、与浏览器工具的宿主分开（`HeadlessPageRenderer`）**：
- 无头、不弹窗口；一次一页，读完即关页面，闲置三分钟整个退出。
- 临时档案，按进程隔离（`$TMPDIR/UiharuMind-fetch-<pid>`），退出时删除。同一份档案不能同时开两个 Chrome，
  与可见浏览器共用会锁档案；按进程隔离则多实例互不影响。
- 起 Chrome 失败（多半没装）后十分钟内这一环安静跳过，不每次白试。

**三、不走审批，也不要求开浏览器扩展。** 没有登录态和 cookie，风险与直连同级；内网地址照样不受理。
需要登录或验证码的页面不在这一环的范围，仍由浏览器工具与接管处理。

## 代价

- 少数风控严的站点认得无头浏览器，读到空壳，继续落到 llms.txt。
- 没装 Chrome 的机器上这一环形同不存在。
