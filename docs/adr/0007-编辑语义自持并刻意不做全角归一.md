# 编辑语义自持，并刻意不做全角归一

文件工具从七个收到五个：`Read` / `Write` / `Edit` / `Glob` / `Grep`。
`Replace`（单处精确替换）与按行号改行的 `Edit` 合并成一个 `Edit`，`Delete` 去掉。

新 `Edit` 收一组 `edits`，每条给 `oldString` / `newString`：

- 每条都对着**原文**匹配，不是对着同一次调用里前几条的结果；
- 每条必须在文件中**唯一命中**，命中多处即整体失败，并告诉模型「出现 N 次，请加上下文」；
- 条目之间不得重叠，重叠即整体失败并点名是哪两条；
- 任一条不适用则**一个字都不落盘**；
- 成功后回给模型一段带行号的精简 diff。

语义的唯一定义处是 `FileEditPlanner`（纯函数：原文 + edits → 新正文 + diff｜失败话术）。
审批卡片调的是同一个函数**干跑**出真实 diff，因此卡片上看到的就是落盘后的样子。

匹配分两步：精确匹配；不中则退到**保守 fuzzy**——按整行窗口比对，逐行 `TrimEnd` 后相等即命中。
它同时吸收「行尾多余空白」与「CRLF/LF 不一致」两类差异，后者是结构性吸收的：
切行时 `\r\n` 与 `\n` 都是终止符，不参与比较。

落盘保真由 `TextFileEnvelope` 兜：BOM 读入时摘下、写回时戴回；正文**不做任何归一**，
只有新插入的文本按文件的行尾风格转写。

## 为什么

1. **按行号改行没有内容校验。** 旧 `Edit` 收 `line_number` + 字面 `new_line`，模型数错一行就静默
   改错一行，而且改完只回一句 `Applied N line edit(s)`——它看不见自己干了什么。要求 `oldString`
   唯一命中，等于把「你以为在改这里」和「实际在改这里」绑在一起，错了当场失败而不是悄悄写坏。

2. **两个语义重叠的写工具在逼模型猜。** `Replace` 与 `Edit` 都是「改一处」，`Write` 还能整份覆盖。
   合并之后写工具只剩两个，纪律段也讲得清：改已有文件一律 `Edit`，`Write` 只用来新建或整份替换。

3. **一次调用改多处，省的是轮次。** 一处改动一次调用，在本地模型上每轮都要重新读一遍上下文。

4. **`Delete` 是最危险也最不必要的那个。** 它能带 `recursive` 递归删整棵目录树，路径还可以是任意
   绝对路径。删文件走 shell：审批卡上一条 `rm -rf /path` 比 `Delete(path, recursive:true)`
   更能让人看清后果，而 shell 那条链已经有预授权模式机制。pi 与 Claude Code 都没有删除工具。

5. **落盘保真修掉两处静默改写。** `File.WriteAllTextAsync(..., Encoding.UTF8)` 会写出 UTF-8
   preamble，而读取端又把 BOM 吃掉——每编辑一次文件就长出一个 BOM；旧 `Edit` 还会把整份文件
   CRLF 抹成 LF 再写回，让 Windows 换行的文件整份变更。

## 取舍

- **放弃「等框架公开 FileEditor 就删掉复制品」这条退路。** `MfaFileEditor` 是 MFA 内部
  `FileEditor` 的逐字复制，注释里写着删除条件。翻案理由：框架那套语义（盲改行号 / 单处精确替换）
  正是我们要摆脱的东西，等它公开也只是拿到同一套烂语义的正版。编辑语义从此自持。

- **刻意不照搬 pi 的 fuzzy 归一。** pi 的 `edit-diff.ts` 第一步是 `text.normalize("NFKC")`，
  另有智能引号、各种破折号、各种 Unicode 空格的归一。NFKC 会把全角标点映射成 ASCII：
  `（`→`(`、`）`→`)`、`：`→`:`、`，`→`,`。**本仓注释通篇是带全角标点的中文**，而 fuzzy 命中后
  被重写的正是命中区域那几行——也就是最可能挨着中文注释的那几行。一次编辑就可能把
  `（注意：会阻塞）` 静默改成 `(注意:会阻塞)`。这在英文代码库里几乎不发生，在我们这儿是常态风险。
  代价是模型把全角写成半角时不会被兜住，那种情况报错重试一轮；比悄悄改写注释便宜得多。
  `FileEditPlannerTests.FullWidthPunctuation_IsNeverRewritten` 是这个决定的看门人。

- **不做「不归一」之外的行尾处理。** pi 的做法是整份归一到 LF、算完再按主风格还原；混用换行的
  文件会被统一。我们改成正文一个字节都不动、只转写新插入的文本，因此混用换行的文件也安全。
  副作用是 fuzzy 只覆盖**整行**的 `oldString`——行内片段靠精确匹配，中不了也不该靠猜。

- **不移植 pi 的同文件写入串行化（`file-mutation-queue`）。** 框架的
  `AllowConcurrentInvocation` 默认 false 且全仓没开过，子代理是刻意同步阻塞的（本地模型单 slot）。
  那把锁防的是一个当前不存在的并发。工具类上留了一段注释说明「为何不需要锁」。

- **不移植 unified patch 与 `firstChangedLine`。** pi 用它们喂 TUI 的 details 面板和「跳编辑器」，
  我们没有这两个消费者。回给模型的只有带行号的精简 diff，限幅 80 行。

- **预演失败在审批卡片上静默回退成参数摘要。** 干跑能提前判定「这次编辑必然失败」，本可以在卡片上
  标红让人当场拒掉。没做：修掉 `AutoEdit` 空档位之后，编辑在常用档位下根本弹不出卡片，
  为一条罕见路径多养一条 UI 分支不值。真正承重的是**回给模型的话术**，那份写足了。

- **不容错「模型把 edits 发成 JSON 字符串」。** pi 专门为此做了参数矫正，注释点名了几个模型的毛病。
  我们靠框架的 schema 绑定报错让模型自己改一版；真在实机撞上再补。

## 代价（明说）

- **关掉了 shell 的智能体彻底没有删文件能力。** `AgentToolConfig.EnableShellExecution` 为 false
  时没有任何工具能删文件（`Write` 覆盖成空文件不算删）。
- **旧会话档里的历史工具调用渲染会退化。** 存档里那些 `Replace` / 按行号的 `Edit` 调用，
  审批卡片不再认得它们的参数形状，diff 区回退成参数摘要。历史正文本身不受影响。
- **`Grep` / `Glob` 一个字没换引擎。** 这两个我们比 pi 强（进程内 SIMD 引擎、自带 `.gitignore`
  层级排除、同一套还服务界面的文件搜索窗），pi 是 spawn 外部 rg/fd 二进制。只修了自己实现里的
  三个缺陷：`contextLines` 传进引擎却被丢掉、结果没按文件聚合、限幅话术与实际口径不符。
