# 子代理仍同步阻塞；原理由「本地单 slot」已失效

**这是一条带保质期的决定。** 单独成篇而不并进 ADR 0021，是因为它的理由已经塌了一半、
下一期就要重审——这种东西混进一份「定版」型 ADR 会污染它，将来被取代时也不干净。

决定：子代理仍在主 agent 的一次工具调用内部同步跑完，本期不做后台化。

## 原理由塌了哪一条

`SubAgentTool` 的类注释写着：

> 同步阻塞而非后台并发，原因有三：**本地模型是单 slot（llama-server 未传 `-np`），
> 并发只会在服务端排队**；同步天然满足「等它跑完」这条；取消令牌能一路传进子代理。

第一条是**事实上失效的**——实际主力已转为远程模型，并发有真实收益。
注释必须就地标注这条已过期：留一条前提已消失的理由在那里，比没有理由更糟，
后人（包括 AI）会以为阻塞是经过论证的选择。

第二、三条仍然成立，但它们只说明「同步够用」，不说明「异步不可行」。

## 阻塞的真实代价（原注释没有记）

`MessageInjectingChatClient` 坐在 `FunctionInvokingChatClient` **下面**，
在每次向模型发请求前排空注入队列。而子代理跑着的时候，主 agent 的 `FunctionInvokingChatClient`
正卡在工具执行里，**根本没有发下一次请求**。

净效果：**子代理跑着的整段时间，用户给主 agent 插的话进了队列但不会被消费。**
一个墙钟上限 24 小时的工具，期间主 agent 对用户是聋的。

（ADR 0021 的外驱模式做完后，用户**能实时跟子代理说话，却不能跟主 agent 说话**。
这个组合怪，但自洽：想改方向的场景多半在子代理那头就能解决。）

## 为什么仍然不做

1. **轮次归属是执行域的承重墙。** `TurnDriver` 的定义是「它负责**这一轮历史的自洽性**」。
   非阻塞意味着主 agent 那一轮**结束并存档了，却还挂着一个未了结的副作用**——
   报告回来时那一轮已封存，它要么落进下一轮（可能几小时后才有，或者根本没有），
   要么自己起一轮（那一轮的「用户消息」是什么？）。**「一轮」这个概念会被撑开。**
2. **范围风险。** ADR 0021 已经要动子会话落盘、`TurnDriver` 改造、外驱模式、右栏、
   窗口替换、模板下沉六处。把一个尚未收敛的承重墙问题并进来，
   是让一期稳妥改动去赌一个开放性设计。
3. **ADR 0021 做完之后，非阻塞会便宜很多。** 子会话已是可寻址实体、右栏已有索引与独立
   停止入口、`SessionRunRegistry` 已能持有活 runner、卡片已能表达状态、后续报告已有落盘通道——
   非阻塞缺的基础设施，那一期正好全建好。

## 解锁门槛是轮次归属，不是并发能力

将来重审时，判据不是「远程模型能不能并行」（能），而是**「一轮」被撑开之后还剩什么**。
形态上倾向**逃生舱而非默认**：默认仍阻塞，用户或模型可主动「转后台」，
工具立即返回「已转后台」，结论走 ADR 0021 那条后续报告通道回来。
默认非阻塞不可取——它把编排责任推给模型，而本仓对本地模型的自主判断有实证的低评价
（见 `SubAgentTool` 里「自定义子代理提示词」那次失败的记录）。

## 本期预付的四笔钱

1. 卡片状态机预留「已派出 / 结果待回」这一档，不要设计成三态。
2. 界面从一开始容纳 **N 个并发子代理**——阻塞时天然只有一个，非阻塞后 N 个是常态。
3. `SubAgentTool` 类注释就地标注「本地单 slot」已失效。
4. 本 ADR 本身。

## 顺带修正：两条兜底重新定价

`SubAgentTool.MaxIterations = 32768`（`:47`）与 `Timeout = 24 小时`（`:51`）是按
**本地无人值守**定的——注释原话是「一个死循环的子代理会一直烧本地模型」。

**本地烧的是电，远程烧的是钱。** 一个跑偏的子代理在远程 API 上连转三万多轮不是「慢」，
是账单事件。而这两个数字**现在就在生效**，与非阻塞那一期无关，故本期就改。

按场景分档：交互场景（用户看得见嵌套过程、也按得动停止）保留宽松上限——
那段推理本身是对的，错的只是无人值守那一档的数值；无人值守（定时任务）按远程成本收紧。

不改成 token/成本预算上限：更贴近真实风险，但要接 `TurnUsageLedger` 做新判定，本期不塞。
