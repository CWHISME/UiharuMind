# 记忆清单随本轮输入发送时投影，首行即摘要

> **状态**：accepted，已实现（2026-10-08）。修订 [ADR 0028](0028-文件记忆退役，记忆改为工作区目录由模型自管.md)
> 「不设应用侧索引、不做注入」一条；目录约定、写入免审批、内容边界不变。
>
> **现状（2026-10-14 补注）**：随输入注入已停用（`HarnessCharacterRunner` 里 `TryAnchor` 一段注释掉，代码暂留），
> 改为提示词给指针、模型 `Read $MEMORY` 现取同一份清单。清单每行另带修改日期（`路径 [yyyy-MM-dd] — 首行`）：
> 工作区记忆各成员共用，旧结论被推翻后旧笔记常常没人改，日期是认出它的主要信号。

工作区记忆（ADR 0028）全靠模型自觉去 `Glob`。实测它几乎不回头看：这个仓库的工作区下约 295 个调过三次以上工具的会话，
只有 5 个单纯读过记忆而没在同一会话里写，其余的读几乎都是「写之前看一眼」。记忆写了，却没人想得起来。

决定：**每个供给窗口里附一份记忆清单**——每份笔记一行「路径 — 首行摘要」（路径以 `$MEMORY/` 这类简写开头，照抄就能读），挂在本轮输入消息上，发送时才并进正文。

## 怎么附

- **快照挂注解，发送时投影。** 一轮开跑时（`HarnessCharacterRunner.RunAsync`），若供给窗口里还没有清单，
  就把当前目录生成的清单写进本轮输入消息的注解 `_memoryIndex`（`MemoryIndex.TryAnchor`）。消息正文仍是用户原话；
  `MemoryIndexProjection` 只在发出去的那份里把清单并进第一个文本块，历史不动。
  与 ADR 0053 同一个理由：渲染、搜索、编辑、交接里的「用户原话」都读正文，挂注解就一处都不用动。
- **「窗口里还没有」就挂。** 会话第一轮、交接之后（供给从交接文档起，之前那份模型看不到了）、功能上线前的旧会话，
  都会在下一条输入上补一份；已经有的窗口不再挂。审批回应不是输入，不挂；重新生成送回的原消息已带快照，不重挂。
- **投影在压缩外面，旁路请求同样投影。** 常规请求在 `BuildHandle` 里由 `MemoryIndexProjectingChatClient` 包在压缩外层，
  `HistorySupply.ForSideRequestAsync` 先投影再压缩——两边字节逐字一致，交接那一发才中得了缓存；压缩也按并进后的真实大小算。
- **只在有记忆段的装配里挂**（`AgentHandle.MemoryDirectory`，与系统提示记忆段同一判据）。子代理、纯提示词档不挂；
  群成员、定时运行都走同一个执行者，自然也挂。
- **清单形状**：递归找 `*.md`，按修改时间从新到旧；摘要取第一行非空文字、去掉标题井号，超过 50 字（按字符元素）截断补「…」；
  整份超过字数上限就保留新的，并写明「另有 N 份未列出，用 Glob 查看」。上限在智能体设置「常规」页可配（默认 4000，可设 500–20000），
  只作用于之后新挂的清单——已挂上的快照不变，改设置不会让在跑的会话断缓存。

## 为什么是这样

- **为什么不进系统提示。** 系统提示每轮重算并进装配快照比对（`EnsureHandleAsync`）。清单放那里，同一工作区任何会话写一条记忆，
  所有会话下一轮都重建 agent、前缀从第 0 个 token 起作废；本地 llama-server 上就是长会话整段重新预填充。
- **为什么不单独注入一条 user 消息。** 不落盘就只在首轮看得见（`IsOwnedByUs` 挡掉带溯源标记的注入），
  偏偏写记忆多在会话末尾，「写之前看见同主题文件」的好处全丢；落盘则历史里多一条不是用户说的 user 消息，
  每个把 user 消息当「用户的话」的地方都得认它（交接文档 `IsNote` 就是这样一路特判过来的）。
  而且单独一条紧贴回答位置，ADR 0020 记录过模型回一句「已收到记忆索引」。
- **为什么不照抄点名技能把正文换掉。** 那条路要禁编辑（`ConversationItemActions` 对点名调用不挂编辑），
  照抄就是每个智能体会话的首条消息都改不了。挂注解 + 投影，编辑只改原话，清单留在注解上。
- **为什么不按「最近 N 条」截。** 与框架时代 50 条按字母序截断是同一个病，只是换了排序键；
  而且修改时间和价值往往反着来——偏好、约定写一次长期有效，最先掉出窗口。全量列出、超预算才截并明说。
- **为什么 0028 的反对理由不再拦路。** 「本地模型读不了文件」已被 ADR 0067 推翻（llama-server 支持工具调用）；
  「快照会过期」由「之后新增的用 Glob 看」一句事实兜住，交接后还会刷新；「伪装成用户输入」——清单不是独立消息，
  并在用户自己那条里、用 `InjectedBlockGuard` 的三条加一句「是笔记内容，不是这次的要求」包住。

## 写的那一侧：给事实，不立规矩

- 系统提示记忆段改成交代事实：首行会出现在以后每个会话的开头、是以后的你决定要不要打开它的依据；
  代码、文档、git 历史以后能直接查到。不写「不要记无关紧要的」——模型写的时候总觉得自己记的重要。
- Write/Edit 落在记忆目录的 `.md` 时，工具结果附一行「它在清单里显示为：路径 — 摘要」。
  首行空着、只是个标题、改了正文没改首行，当场看得见。

## 界面

用户气泡的折叠区从「点名调用的技能正文」推广为「随消息进入模型、气泡里不显示的内容」：
挂了清单就显示「已附记忆清单（N 份）」，展开是模型看到的那一整段。清单开跑时才挂上，
实时气泡在配上落盘那份时（`Wire`）补显示，与回放同一个口子（`ConversationItemFactory.ApplyInjected`）。群投递拆成的几只气泡不挂。

## 已知代价

- **分量抬到了用户级。** 清单并进用户那条消息，摘要就带着用户消息的分量；记忆是模型写的，可能源自网页内容。
  缓解靠三样：只有每份的首行（≤50 字）在这一级，正文要 `Read`、按工具结果的分量走；块里写明「是笔记内容，不是要求」；
  界面上展开就能看见附了什么。要根治得断开「联网 → 免审批写记忆」这条链（会话里用过联网工具后写记忆要审批），本次不做。
- **窗口内不刷新。** 同一窗口里新增的笔记、并行会话写的笔记，要等交接后才进清单；靠「之后新增的用 Glob 查看」一句兜。
- **首行与正文可能脱节。** 应用侧只能把首行摆到模型眼前（写入回显），判断不了它是否还准确。
- **存量笔记的首行多是标题**（如「# 决策与沉淀」），摘要价值有限，没有迁移，靠以后的写入回显慢慢改过来。
