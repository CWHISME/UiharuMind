# 交回改成对方来信：醒着插进那一轮，闲着追加再唤醒，去掉合并窗口

> **状态**：accepted，**已实现**（2026-10-04）。后台任务插进一轮先随 `86e54ea0` 落地，其余随本篇。
> 修订 [ADR 0025](0025-子代理默认后台化，报告由唤醒轮交回.md) 的取舍「报告不走注入队列」「合并唤醒」与
> 「已知代价」里那句报告文案；修订 [ADR 0021](0021-子代理运行落成一等会话，改走TurnDriver.md) 的取舍
> 「后续报告落成真消息，不走注入队列」；把 [ADR 0044](0044-委派门面统一为SendMessage，子会话骨架不动.md)
> 「给某人发消息」的说法补到回信那一侧。

## 背景

两件事凑到一起：

**交回总要等对方这一轮收了。** 后台任务与子代理报告都是「父会话忙就每 5 秒再看一次，闲了才追加、再起唤醒轮」。
一轮可以很长：「设置模块优化」群里白露串行一轮跑了 24 分钟，14:28 启动的全量回归 40 秒就跑完了，
结果却挂着等她说完；她只好去读日志，才发现早已跑完。「Revew」群里御坂美琴 10:56 到 11:04 一轮没停，
期间跑完的四个后台任务在她说完后被拼成一条一起交出，最早那个晚了 8 分钟。
「不要轮询，结果会送回来」的承诺，在对方醒着的时候恰恰不成立。

**回信还在用函数调用的说法。** ADR 0044 把委派改成 `SendMessage`、全篇写「给某人发消息」，
就是不想让模型把对方当一次性工具：派活 → 等结果 → 自己总结。可交回来的那条还写着
「以下是你先前那次**委派**……在**工具调用结束之后**产出的**后续结论**」「这是**子代理交回的报告**」——
发的时候是在跟人说话，收的时候又被告知这是一次调用的产出。

## 决策

1. **送达只有一套，按对方醒没醒分两条路**，后台任务与子代理来信共用：
   - 对方这一轮**在跑**：插进那一轮，下一次模型调用前取走，随那次调用落盘。群成员经群调度插
     （与群插话同一条路：`GroupMemberTurnState` 封口、收尾时撤回没消费的）。
   - 插不进、或那一轮**没消费就收了**：撤回来，追加进历史，再起唤醒轮（即原来那条路）。
   - 送到只认收信人历史里有它：离开队列只是被取走，要随取走它的那次模型调用结束才落盘——中间进程没了就丢，
     那次调用没发出去（刚取走就被停）也不会落盘。所以取走后等它进历史（那一轮还在跑也不必等它跑完）；
     那一轮收了它还在队列里、撤不动（执行者已换掉）、或取走了却没进历史，都改走落盘。
     「还没回信」的标记与 `PendingReport` 因此到它进了历史才清（评审实测找出：最初按「离开队列」算送到）。
   - 单聊这一套是 `SessionDelivery`：信（`SessionLetter`）只管插进去长什么样、闲着时怎么落，
     怎么送归它。后台任务的结局与子代理的回信各是一种信。唤醒轮不等它跑完，送信方的收尾不陪着。
2. **去掉 1 小时合并窗口。** 插话本身就是合并：第一封来信叫醒对方，那一轮跑着时陆续到的直接插进去，
   唤醒次数跟着「对方空着的间隙」走，不再跟着来信封数走。窗口留着的副作用是四个回了三个，
   主会话干等最慢那个，最长一小时。
3. **「还有几位没回」作为事实写进来信**，替代窗口原本靠「等齐」才给的东西：
   主会话名下还有没回信的，在头部附一句「你还在等 N 位的回信」。数的是人不是轮次（同一位排着几轮算一位）。
   要不要等齐由模型自己判断。
4. **连续无用户参与的唤醒轮上限（现为 32）搬进共用流程，后台任务也计入。** 撤销后台任务「不计」的豁免：
   自动档下唤醒轮里再起后台任务，同样会自己转起来。这是保险丝，不是优化。
5. **删掉「用户说过话就跳过唤醒」**（`ShouldSkipWakeForParent` 与两张时间登记表）。
   它是为窗口拖出来的那段时间补的：窗口期内用户先开口，报告已被那一轮读到。没有窗口之后，
   落盘与唤醒之间只剩一瞬，`SessionWakeTurn` 原子占位（会话忙就不起）已经够了，不另做历史比对。
6. **子代理的来信写成「谁发来的」**：

   ```
   来自 名字 [sub-session: e3cf3ee4…]，回你之前发的「开头…」：

   正文…
   ```

   - 署名用与工具回执同一种 `[sub-session: …]` 标识，模型照着就能用 `SendMessage` 接着回。
     没有具名角色时，名字取 `role`；再没有就只留标识——会话标题这时是任务正文的开头，不是名字。
   - 用「来自 X：」起头，**不用群投递的 `[名字]: 内容`**：ADR 0060 实测过，user 消息里光放
     「[名字]: 内容」，模型会当成用户单独发给他的，群投递因此加了一行「来自群聊：」。
   - 「回你之前发的『…』」保留对应关系：来信可能隔了好几轮才到，话头已经变了（ADR 0025 已知代价）。
   - 状态改写成事实：更正写「（更正上一封）」；中断写「对方被打断了（原因），以下是说到一半的内容」，
     没内容就写「对方没回任何内容」。不再写「不要把这次委派当成已完成」这类命令。
   - **去掉「这是子代理交回的报告，不是用户的回复……」那句长警告。** 当初的事故（主代理把来信里的
     「可以提交」读成用户点头）根子是来源说不清，署名已经补上了这个事实。冒烟仍误读就补半句
     「（对方发给你的）」，不先把整段放回去。
   - 后台任务不是人，不套「来自」，沿用打头那句「你先前启动的后台任务 `id`（描述）已结束……」；
     同理去掉其后「这是任务的运行结果，不是用户的回复」——来源那句已经说清，输出末尾整段在围栏里。
7. **原地替换照旧。** `ResolveSlot` 的规则是「上一封还停在末尾、没被读过，就用新的替换」。
   插话路径不必另做：同一个子会话的回信按先后串行送（`_deliverGates`），上一封送到了才送下一封，
   不会有两封同时在队列里。插进去时派活者醒着，说明上一封（若有）已被读过，有就写成更正。
8. **「还没回信」的持久化标记，改成被消费或已追加之后才清。** 插在队列里还没被取走时进程没了，
   子会话里有结论，标记也还在，启动扫描能找回来。启动扫描要分两种：子会话已经说完、只是来信没送到的，
   **补送那封信**；没说完的，才落「在应用退出时被中止」。现在不分，一律写成中止。
9. **工具这一侧的说法跟着改**：`SendMessageDescription` 去掉 "subagent"；派出回执从
   "Dispatched to the background … Its report arrives" 改成 "Sent … NO REPLY YET … Their reply arrives"；
   派活中途追加一句的回执也不再说 report。`SubAgentTool` 交回内容里还有几处 report 措辞（停下、超时那些注记），
   本篇不动。

## 取舍

- **ADR 0021 当初为什么不走注入队列，这两条还成立吗？** 一是队列只在内存、不落盘；
  二是拿不到注入器时静默返回 false，调用方毫无兜底。决策 1 把这两条都接住了：false 就走追加，
  没消费就撤回再追加，正常退出时落盘（`DeliverOnShutdown`）。剩下崩溃那一格，
  子代理靠决策 8 补回；后台任务的结局本来就只在内存里，崩溃丢失与改前相同。
- **空着、来信又隔得开时，每封各起一轮。** 每轮把整段上下文重发一遍：白露一次调用 19 万输入 token，
  大多命中缓存，但撞过限流（日志里的 429 rpm exhausted）。先不加去抖，按实测再定；
  真要加也只到秒级，接住「几乎同时说完」那种，不回到小时级。
- **失去「等齐了统一汇总」的默认行为。** 模型可能拿着部分来信提前收口。用决策 3 补事实，不立规矩。
- **去掉长警告有回归风险。** 0025 那次事故是真的。验收时子代理冒烟场景必须覆盖
  「来信里带『可以提交 / 你看行就合』」，主代理不得据此直接改文件或提交。
- **渲染不变。** 插进来的来信也画成旁白（`ConversationHistoryRenderer.CreateUserItems` 已按
  `IsHandedBackReport` 分流），与回放同一个样子。

## 实现

- `AI/Execution/Delivery/`：`SessionDelivery`（怎么送）、`SessionLetter`（信）、`ISessionDeliveryHost`（可测缝）。
- 后台任务：`SessionReportSink` 只剩一种信；群成员仍走 `GroupMemberReportSink` → 群调度。
- 子代理：`BackgroundSubAgentDispatcher` 的回信是 `ReplyLetter`，删掉合并窗口、`ShouldSkipWakeForParent`
  与两张时间登记表；`SubAgentReportHandoff` 拆出 `Write`（闲着时落）与 `Compose`（插进去的那封），
  `BuildText` 换成来信格式；`ChatSession.PendingReport` 落盘，启动扫描据此分流。
- 自激封顶从调度处搬到 `SessionWakeTurn`（`NoteUserTurn` 一并搬过去）。
- 测试：`SessionDeliveryTests`（插进并取走 / 一轮中途取走 / 插进未取走回退 / 闲着直落 / 没可插的等闲 / 后台任务按编号只落一次）、
  `SubAgentReportHandoffTests` 的来信文案；删掉合并窗口那批测试。
- **未做**：启动扫描分流与 `SessionWakeTurn` 封顶没有单测（都走 `SessionManager` 单例）；
  子代理冒烟（取舍第四条那项误读检查）待跑。
