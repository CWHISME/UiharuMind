# 私聊抢占群轮，私聊完接回

> **状态**：accepted，**已实现**（2026-10-04）。
> 修订 [ADR 0046](0046-群发言投递进成员会话，群壳只记流水.md) 未决「私聊时他正在跑群里那一轮」的相遇策略（私聊排队 → 私聊抢占）；
> 更正 [ADR 0049](0049-并行群聊调度（唤醒边界@路由主持人），与串行并存.md) 修订段里「私聊插话照旧续轮」一句；
> 化身同样适用（[ADR 0055](0055-离席由化身值守，对成员就是用户本人.md)）。

## 背景

「设置模块优化」群里，化身 15:12 正跑着离席那一轮，用户在它的窗口里私聊一句（「这个 rotate 看着像刷新，换 undo 试试」）。
这句在 15:30:20 才第一次出现在请求里：中间 18 分钟化身照原计划一路跑，夹着几十次 429 重试；
气泡发送时就画出来了，排队只弹过一条转瞬即逝的提示，看上去就是被无视了。

排队是 `c95876a9`（09-25）定的：群轮整轮持闸，私聊等闸。它当时拦掉插话的理由仍然成立——
群轮里说完的话都进群（ADR 0060 修订「回复就是发言」），私聊插进去，回给用户的话就泄进群里。
而 ADR 0049 修订（09-28）写成了「私聊插话照旧续轮」，与代码不符，读文档的人会以为私聊能插进去。

## 决策

1. **私聊抢占，不插话**。用户在成员或化身窗口里发话时，群轮占着闸就先叫停**他这一轮**（别人照常说），
   等它停稳再跑私聊。一轮只有一条通道：群轮的回复进群、私聊的回复只给用户，不出现「这一轮后半段算谁的」。
   落在 `GroupMemberTurnGate`：群轮抢闸拿到一个可叫停的句柄（`PreemptibleTurn`），私聊等闸时**先排上队、再叫停**——
   群轮一放闸就归私聊，不会被同时醒来的接回抢走。
   - 私聊要在**装配之前**过闸（`ConversationTurnRunner`）：群轮整轮持着执行者自己的锁（流式、429 重试、工具调用期间都持着），
     先装配就会一直等在那把锁上，根本走不到叫停这一步。两边的加锁顺序都是先成员闸、后执行者锁。
   - 跑完之后才到的叫停不算（`WasPreempted` 只认没跑完的）；同时停了群按停群算。
   - 否掉「插进群轮、私聊之后的回复不进群」：私聊插进去之后，他可能先回用户、再接着把群里的活做完，
     最后那句结论是给群的；按「最近一条用户消息是私聊」一刀切会把它吞掉，规则分不清。
   - 否掉「插进群轮、给化身留 `SendMessage` 中途发群」：插进去之后的回复要归私聊，结论就得靠模型记得调工具，
     正是 ADR 0060 修订段 26–27 实测会漏、而且漏得看不见的那条路。
   - 代价：叫停时在途的那次模型调用与工具调用作废（跑了一半的测试要重跑）。
2. **私聊完接回**。被叫停的那一轮按「被打断」记（`_interrupted`），另记一笔「被私聊叫停」，约好闸空了再叫醒他：
   成员走单人唤醒（与附注同一条路，`WakeMemberAsync`）；化身是新结局 `Preempted`，不计出手次数、不排退避，
   私聊放闸即由离席接回。私聊一句接一句时，接回撞上闸被占着就再约一次（成员与化身同样，各只约一次，免得放闸时连叫几轮）。
   - 装配阶段就被叫停的，投递根本没进他的历史：游标、已读、入群摘要、附注都退回取投递之前，接回时照样交。
   - 私聊那一轮没被消费的插话，在放闸**之前**同步撤掉：放闸可能当场接回群轮，同一个执行者，留着会被群轮取走、回复进群。
3. **接回时有没有新话都附一句事实**（`GroupTranscript.PrivateResumeNote`），贴在重锚之后、界面不画：
   「你上一轮在群里的活被用户私聊打断了。私聊里说的、做的，群里都看不到。」
   期间别人的新话照常随投递交。不写「接着做完」：用户可能在私聊里叫他放下或改方向，
   做完了、没做完、改了主意，由他看着自己的历史定。原来「被停或失败、没新话才交 `ResumeNote`」的口径不动。
4. **私聊期间用户停了整个群，就不再自动接回**：成员留给「继续」（仍按被打断交 `ResumeNote`）；
   化身按停下处理，私聊完过 `StopDelay` 再叫。私聊期间被移出群的成员也不再叫。

## 后果

- 输入区那条提示从「已排队」改为「已先停下那一轮来回你，私聊完会接着做」（`GroupMemberPreemptTip`）。
- 抢占只来自用户在成员窗口里发话：群轮跑着时成员窗口处于外驱态，重试点不了。成员会话的自动唤醒（后台任务交回）走群附注，不经私聊闸，不抢占。
- 私聊过闸改在装配前、且不再 `ConfigureAwait(false)`：从前等到群轮放闸后在线程池上续跑，整轮私聊都不在界面线程上
  （日志里的「ConversationTranscript applied off the UI thread」）。
- 测试：`GroupMemberTurnGateTests`、`ParallelGroupChatTests.PrivateChat_*`、`GroupAwayControllerTests.PrivateChat_*`、
  `ConversationTurnRunnerTests.GroupMemberSession_PreemptsTheGroupTurnBeforeAssembling`。
