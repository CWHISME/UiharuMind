# 接口地址就是接口格式：地址给候选，格式从尾段反推

> **状态**：accepted（2026-10-30）。
>
> **改的是** [ADR 0092](0092-远程模型候选来源改用运行时模型目录，做成通用能力.md) 决定 5 的后半句：
> 那条定的是「`ApiFormat` 只由目录的 `supported_endpoints` 写入，手输/未选不碰」。
> Messages 线接上之后（[ADR 0100](0100-加密思考票据按消息各挂各的，随消息落盘，收成协议无关的思考模块.md)、
> [ADR 0101](0101-思考回填改为消息对象绑定，序号对齐退场.md)），
> 「目录没声明端点」从「不影响」变成了「这个模型没法用」。

## 背景

三条 wire 都通了：`/chat/completions`、`/responses`、`/messages`。目录里只声明 `/messages` 的 Claude 系
也不再被过滤，选中即推成 Messages——CommandCode 这种**会声明 `supported_endpoints`** 的目录本来是通的。

缺口在目录**不声明端点**的时候（OpenCode 的最简目录只有 `id`；代理网关的 `/v1/models` 几乎从不声明）。

第一版做法是另加一个「接口格式」下拉，结果把一件东西拆成了两半：

- 格式说 Messages，地址还停在 `.../v1/chat/completions`；
- 而 `WireProtocol.Resolve` 当时遇到「尾段是另一条线的端点」是**原样返回**的，
  于是 Messages 形状的请求体打到 chat 端点——404/400，配置里两个字段各自看着都对。

所以结论不是「再加一个字段」，而是**这两个字段本来就是同一个东西**。

## 决定

1. **添加模型页只有一个「接口地址」控件**（可编辑 ComboBox）。选哪个地址就是哪条线，
   没有第二个格式字段可填。位置不变：自定义服务商平铺在配置区，预设服务商收在「高级设置」里。
2. **候选按模型数据给，目录声明优先**：
   - 目录声明了端点 → 只给声明的那些；
   - 没声明时模型 ID 含 `claude` → 只有 `/messages`；
   - 其余：有目录的服务商（OpenCode 的最简目录）与自定义网关三条全给，
     单线预设（DeepSeek/智谱/Agnes）只给它自己那条——摆一个必然 404 的选项出来没有意义。
3. **默认值在「选模型」那一刻切过去**：声明里有 `/messages` 的 Claude → messages，
   否则**声明里有 chat 就走 chat**，只有「只声明 responses」的才走 responses。
   初始化、复制、拉目录只重建候选，不动已填的地址。

   实测依据（CommandCode `/provider/v1/models`，2026-10-30，94 个模型）：

   | 端点组合 | 数量 |
   |---|---|
   | `/chat/completions` + `/responses` | 72 |
   | `/messages`（全是 Claude） | 11 |
   | 只有 `/chat/completions` | 11 |
   | 只有 `/responses` | 0 |

   所有 `gpt-*` 都同时声明两条且 chat 在前；文档也只说「answer on `/v1/chat/completions`,
   most of them on `/v1/responses` as well」——responses 是**也支持**，不是该用。
   `responses-only` 这条分支在它上面是空集，但 OpenCode 那种「一个模型只由一条 API family 服务」
   的网关会有，所以留着。
4. **用户手改过地址就不再自动改**（`_modelPathEditedByUser`）：改模型 ID、拉目录都不顶回去；
   只有从候选里**点**一个模型（明确表达「按这个来」）才重新推荐，且换的是那条线、保留用户填的网关。
5. **格式仍随模型落盘，但由地址派生**：`BuildResult` 用地址尾段反推 `ApiFormat`
   （`RemoteEndpoints.FormatOf`），认不出尾段（只填到 `/v1`、裸域）时**保留原值**——
   运行时按格式补后缀，那种地址本来合法，判成 chat 会把一个能跑的模型存坏。
6. **`WireProtocol.Resolve` 遇到「尾段是另一条线的端点」改为替换**，不再原样返回。
   这条修的是根因，顺带让历史存档、CLI/脚本建的模型、任何没走界面的入口一起自愈。
7. **供应商可以声明每条线的端点**（`BaseRemoteModelConfig.EndpointFor`，默认空 = 交给通用规则）。
   路径布局不都是「同一段前缀换个尾段」——OpenCode 的 chat/responses 在
   `/inference/openai/v1/`，Anthropic 在 `/inference/anthropic/v1/`
   （[官方文档](https://opencode.ai/v2/docs/console/api/inference)），换尾段会拼出打不通的地址。
   用户把地址改成别家网关时（不在该供应商声明的那几条里）仍按用户的地址走，预设不覆盖。

   两家网关的布局正好相反，也正好说明这条为什么不能写在公共层：

   | 网关 | 三条线的路径 | 处理 |
   |---|---|---|
   | CommandCode | 同在 `/provider/v1`（`/chat/completions`、`/responses`、`/messages`） | 换尾段即对，不覆写 |
   | OpenCode | chat/responses 在 `/inference/openai/v1`，messages 在 `/inference/anthropic/v1` | 覆写 `EndpointFor` |

## 取舍

- **为什么不按模型 ID 猜其它协议**：只有 Claude 能猜——CommandCode 的文档直接写明
  「Claude 只能用 `/v1/messages`，发到 chat/completions 或 responses 返回 400」，OpenCode 也是
  「Claude 与 Qwen 走 Messages」。其余（`o9-*` 是不是 responses）猜不准，交给目录声明。
- **为什么两条都声明时留在 chat**：responses 在本仓是**附加能力**，chat 是基线——
  响应清洗、请求改写、思考票据、`cache-audit` 全都以 chat 为参照。目录写「多数模型也支持
  `/responses`」，那是可选路，不是主路；把它当默认等于让一批跑通的模型突然换协议（0092 的老教训）。
- **为什么 Claude 只在目录没声明时才算数**：目录是实际端点的声明（CommandCode 文档就要求「选端点前先查
  `supported_endpoints`」），它若明说这条 Claude 只走 chat，再按 ID 判成 messages 就是稳定 404。
- **为什么地址仍然可编辑**：自定义网关的路径没有规律可循；候选只是「按模型数据能推出来的那几条」。
- **为什么不用两个控件联动**（选格式改地址、改地址反推格式）：联动要维护「谁改的」这类状态，
  而界面上仍然有两个真值。合成一个控件后，格式是纯派生量，没有状态可冲突。

## 已知代价

- **没声明布局、也没有文档的供应商仍按「换尾段」推**：候选是「按已有数据能给出的那几条」，
  不是白名单，推错了手输。
- **单线预设的候选只有一条**：想临时试别的线得手输地址（预设没声明、目录没给，我们无从知道它支不支持）。
- 编辑模式不跟着目录改地址：换协议会让整条历史的前缀缓存与思考票据作废，必须由人按下。
