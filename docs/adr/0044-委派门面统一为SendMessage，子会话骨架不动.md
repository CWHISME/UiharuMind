# 委派门面统一为 SendMessage，子会话骨架一行不动

`RunAgent` / `RunReadOnlyAgent` / `ContinueAgent` 三个工具退役，**暴露给模型的通信原语只剩一个**：
`SendMessage(to, content, scope?, mode?)`。群聊广播、私聊、委派、插话全走它，
区别只在**收件人在不在当前会话**。

底层骨架——`ParentSessionId`、子会话、后续报告、唤醒轮、`SessionRunRegistry`、
`BackgroundSubAgentDispatcher`——**一行不动**。本 ADR 换的是门面，不是骨架。

本 ADR 修订 [0003](0003-角色档位定版为四档真旗标.md) 的 `MountAgents` 部分与
[0025](0025-子代理默认后台化，报告由唤醒轮交回.md) 的工具形态，
并兑现 [0042](0042-对话页合并为单页，类型由左栏切换器唯一决定.md) 那句
「子会话 / 子代理机制原地不动，是群聊的骨架」。

> **已落地**（`6b9b2a28`）。
>
> **【修订】「群聊广播走它」收窄为只对智能体成立**：普通角色没有工具，在群里用正文说话，
> 见 [0046](0046-群发言投递进成员会话，群壳只记流水.md) 决策 4。

## 背景

群聊方案
（[`docs/proposals/代理人格化/群聊多角色代理设计方案_v5.md`](../proposals/代理人格化/群聊多角色代理设计方案_v5.md) §6.3）
要取消「子代理」这个说法。读进去会发现，它反对的**不是** `ParentSessionId`，而是工具签名教给模型的心智：

> `RunAgent(agent, task)` 的签名本身就在教模型「agent 是可运行的东西、task 是输入、产出是返回值」——
> 这是**函数调用心智，不是对话心智**。

后果具体：主代理会把角色当工具人，派活 → 等结果 → 自己总结，对方**没有机会反问**、
没有机会说「你这个需求我没听懂」。而「允许反问」恰恰是委派区别于 API 调用的地方。

骨架里没有心智。`ParentSessionId` 不教模型任何事——它是存储关系。
所以「取消子代理」与 0042 的「骨架不动」不冲突：**换门面就够了**。

## 决策

1. **`RunAgent(agent, task)` → `SendMessage(to, content)`。** 收件人不在当前会话即为委派，
   机制上仍然开一个带 `ParentSessionId` 的子会话，仍然后台派出、仍然由唤醒轮交回报告。
2. **`RunReadOnlyAgent` 删除。** 只读不再靠「装配期不挂写工具」，靠**权限档**
   （[0010](0010-权限档定版三档，越界写入贯穿三档.md)）加派活者在 `content` 里的要求。
   `ExploreSubAgent` 身份卡随之退役。
3. **`ContinueAgent` 删除。** 续跑 = **向一个休眠会话发消息**。
   归档不是删除，是休眠（方案 §6.9「休眠态 0 调用」），发消息即唤回。
4. **`MountAgents` 从装配期过滤降为场景层名单。** `to` 是**自由字符串**，不进工具 schema——
   否则成员一变工具定义就变，同一会话内前缀失效。名单只出现在场景层文本里告诉模型有谁可找；
   发给名单外的人**运行时拒绝并回报名单**。
5. **工具定义在一次会话内永不变。** 这是上条的推广：所有动态值（成员名单、可用身份）
   一律放场景层，不进 schema。
6. **一层封顶保留。** 群成员是 peer（第 0 层），他们开的才是子代理（第 1 层），
   子代理不能再开子代理——`AssemblyInvariantsTests` 那条不变量原样有效。

## 取舍

- **为什么不是保留 `RunAgent` 再加一个 `SendMessage`。** 两个原语并存，模型会挑那个看起来更像
  「把活派出去」的用——函数调用心智不会因为旁边多了一个选项就消失。
  这次改动的全部价值在于**只剩一条路**。

- **删掉 `RunReadOnlyAgent` 的代价，被权限档接住了。** 探索档原先是装配期就不挂写工具，
  删掉之后「只读」变成靠指令说，单看是净损失。但权限档保留（方案 §2.6③ 要删权限档，
  **不采纳**，见 [0043](0043-角色档位从四档枚举改为一轴派生.md) 同类理由）：
  `ReadOnly` 档下子代理真要写，照样弹审批卡，且
  [0010](0010-权限档定版三档，越界写入贯穿三档.md) 的「工作区外写入永不自动放行」贯穿三档。
  **机制托底还在，只是不再有「探索档」这个独立形态。**
  丢掉的是「轻量模型 + 恒定只读」这一组默认值，需要时由派活者显式指定模型补回（0031 的能力仍在）。

- **为什么 `MountAgents` 不干脆删掉。** 方案 §6.8④ 只要求「别把名单写进 schema」，
  不是「别有名单」。名单留在场景层，工具定义纹丝不动，缓存不受影响，而
  0003 那条不变量（子智能体不能比派活者能力更大）还有地方落。

- **`ContinueAgent` 映射成「唤回休眠会话」不是凑数。** 方案 §6.9 本来就写了
  「休眠态 0 调用，成本只发生在被唤醒的轮次」——两边语义天然对齐。
  真正的改动是：**归档态的会话必须可被寻址**，不能在归档时把 id 丢掉。

## 代价（明说）

- **`ExploreSubAgent` 退役。**（**【修正】拟稿时写的是「右栏两档显示塌成一档」，事实不成立**：
  全仓 `ESubAgentType` 在 UI 层零命中，`ChatSessionMeta.SubAgentType` / `ChatSession.SubAgentType`
  只在 Core 内部传递，从未被任何 ViewModel 渲染。两档**从来就没有界面区分**。)
  真实情况：两档唯一的用户可感差异是**工具描述文本本身**（`RunReadOnlyAgentDescription` 里那句「只读」）。
  退役它因此不是「移除已有区分」，而是少一条本来也没被展示出来的分支。
  「这次委派能不能改东西」改由**权限档**回答，那是会话级的。
- **老存档里挂过 `MountAgents` 的角色，过滤时机从装配期挪到运行时。** 行为上更宽松了一瞬间
  （模型可以尝试发给名单外的人，然后被拒），换来的是工具定义稳定。
- **模型需要重新学一套心智。** 提示词里要讲清楚「委派 = 给不在这儿的人发消息」，
  而不是继续用「派一个子代理」的说法。工具纪律段要改写。

## 未决

> **拟稿时把「派活者那一轮封存还是挂起」列为未决，已撤销——现架构本来就实现了方案 §3.3。**
>
> | 方案 §3.3 的伪码 | 现状对应物 |
> |---|---|
> | 「存在未完成的消息回执 → 标记 awaiting」 | **`HasPendingWork`**（本会话 + 名下未交回的后台子会话，驱动角标与右栏计数） |
> | 「回复一到自动开新一轮」 | **唤醒轮**（含排队、合并、32 轮自激封顶） |
>
> 而 §3.3 那半句「**控制权留调度器**」应当**不采纳**——术语表已经警告过这个坑：
> 后台子代理跑着时主代理那一轮已经结束、没有轮次可插，拿它去点亮忙碌，
> 用户打的字会进注入队列等到下一轮（可能几分钟后）才被消费，
> 「按了发送、显示等待插话、然后什么都不发生」。**现状答得比方案好。**
>
> **结论：门面替换是纯粹的门面替换，不改运行时行为。**
> **【已答】roster 挪到场景层之后还算不算装配输入。** 摸底指出
> `AgentAssemblyFacts.MountedAgents` 目前把名单纳入重建判据，三条快照测试钉着
> （`ChangedSubAgentRoster_*` / `RenamedOrRedescribedSubAgent_*` / `SubAgentRoster_IsIgnored_WhenTheToolIsOff`），
> 与决策 5 看似冲突。**不冲突，两句话说的是不同时刻**：
>
> - 决策 5 管的是**一次会话之内**——工具 schema 不因成员增减而变，所以前缀不失效；
> - 重建判据管的是**装配那一刻**——场景层文本也在前缀里，名单变了当然要重新装配。
>
> **结论：三条快照测试全部保留，`AgentAssemblyFacts.MountedAgents` 字段保留。**
> 要改的只有一件：roster 从**工具 description**（`SubAgentTool.Create` 里的 `RosterHeading` 段）
> 挪进**场景层文本**。schema 不含名单，装配仍然感知名单。

- 「允许反问」落地成什么。方案把它列为委派区别于 API 调用的关键，但它是**人格与提示词**的事，
  还是需要一个机制（比如被委派方可以回一条不带结论的消息而不触发交回）——未定。

## 分阶段

1. **工具层归一**（已落地）：三把工具 → `SendMessage(to, content, role?, model?)`；
   `to` 自己分流（人名 → 新开；子会话标识 → 续上）；roster 从工具 description 挪进系统提示的
   委派一节（`ToolDisciplineFacts.DelegationRoster`）；政策正文整段改写成对话心智；
   机器人图标判据、交接文档措辞、两条不变量测试跟着改。
2. **存量就地封存**（已落地，**口径比拟稿时收紧**）：拟稿写的是「`ExploreSubAgent` /
   `ESubAgentType` 退役」，落地时改为**封存**——真删会让存量静默出事：
   老的探索子会话存档里钉着 `SubAgentType: Explorer` 与 `CharacterId: ExploreSubAgent`，
   拔掉枚举它们重建后**变成可写**，拔掉卡片它们**打不开**。
   这是权限相关的行为改变，不能靠"个人项目量级"一句带过。
   沿用仓库既有口径（[0013](0013-磁盘布局按性质分树，旧布局就地废弃.md)、
   [0028](0028-文件记忆退役，记忆改为工作区目录由模型自管.md)）：**就地封存，不迁移，也不破坏**。
   - **封存**（保留并在注释里标明「仅为重建存量」）：`ESubAgentType`、`SubAgentProfile.Explorer`、
     `DefaultCharacter.ExploreSubAgent` 卡、`AgentSettingConfig.ExplorerSubAgentModelName`
   - **真删**：设置页的「探索子代理模型」选择器——它对新委派已经不起任何作用，
     留着只会让人以为它还管用
3. **待做**：`Lang.resx` 里 `AgentSettingExplorerSubAgentModel` / `...Desc` 两个键现在没人引用。
   本轮**刻意没动**多语言资源——那两份文件当时有未提交的在途改动，不去缠它。
