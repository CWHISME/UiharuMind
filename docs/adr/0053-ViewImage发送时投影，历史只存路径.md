# ViewImage 发送时投影，历史只存路径

视觉模型的智能体经 `ViewImage` 看自己找到或画出的图。Chat Completions 里**只有 user 消息能带图**，
tool 消息只收文本，所以图得以一条 user 消息紧跟在工具结果后面进上下文。这条 user 消息
**只存在于发出去的请求里**：历史落盘的只有工具结果（原图路径 + 预览副本路径），
每次服务调用时由最内层客户端读副本、把图投影成 user 消息插到那一串 tool 消息之后。

## 为什么不把合成的 user 消息写进历史

ADR 0052 留下的原设想是落盘一条带新标注的 user 消息。否决：全仓有一整串地方默认「user 消息 = 用户说的话 / 一轮的开头」，
每一处都得认出这条新消息——渲染来源（`ConversationMessageOrigin.KindOf` 会把它画成右侧用户气泡）、
前台裁剪的轮首锚点（ADR 0037/0038）、编辑与重试的挂接（会给它挂上「以它为输入重跑」）、
删除闭包（只按 CallId 收，删了调用会留下孤儿图）、交接回忆的「用户原话」、记忆检索的查询词、
子代理报告里的「用户插过话」、停止时插话队列里的残留。漏一处就是一个只在长会话里才显形的错。

投影把这些全绕开：历史里没有新消息形态，上面每一处都不用动。还白得两样：

- **折叠天然成组。** 压缩在投影之前跑（`MoveCompactionToLeaf` 把压缩挂在投影外面）。工具组被折叠，
  结果文本没了，投影就找不到它，图跟着消失——不会出现「调用折掉了、图还孤零零留着」。
- **非视觉模型自然降级。** 只在视觉模型的装配里挂投影；换到非视觉模型，历史里的结果就只是一行路径文本。

## 缩图在工具调用时做一次

SenseNova 一张 2K PNG 约 5MB，而投影的图每次服务调用都重发。调用时把图缩成预览副本存进草稿目录
（与用户附图同一套上限：长边 1568、单张 150KB 级），文件名带内容哈希、只写不改；之后每次投影读的都是这份副本，
**字节逐次一致，服务端前缀缓存不失效**。发送路径上没有任何压缩——用户附图也是组装消息时压一次就存进历史。

缩图器在 App 里（SkiaSharp），Core 不引用它：App 启动时注入（与 `BackgroundSubAgentDispatcher.Notifier` 同一做法）。
没注入时（CLI）原样复制，只拦超大文件。

## 挂载

与 `AnalyzeImage` 共用识图开关，两者互斥：当前模型自带视觉挂 `ViewImage`，否则挂 `AnalyzeImage`。
判据进装配快照的本就有 `VisionTool` 与 `ModelSupportsVision` 两项，切模型时下一次挂接自动重建，不新增快照字段。

## 已知代价

- **压缩的 token 估算看不见投影的图**，所以 `HistoryCompaction.CorrectedGroupTokens` 按结果里的预览行数
  补上每张图的上界，与内联图片同一口径。
- 看过的图每次服务调用都重发，直到所在工具组被折叠或截掉。
- 预览副本被删时投影改发一行「图片已不在」的文本，不报错。
- 工具结果之后紧跟 user 消息，各家网关是否都接受要实测；同一次请求里若紧接着还有插话，就是连续两条 user 消息。
