# 工作循环指令从框架默认搬到角色提示词

装配 harness 时不再把 `HarnessAgent.DefaultInstructions` 拼进 `HarnessInstructions`。
那段工作循环（先弄清事实 / 边做边说 / 失败换路 / 收尾总结）改写成
`AgentToolPrompts.AgentWorkLoop`，并**作为角色提示词的一节存在**：

- 内置智能体 `WorkspaceAgent` 的存档里直接写着这一节；
- 新建智能体档角色时，提示词框预填这一节；
- 片段库有一条同名内置片段（正文取同一个常量），随时可插回；
- 子代理把它拼进自己那份生成指令，`HarnessInstructions` 因此为空串。

`HarnessInstructions` 现在只装**按实际装配的工具集派生的使用纪律** + 工作目录这一事实段。

## 为什么

1. **harness 段用户看不见。** 它不在任何界面上，却每轮都发给模型。这与角色域这一轮的主线一致：
   挂载被退役、脚手架改成插入文本，理由都是「编辑页里看不到的东西不该悄悄进提示词」。
   工作循环是最后一处还藏着的段落。
2. **框架默认那段带第二个身份。** 全文 773 字符，第一行是
   `You are a helpful AI assistant that uses tools to complete tasks.`
   而框架把 `HarnessInstructions` 拼在 `ChatOptions.Instructions`（角色人格 + 工作区规矩）**之前**。
   于是每个智能体的系统提示都以「你是通用助手」开场，角色自己的人格排在后面跟它抢。
   子代理那边更明显：它自己的指令开头就是 `# Role  You are a sub-agent of UiharuMind…`，
   前面却先有一句「你是通用助手」。
3. **措辞里有几条是偏好而非事实。**「解释你的推理过程」「连续工具调用不要超过 4 次」对本地弱模型
   有用，对强模型是噪声。搬进角色提示词后，用户改得动——不需要我们再开一个「提示词覆盖」设置项
   （那一层刚在同一轮里被删掉，理由是排查要看两处）。

## 取舍

- **放弃「框架升级措辞自动跟随」。** 这正是当初把 `DefaultInstructions` 拼回开头的理由，
  现在翻案：跟随的代价是那段话既看不见也改不动，且强塞一个身份句。1.17 若改了措辞我们不会跟——
  但这段内容属于"我们要模型怎么干活"，本就该由我们说，而不是随框架版本漂移。
- **用户删掉它就真的没有了。** 不留代码兜底：留了就等于同一段话可能出现两份（角色卡一份、
  兜底一份），而"模型收到了两份相似的工作循环指令"比"少一段"更难查。预填 + 片段库两条路
  已经让它足够容易拿回来。
- **为什么不做成设置页里可编辑的全局提示词。** 那会让唯一权威重新分裂成两处（角色卡与设置页），
  与同一轮删掉四段工具提示词覆盖的口径相反。
- **正文只有一处：`AgentToolPrompts.AgentWorkLoop` 常量。** 内置智能体的存档、片段库播种、
  新建预填都引用它，不各抄一份。测试钉住内置智能体的 Template 真的含有它——
  否则哪天被顺手删掉，症状是"模型不会干活"，实机极难归因。
- **标题用一级（`# Work loop`）。** 它现在与角色卡里的 `# Task`、`# Style` 同级；
  harness 段里的纪律标题仍是二级（`## File operations` 等），两层不混。

## 代价（明说）

- **你已有的自建智能体角色不会自动长出这一节。** 存档里没有的东西不会凭空出现，
  而这轮之后 harness 段也不再给它。要么在编辑页用「插入片段 → 智能体工作循环」补上，
  要么自己写一段。受影响的只有本次改动之前建的智能体档角色。
- **`WorkspaceAgent` 存档的 `# Style` 少了一条。**「先弄清事实再动手」与工作循环第一条重复，
  已删。若你改过这张内置卡（`SaveDefaultCharacterDataPath` 下有覆盖文件），
  你那份不会跟着变——它会保持旧内容且没有工作循环节。
