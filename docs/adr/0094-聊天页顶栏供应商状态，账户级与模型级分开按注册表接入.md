# 聊天页顶栏加供应商状态：账户级读数与模型级计费分开，按注册表接入

> **状态**：accepted（2026-10-27）。
>
> **取代**：仓库外的评审批次 `F:\MyProject\Doc\顶栏供应商状态设计方案.md`（该稿在评审中改了四处：
> 轮末钩子、可见性门控、缓存粒度、单飞写法，均见下文加粗处）。

## 背景

用户选完模型就开始用，但界面上看不到三件事：**额度还剩多少**（订阅制的 5 小时 / 周滚动窗口，
打满后请求被拦才报错）、**这一刻是不是高峰期**（同一句话在高峰期烧双倍额度，界面毫无提示）、
**凭据是否失效**（key 过期要等发消息收到 401 才知道）。

三件事的共同点是都绑在「当前用的哪家供应商、哪个模型」上，且各家给数据的方式不同：有的能调接口，
有的只能按官方价目表在本地按时钟算。所以这件事不能写成「给聊天页加一条 CC 的额度条」，
而要写成「给顶栏加一个按供应商接入的状态位」。首批只接 Command Code（下称 CC），
其余供应商无实现时顶栏**零变化**。

## 决定

1. **读数放在「会话头里、模型名的右手边」**（用户拍板的位置，第三次才落到位）。
   它报的是「这个会话用的那家供应商」的额度，所以必须挨着**那个会话的模型名**：
   顶栏那个模型下拉是**全局选择**，与本会话未必是一家，挂在它旁边就是名不副实。
   主页面与 QuickChat 窗口都嵌 `ConversationView`，会话头是同一处，两边一次改完都对。
   读数单行 18px、不换行、超宽省略；没数据不占位。

   实现上它在 `ConversationView.axaml` 会话头的元信息行里：模型名按钮（按内容宽、最长 320px 截断）
   与读数并排，外加一个 `*` 余量列把会话编号钉在行尾——
   <b>模型名那格不能是 `*`</b>，否则读数会被推到行尾而不是紧贴模型名（踩过一次）。

2. **Core 只出结构化数据，文案在 App 拼**。`LangKey` 生成在 App 程序集（`UiharuMind.Localization`
   只做宿主与生成器，Core 不引用它），且倒计时要逐秒重算，成品字符串没法复用。

3. **账户级与模型级彻底分开**（评审改动之一，原稿把两者塞进同一份快照，切模型会串徽章）：
   - `IProviderStatusSource`（联网）只产出**账户级**：窗口用量、余额、计划名、凭据异常。
     `ProviderStatusSnapshot` 里**不含**任何模型级结论。
   - `IModelBillingRule`（纯本地时钟）产出**模型级**：高峰倍率、免费模型、促销倍率。
   - 缓存键 `(configType, apiBase, SHA256(key))` 因此可以不含 `ModelId`：同一把 key 下切模型共用一份，
     而模型级徽章每次按当前 `ModelId` 现算，不会命中别人的结论。

4. **两个扩展点分开**。有的供应商只给价目表（无额度接口），有的只给接口（无时段概念）；
   合成一个接口会逼出一堆空实现。注册表与 `RemoteModelConfigRegistry` 同构：显式登记、不扫程序集、
   不反射；未登记 → `For` 返回 `null` → 上层判定「本家没有状态可显示」，顶栏不占位。
   供应商差异只许出现在该供应商自己的实现类里，共享链路（取数、缓存、退避、格式化）与供应商无关。

5. **读数归会话视图模型持有**（`ConversationViewModel.ProviderStatus`），不归页面、不归全局：
   它的生死跟着会话视图模型走（弃用即退订公共调度器），它的口径也跟着这个会话走。
   口径分三层：<b>会话自己指定的</b>（已落盘的钉选 / 运行期覆写 / 空态选好还没发的那家）→
   <b>会话钉了但指望不上就落全局</b>（判据复用 `LazyChatClient.ServingModel`，与 `ContextLength`、
   请求路径同一条）→ <b>全局当前选中</b>（取「顶栏选中的那个」，它包含「已选但还没加载完」那档）。
   页面与全局都不再持有读数：会话能钉自己的模型，全局一份必然对不上「读数报 A 家、请求发给 B 家」。

6. **定时拍归公共调度器管，不归界面管**（`ProviderStatusHub`，全应用一个 30 秒的
   `DispatcherTimer`）。开着五个同供应商的窗口就该只有五个订阅者、一个拍子；
   HTTP 那层再由取数服务按 key 的 TTL 缓存合并成一次。**两层都不按界面数翻倍**——
   否则五个窗口各自醒来、各自解析、各自刷界面（还各发一次请求）。

   读数因此是「被动」的：自己不挂定时器，被调度器叫 `Pump()`。

7. **取数时机**（评审改动之二）：公共调度器那 30 秒一拍只重算倒计时与「是否仍处高峰」，**不联网**；
   网络请求由四处驱动——tick 命中 TTL、切模型、一轮对话结束、**点开明细面板**（此刻就要看最新的）。
   面板里的「数据 X 前」**按秒走**（每秒重算文案，不碰网络）：30 秒一跳的秒数看着像卡住了。
   - **可见性只压网络，不压首次取数**。原稿用 `IsEmpty` 驱动控件自身的 `IsVisible`、
     又用 `IsEffectivelyVisible` 门控刷新：首帧没有缓存 → 控件隐藏 → 永不刷新 → 永不出现。
     `LocalUsageIndicator` 早踩过这坑（`LocalUsageIndicator.axaml.cs` 注释：「藏的是按钮不是自己：
     自己藏了 `IsEffectivelyVisible` 就一直是假，再也刷不回来」）。现在的规则是
     `shouldPoll = 可见 || 从未成功过`，且控件隐藏时也允许它先把数据取到手再显示。
   - **轮末挂在 `ETurnNotice.Ended`**，不是 `OnObservedTurnEnded`。后者首行就是
     `if (_driver.IsRunning) return;`——用户自己发的那一轮根本走不到，而那一轮正是烧额度的那一轮。
     `ETurnNotice.Ended` 分支里已经在刷 `Usage.RefreshCoalesced(force: true)`，同一处补一次即可。

8. **缓存、单飞、退避收在一处**（`ProviderStatusService`）：TTL 60 秒；失败返回上一次成功快照；
   连续失败 15s → 翻倍 → 封顶 5min；TTL 内复用；无 Source 不建缓存项。
   **单飞是按 key 的**（评审改动之三）：原稿照抄 `LocalUsageData._refreshing`，那是一个字段的
   单数据源写法；多 key 缓存下会把 A 的在途请求返回给 B。改为 `ConcurrentDictionary<key, Entry>`，
   in-flight 任务挂在各自的 Entry 上。
   HTTP 状态映射：401/403 → `CredentialInvalid`（降级快照，不抛给用户）；429 → `WindowExhausted`
   （窗口打满在 HTTP 层通常就是它，原稿只映射了 401）。

9. **密钥不落日志**（评审改动之四）：`ProviderStatusContext` 是 **class 且重写 `ToString()`**，
   不是 record——record 自动生成的 `ToString()` 会把明文 `ApiKey` 打进任何字符串插值、异常消息与日志，
   而这件事恰好是「不进日志」承诺的唯一破口。缓存键里的 key 走 SHA256；解析异常只记端点与方法。

10. **不动 `BaseRemoteModelConfig`**。原稿要加一个 `StatusApiBase` 虚属性，与它自己风险表里
   「URL 常量收在 Source 内」矛盾，且 `BaseRemoteModelConfig` 已登记进 `SaveJsonContext`
   （新公共属性会随配置落盘）、设置页 `SettingListView` 会反射遍历属性（不加特性就多出一个输入框）。
   状态接口基址一律由 **Source 自己**从 `ModelPath` 的 authority 推导（CC 的
   `https://api.commandcode.ai/provider/v1/chat/completions` → `https://api.commandcode.ai`），
   常量留在 Source 内。用户把端点改成中继时状态接口自然失败 → 整块不显示，不影响聊天。

11. **界面复用既有语义色与控件**：`Border.status-dot` 的 `Ready/Warning/Error`、`KindBadge`
   （底色用现成的 `Gold`，与视觉徽章同色；不新造 amber 资源——仓里没有这个画刷）、
   `LocalUsagePanel` 的骨架与 `ProgressBar` 条。
   **常态不出状态点**：顶栏已有一个常驻的点（`LocalUsageIndicator` 在模型选择器内部，讲本机资源），
   再并一个绿点只会让两个点的语义互相稀释。绿点省掉，接近上限转黄、打满/凭据失效转红时才出点，
   与「不打扰」一致。

12. **读数进不进得下**：读数 `MaxWidth` 收口 + 省略；**不给模型下拉加 `MinWidth`**（加了会让顶栏溢出
    而不是压缩，见实施补记 2）；窗口再窄时两边都靠省略号收口。这条不许只写在风险表里——
    它决定「顶栏不撑高」在 800px 窗口下还成不成立。

## 取舍

- **不做价格估算**（本地 token × 单价）：各家价目表变动频繁，且接口给的是**实际扣费**，估算只会和真值打架。
- **高峰时段本地算、不查接口**：接口没有这个字段，且它是「按时刻判断的规则」而不是「服务端事实」，
  联网纯属浪费；代价是官方调时段要改一次代码（规则表只有一处）。
- **额度按账户缓存、不按模型**：接口给的就是账户级数字，按模型缓存只是重复请求同一份数据。
- **失败留旧值、不弹窗**：顶栏是背景信息，弹窗会打断聊天；唯一例外是凭据失效（用户必须知道 key 坏了），
  但那也是就地变红字，不弹窗、不写通知中心。
- **认不出的模型/供应商什么都不显示**：宁可少提示，不可给错误的计价暗示。
- **状态位与 `ConversationUsageViewData` 不是一回事**：后者讲「这一轮/这个上下文用了多少 token」，
  前者讲「账户额度还剩多少」，两个层面，互不替代。

## 已知代价

- **端点对上了，字段名全猜错了**（2026-10-27 用真 key 实测，fixture 在
  `Core.Tests/AI/Status/fixtures/`）：`/alpha/billing/credits` 与 `/alpha/whoami` 都是 200，
  但真实形状是
  `{"credits":{"belowThreshold","creditThreshold","monthlyCredits","purchasedCredits","freeCredits"},
    "windowLimits":{"limited","exceeded","fiveHour","weekly"},"sandboxAccess","sandboxMinutes"}`——
  **窗口在 `windowLimits` 下**（不是 `credits.fiveHour`），**余额被拆成三个桶**（没有单一 remaining），
  而且 `fiveHour`/`weekly` **可以整个是 null**（免费账户根本没有滚动窗口）。
  设计稿按「`credits.fiveHour` + 单一 remaining」写，实测一条都命中不了 → 顶栏一片空白。
- **窗口对象内部（`used`/`limit`/`resetsAt`）至今没有真样本**：实测账户是免费档，
  `windowLimits` 里全是 null。fixtures 里 `-pro` 那份是假拟的，只钉容错分支。
- `/alpha/whoami` 实测只有 `user` 与 `org`（org 为 null），**没有 plan 字段**，计划名暂时读不到。
- 免费档没有窗口时，读数退到余额（否则用户看到的是空白，而实际是「余额 0，发不出去」）。
- 每 60 秒两个请求：只在选中已接入的供应商时发生，失败有退避，隐藏即停（首次取数除外）。
- 多实例共用同一档案时，每个实例各自轮询（额度数字只读，无害，仅多一点请求）。
- 计费规则（高峰时段、免费/促销名单）是**代码里的表**，官方调整时改一次；不抓网页。

## 本期不做

- 价格估算、账单跳转、多账户轮换、充值。
- 本地模型的等价物（`LocalUsageIndicator` 已覆盖内存与 CPU）。
- `/alpha/usage/summary`（本月已花、token、成功率）——二期进悬停面板。
- 「14:00 起进入高峰」这类预告（只在已进入高峰时提示，免得顶栏常年挂时间）。

## 实施补记（2026-10-27，落地时与设计稿的两处偏差）

1. **可见性判据改成「在不在可视树上」，不是 `IsEffectivelyVisible`**。Avalonia 12 的
   `Visual.IsEffectivelyVisible` 是普通 CLR 属性 + **internal** 事件（`Avalonia.Base/Visual.cs:209/214`），
   既没有 `IsEffectivelyVisibleProperty` 也没有对外的变更通知，控件观察不到它。
   `ProviderStatusIndicator` 因此用 `OnAttachedToVisualTree` / `OnDetachedFromVisualTree` 当判据；
   「切到别的页但控件仍挂着」这一档不区分——代价是那段时间仍按 60 秒轮询，两个只读请求，可接受。
   定时器收在 `ProviderStatusMonitor`（全局一份，`App.ProviderStatus`），不放控件里：
   控件藏起来就不再驱动定时器，正是「自己藏了自己」那条死路的另一半。

2. **窄窗不靠 `MinWidth` 保底**。给模型下拉加 `MinWidth` 会让顶栏溢出（右侧按钮被顶出去）而不是压缩，
   所以只给读数 `MaxWidth=200` + `TextTrimming`：窗口再窄，两边都靠省略号收口，不会溢出。

3. 取数服务的构造函数是 `public`（`ProviderStatusService(IProviderStatusRegistry, Func<DateTimeOffset>)`）：
   「并发 5 次只发 1 次」「TTL」「两个 key 不共享」这些用例必须能换注册表与时钟；
   静态注册表加静态单例没法替身。应用里仍只用 `ProviderStatusService.Shared`。

4. 无头测试钉的是几何而不是常量：`TopBar` 高 50 是 XAML 写死的，断言它恒真无意义；
   现在钉「没数据时读数控件宽度为 0、模型下拉仍 > 200」与「有数据时读数单行（高 ≤ 18）」。

3. **读数的位置改了三轮**：① 顶栏 shell 中间列的 `Auto` 格 → 因为 `ModelSelectComboBoxView`
   自带末尾按钮，实际落在「卸载」之后；② 塞进 `ModelSelectComboBoxView` 那一行、模型下拉右边；
   ③ 用户指出应当挨着**会话自己的**模型名 → 现在落在 `ConversationView` 的会话头里。
   ②③ 之间的教训是：**全局选择与会话选择是两回事**，报「会话的额度」就贴着会话的模型名。
   无头截图（`App.Tests/Headless/ProviderStatusTopBarTests` 落 `provider-status-header.png`）确认：
   读数在会话头元信息行的最左（模型名之后），单行不换行、没数据不占位。

4. **注册表查找要兜住「Config 落在基类」**。实测存档读回来的 `RemoteModelInfo.Config` 运行时类型是
   `BaseRemoteModelConfig`（反序列化只看属性声明类型），`ConfigType` 字段倒是写着 `RemoteCommandCodeModelConfig`。
   `RemoteModelManager` 启动时会按 `ConfigType` 再修一次，但状态读数不该依赖"那条路一定走过"——
   `ProviderStatusContextFactory` 在拿到基类时用 `RemoteModelConfigRegistry.ResolveConfigType` 兜一层。

5. **解析器改按实测形状读**：`windowLimits.fiveHour` / `windowLimits.weekly`（另留 `limits`/`windows`/`credits`
   三等候选层与窗口摊在顶层的旧形状）、余额按 `monthlyCredits + purchasedCredits + freeCredits` 求和
   （没有再退回 `remaining`/`balance`）、`windowLimits.exceeded` 支持布尔（全超）与字符串/数组/对象（点名）。

6. **没有窗口的账户也要说话**：`Meters` 为空但 `Balance` 有时，读数用 `余额 $X` 顶上。
   实测的那个账户正是这种：`credits` 三个桶全是 0、`windowLimits.limited=false`，
   而聊天会被 CC 以 `insufficient credits` 拒掉（400）——顶栏显示「余额 $0」比留白有用得多。

7. **「跟随会话」是用户当场纠正的一条**（原稿写的是「跟全局当前模型」）。第一版把读数做成全应用
   一份（`App.ProviderStatus`），结果会话右栏能给自己钉模型，钉了之后顶栏报的还是全局那家。
   现在读数的口径是 `ConversationViewModel.ServingModel`（会话钉的优先、指望不上落全局），
   页换会话或会话改钉选时当场 `Tick()` 改口径（监听 `SessionModelLabel` 变化），不等下一拍。
   钉选判据复用 Core 已有的 `LazyChatClient.ServingModel`——不新造一条「哪个模型在服务」的口径。

8. **绑定链断过一次（读数永远空）**。读数放在模型选择器那一行里，而那个控件在构造里把
   **自己的 DataContext 设成了 `App.ModelService`**——控件身上的 `{Binding ProviderStatus}`
   只认它自己的 DataContext，页面那份永远递不进去，顶栏就一直空着。
   现在由壳的 code-behind 显式递（`OnDataContextChanged` → `ModelSelect.ProviderStatus`），
   并加了一条无头用例专门钉这条链（页面数据 → 选择器那一行 → 行内指示器）。
   **教训**：控件自带 DataContext 时，父级给它的数据不能靠绑定递。

9. **「同一把 key 被几个界面同时看着」不会翻倍**：定时拍是全应用一个（`ProviderStatusHub`），
   HTTP 是服务层按 `(configType, apiBase, SHA256(key))` 缓存合并的。
   开着多个 QuickChat 窗口或多个会话页时，同一家供应商一共一次请求——
   `ProviderStatusViewDataTests.TwoSurfaces_SameProvider_ShareOneRequest` 钉着这条。
   （QuickChat 窗口本身不显示这条读数：它没有模型选择器那一行。）

10. **会话头那一格不能是 `*`**。模型名按钮原本独占 `*` 列（长名字靠这一列截断、会话编号靠它顶到行尾），
    读数插进去后必须改成「模型名按内容宽（MaxWidth 320）+ 读数 + `*` 余量 + 会话编号」四列，
    否则读数会被余量推到行尾，又一次「位置不对」。

11. **秒级跳动与取数是两件事**。公共调度器那 30 秒一拍是给**取数**用的（TTL 60 秒），
    撑不起「数据 X 前」的秒级跳动——那条每秒一跳的定时器**只挂在明细面板开着的时候**
    （`ProviderStatusIndicator` 自己有，`Opened` 起 `Closed` 停），而且只重算文案、不碰网络。
    点开面板还会强制拉一次（`force`），让面板里的数字是此刻的——这条与 `LocalUsageIndicator`
    的既有做法一致（点开就刷），代价是每次点开一个请求。

12. **点开明细时先说「更新中…」，别闪旧秒数**。否则会先看到上一轮的「47 秒前」，
    新数据到了又变成「0 秒前」——数字从 47 掉到 1，看着像倒计时在倒着跑。
    现在的顺序是：开面板 → 「更新中…」→ 新数据到了 → 「数据 刚刚」→ 「1 秒前」→「2 秒前」。
    刚取到的那几秒说「刚刚」而不是「0 秒前」，也是为了不让数字从 0 开始爬。

    （Avalonia 的 `FlyoutBase` 只有 `Opened`/`Closed`，**没有 `Opening`**，所以「更新中…」是
    在开出来的那一帧换的——不是画之前。这点记下来，别再去找那个事件。）
