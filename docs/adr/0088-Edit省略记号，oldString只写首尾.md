# Edit 省略记号：oldString 只写首尾

## 起因

2026-10-16 当天 24 个会话里，Edit 参数占模型全部输出的近一半（154 万字符，推理 134 万），其中 oldString 77 万，真正被替换的行占 65 万。模型为了说明「改哪里」，几乎把旧文本整段重新生成了一遍。大段改写（精简注释、重写函数体）时最明显：超过 6 行的 oldString 有 771 条，首尾各留 2 行就能省掉 41 万字符。

13560 条历史编辑里没有一条自发省略过中间部分，说明模型学到的是「oldString 必须逐字照抄」，没有现成习惯可借，只能由工具说明教。

## 决定

**oldString 里可以用 `[\s\S]*?` 代替中间的原文**：`开头[\s\S]*?结尾` 替换从开头到结尾（含两端）的整段。参数形态不变，不用的模型完全不受影响。

- **记号**：用正则里「跨行任意内容、非贪婪」的写法 `[\s\S]*?`。最初选的自造记号 `{...+...}` 两个模型都不用；同一场景换成 `[\s\S]*?` 后，DeepSeek-V4-Flash 删 92 行方法时 oldString 从 3259 字符降到 339 字符，范围正确，也没有把 oldString 其余部分当正则转义（Agnes-2.5-Flash 仍不用）。模型认得的写法它才会用。撞车：当天全部工具返回约 1.3 亿字符里出现 0 次，仓库 .cs 里 3 处，都在正则代码里，由下一条兜住；`.*`（1448 次）撞车太多，`.*?` 按正则语义不跨行。常量只在 `EditElision.Token` 一处。
- **原文优先**：整串先按原文走现有的全部匹配（精确、整行 TrimEnd、全角归一、剥行号前缀、缩进偏移），都不中才按记号拆段。文件里真有这串字符时照常命中。
- **开头唯一，结尾就近**：第一段须在文件中唯一，与现有规则一致；之后每一段取前一段之后最近的一处，等价于非贪婪匹配。
- **拒绝弱锚点**：第一段之后的段，若没有字母、数字或汉字（只剩 `}`、`});` 之类），直接报错。就近匹配一个 `}` 正是范围被截短的典型陷阱。
- **整行与行内两种拆法**：记号独占一行（前后只有空白）时按整行比对，沿用逐行 TrimEnd 与全角归一，CRLF 文件照样能中；记号夹在行内时按原文精确找。
- **newString 里的记号**：只有 oldString 这一条确实按记号拆段命中时，newString 里的记号才是占位符，按顺序原样填回被省略的原文。newString 不含记号时整段换成 newString；含记号时数量须与 oldString 一致，否则这一条不生效并说明。其余情况（oldString 不含记号、或整串按原文命中）newString 里的记号一律是字面文字。所以「在说明里新写一个记号」不受影响；同一条既省略又想写字面记号的，改成不省略的普通编辑。
- **回执说事实**：成功时报出每处省略实际覆盖了第几行到第几行、共几行。diff 的 `-` 行照旧完整给出，范围截错了模型看得见。
- **审批卡片**：预演与执行同一个规划函数，卡片上是实际被替换的完整原文。

## 硬约束

省略记号拆出的每一段仍对着**原文**定位，部分写入（ADR 0087）的两个不变量不变。被省略的原文在落盘时一字不改（换行风格也不改），只是不再需要模型重写。

## 不做

- **按行号定位**：当天 2086 个被替换块里 15% 的行号在模型改之前已被同文件的其它编辑挪过，按内容定位不受影响，按行号就得重读或推算。
- **缩进偏移叠加省略**：缩进兜底只对整串生效，拆段后的各段不再做缩进平移。各段只有几行，写错缩进的机会本就少，先看实测。
- **转义语法**：同一条既省略又要写字面记号的情况极少，另起普通编辑即可，转义对模型是又一条要记的规矩。
