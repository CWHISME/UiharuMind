# 对话页合并为单页，类型由左栏切换器唯一决定

普通对话与智能体合并成<b>一个对话页</b>，左栏顶部一个切换器（普通对话 | 智能体）决定当前类型；
列表、中间会话区、右栏面板全部跟随类型，右栏自身不持有类型状态。

本 ADR 取代 [0011](0011-两个对话页的会话创建时机刻意不同.md) 的「两个页面」前提，保留其「创建时机」结论的改写版。

## 背景

原先两页（聊天工作台 / 智能体页）共享同一套壳（`ConversationPageShell` + `SessionListModel` +
`ConversationView`），差异只剩三处内容槽与两个创建参数。用户侧的心智负担是「每次要决定去哪个页面」，
维护侧是两份 `PageData` 的事件接线几乎逐字相同。

更关键的是群聊的规划（见 `docs/proposals/代理人格化/群聊多角色代理设计方案_v6.md`）：
群成员 = 复用子会话那套底层（`ParentSessionId` 指向群的独立会话、独立弹窗），
一个群天然横跨普通角色与智能体。若保留两页两列表，群聊会话按成员构成归哪一页都是错的——
列表分区必须从「按角色档位」让位给「会话形态」。合并是群聊的前置条件。

## 决策

1. **单入口单页面**：菜单收成一个「对话」入口（`MenuConversationKey`）。旧键
   `MenuAgentKey` / `MenuChatKey` 保留作内部定位，都映射到同一页。
2. **类型唯一由切换器决定**：`ConversationPageData.CurrentType`（`EConversationType`，
   取代旧 `ESessionListScope`）。列表（`SessionListModel.SwitchType`）、中间会话区、右栏面板全部
   跟随它刷新；右栏不自持类型状态——一致性靠构造保证，不靠事件同步。
3. **右栏三态**：空态 = 角色选择面板（新，`NewSessionRolePanel`，候选按类型过滤）；
   普通对话 = 会话详情 + 上下文占用；智能体 = 工作区 + 能力/子代理/定时任务。后两者原样复用。
4. **创建时机改写（0011 的继承）**：统一<b>懒建</b>——加号只切空态、不建会话（误触零成本）。
   唯一例外是<b>从角色起点开聊</b>（空态右栏点角色、角色页「开始对话」）：那是明确的表态，
   <b>急建</b>并自动选中，开场白因此能随角色写进历史（见 ADR 0016）。
   原聊天页「空列表自动开一个 Empty 会话」的兜底删除——空态就是起点。
5. **删除当前会话后的去向按类型**：普通对话顺位选下一条，智能体回空态（懒建页空态是起点）。
6. **子会话 / 子代理机制原地不动**：右栏索引、浮窗、`ParentSessionId`、后续报告、唤醒轮是群聊的骨架，
   合并只动壳，不碰骨架。

## 为什么是「切换器」而不是保留两个页签

- 两个页签 = 两个会话区实例常驻，切页签就是现在的切页；一个页面内切换器 = 单会话区缓存复用，
  切换类型时旧类型会话实例仍可缓存，切回来不用重载。
- 用户的迁移成本最低：两类的区分感（列表不混排）保留，只是从「两个入口」变成「一个入口内一拨」。
- 群聊的归类天然成立：普通群进普通列表、智能体群进智能体列表（P1 由建群时的类型选择决定）。

## 代价（明说）

- **`CurrentType` 是页面级状态，跨会话持久吗？不持久。** 重启回到默认类型（智能体）。
  若将来用户高频用普通对话，可考虑记住上次类型——需要时另开决策。
- **空态右栏是新组件**，承担「选角色开聊」；原聊天页的「新建按钮弹角色选择器」入口移除。
- **角色页开聊**从「跳页 + 自动选中」改为「跳页 + 显式 `RevealSession`（切类型 + 选中）」，
  依赖页面已被实例化且 `Content` 指向对话页——`StartChat` 里先 `JumpToPage` 再取页面，顺序敏感。
- **ADL 0011 的「两页」前提作废**：开场白机制（ADR 0016）不变，但「空列表自动建会话」行为删除，
  列表为空是常态而非异常。

## 已定（原「未决」第一条）

- **群的类型建群时选定，之后不变。** 类型的机械含义是**这个群绑不绑工作区**——工作区绑在会话上
  （[0026](0026-agent产物按工作区组织，落地Data-Agent-Workspaces.md)），而群的开场读取与产物区
  （设计文档 §2.7、§7）都要一个共享的工作区。
  - **智能体群**绑工作区，普通角色与智能体都能进（普通角色只是没有工具），进智能体列表；
  - **普通群**不绑，只收普通角色，进普通对话列表。

  这比设计文档 §6.4「成员可混」收窄了一半：普通群里的智能体没有工作区，写的文件没处落。
  **不按成员构成派生**——那样加一个人、踢一个人，群就在两个列表之间跳，
  和角色身份开关（[0043](0043-角色档位从四档枚举改为一轴派生.md)）是同一个坑，而且踩得更频繁。
  类型是群自己的属性，同「身份是角色自己的属性」一个道理。
