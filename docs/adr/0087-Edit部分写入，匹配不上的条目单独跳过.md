# Edit 部分写入：匹配不上的条目单独跳过

## 起因

一批编辑以前是全有或全无：任何一条找不到或匹配多处，整批打回，而且只报第一条。改十处错一处，模型就要把十条全部重发；后面的条目若还有错，就得再来一轮。

## 决定

**找不到、匹配多处（以及 oldString 为空）只属于那一条**，这些条目跳过，其余照写。下面几种情况归不到某一条，仍整批不写：

- 文件解码不干净；
- 条目之间重叠：两条都去掉的话，意图就丢了；
- 写回时有字符存不下：替换后的整份文本才知道；
- 全部匹配不上。这时每一条都报出来，不只报第一条。

**回执结论在最前**：`已修改 'a.cs'（部分成功：9/10 处编辑）。`，紧接着是没生效的条目，并明说「只需对它们重新 Edit，已生效的不要重发」，然后才是 diff。开头仍是「已修改 '」，群产物区据此把它算作一次落盘写入。

**失败话术对着写入后的新文本出**，所以「最接近的原文」和多处命中的行号都与磁盘上的文件一致。若其余条目写入后，这一条恰好变成唯一了，就直接告诉模型原样重发。多处命中现在列出各处的起始行号；全角/半角歧义的那句专门提示照旧保留。

**审批卡片照实标出** `部分生效：9/10 处编辑，edits[3] 匹配不上，不会写入`。预览和执行走同一个规划函数，所以卡片上看到的就是最后落盘的样子。

## 硬约束

部分写入安全，靠的是两个不变量：**所有条目都对着原文定位**，加上**重叠检测**。有了这两条，没生效那条的 oldString 在写入后的文件里仍原样存在，重发照样命中。以后谁要改成依次对着前几条的结果定位，这个前提就塌了，必须先重新论证部分写入。

## 不做

- **备份**：工作区一般在 Git 下。部分写入后的中间状态，和模型分两次调 Edit 的中间状态并无二致，不是新风险。
- **语义依赖**：比如加了调用、定义那条却没生效，文件会短暂编不过。这和分步编辑等价，靠回执里醒目的结论让模型下一轮补上。
