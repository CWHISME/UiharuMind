# 会话内搜索搜历史数据，跳旧消息截断重载

决定：**搜索在消息历史上做，不在界面条目上做**；跳到窗口外的命中时，会话空闲就**截断重载**——
清掉现有条目，只围着命中那条画前 10 条、后 30 条，窗口因此**脱离历史末尾**；有轮在跑时才退回分批往前续窗。

## 为什么搜历史

界面上的东西从来不全：会话流按窗渲染（首屏只有 5 条，更早的滚到顶才续，见 `HistoryWindow`），
滚远的卡片整张卸成占位（ADR 0041），长思考与工具结果只显示截断预览，正文又是 markdown 渲染出来的。
所以匹配写成 Core 里的纯函数 `SessionSearch.Find`：吃一份历史快照，吐「第几条、哪一部分、前后一小段」。
跨会话全文搜索以后逐个会话把历史读出来喂进同一个函数，口径不分叉。

口径与界面显示一致：框架注入的不搜、点名调用搜用户敲的那一行、群私聊摘掉发给模型的那句说明、
交接文档搜正文。**默认只搜正文**，思考与工具（含检索片段）由用户自己勾——又长又多，全搜命中多半是噪音。
一条消息至多一个命中，定位粒度是卡片（逐字高亮放第二期）。

## 为什么截断重载

第一版跳转走「滚到顶自动续」那条前插补偿路径，只是批量大些、批间让出 UI 线程。实测 654 条的会话
从最新跳到第 0 条：续十几批、画出约 700 个条目、数秒，每批之间渲染一帧，**看着一路在闪**。

截断重载不管跳多远都只画一小段，整件事在一个派发任务里做完，中间不出帧。同一个会话实测：
跳到第 594 条 335ms / 68 个条目，跳到第 0 条 209ms / 54 个条目，托管堆比分批那版少约 50MB。

## 脱离末尾之后

窗口有了「终点」：`HistoryWindow.Detach` / `ExtendLater` / `EndFor`，`IsDetached` 期间终点之后的不画。
代价是好几处原本默认「窗口跟着末尾」的逻辑要表态：

| 路径 | 脱离末尾时 |
|---|---|
| 往下滚到底 | 续一批更晚的（`LoadLater`），续到末尾重新跟上末尾 |
| 跟底（`ScrollViewerAutoScrollHolder`） | 暂停：「底部」不是最新，跟过去会让续一批连环触发 |
| 运行期裁剪、切走后的后台裁剪 | 不动：按「跟着末尾」算锚点；切回来还停在原处 |
| 尾部对账（`ConversationHistoryReconciler`） | 不动：末尾本来就没画，按尾部对账会把整段补回来 |
| 自己发话、本会话开跑、历史有追加、「重新生成上一条」 | **先回到最新**（末尾首屏重放），新内容才接得上；重新生成要按真正的最后一条挑 |
| 删除消息、重试截断 | 按删掉的下标修正起点与终点（`NoteRemoved`）；截到窗内某条及之后的全部时窗口自然接回末尾，重试不必整窗重放 |
| 切回停在旧消息那段的缓存实例 | 滚回上次跳到的那条（`ConversationSearchNavigator.Anchor`），不贴底——滚动容器是各会话共用的，偏移量留不住 |

脱离期间条目数不设上限（不裁剪），回到最新时一并释放：一次搜索跳转之后往上往下续的量有限，换来的是锚点永远可信。

「回到最新」是消息流右下角一个常驻的向下箭头（与日志页「回到顶部」同一形态）：往上翻离底部一段、或脱离末尾时显示，
前者点了直接贴底并恢复跟底，后者点了重放末尾首屏。运行登记早于第一段实时内容，所以「别处开跑就回到最新」排在内容之前。

**有轮在跑时不截断**：实时流在往条目末尾追加，截掉末尾就接不上——这时仍走分批续窗，接受那几帧闪。

## 实现时定下的

0. **动历史的人都经过开窗**（`ConversationHistoryPager.Detach.cs`）：追加走 `AppendPersisted`，删改报 `NoteRemoved`。
   第一版各调用点自己记得「先回到最新」，审查当场挑出三处漏掉的——重新生成上一条会按这一小段的最后一条截掉后面整段历史，
   重试的提问会被回到最新那次重放冲掉，删除之后往下续会漏一条。三个状态位只由窗口投影（`SyncFlags`），不各自赋值。
   跳转的决策（已在窗内 / 重载 / 分批 / 找不到）在 `ConversationSearchNavigator`，视图那一半只管滚动与闪烁；
   「会话空闲」与对账共用一个判据。

1. 命中按消息实例认，不信快照里的下标：搜索之后历史可能被追加、删除、压缩（`ConversationSearchLocator.IndexOf`）。
2. 消息没有自己的卡（工具结果并进了调用那张卡）就往前找最近一条有卡的；命中在思考就落到思考卡上并展开。
3. 落点在视口上方四分之一，搜索栏盖得更深就让到它下沿以下；清扫会顺带把视口里的卡转成 markdown、改高度，
   所以落点量到稳定为止。命中之后内容不够高、滚不到锚点时往后续批垫高（至多 3 批）。
4. 结果新到旧排，回车跳更早一条；打字只搜不跳——边打字边跳就是每敲一个字重画一次。
5. 开发脚本 `session.search` 走同一套公开入口（打开、填词、按上下条），报告落点。
