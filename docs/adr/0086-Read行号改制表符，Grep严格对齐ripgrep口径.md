# Read 行号改制表符，Grep 严格对齐 ripgrep 口径

> 修订 [ADR 0083](0083-搜索工具结果改纯文本.md) 的正文与说明排布。

## 起因

一位不知情的模型读了一段 Grep 结果，提出的问题都能对上实处：

- 「共 9 处命中」，却只看到 3 个命中行：计数数的是**出现次数**，一行出现三次算三处；
- 行号从 250 跳到 252，251 像是被吞了：两段上下文之间正好缺一行，没有任何断开标记；
- 末尾的 `---` 看着像块分隔，其实是正文和说明之间的分隔；
- `[位于 …]` 结构行夹在代码行中间，看不出它属于哪一块。

结论：输出**七成像 grep**，读的人带着 grep 的预期去读，就会被那三成误导。要么照抄，要么换格式。

## 决定

**Grep 照抄 ripgrep `--heading -n -C` 的契约：**

- 文件路径单独一行，命中行写 `行号:`，上下文行写 `行号-`；
- 行号不连续处单独一行 `--`，第一块前面不加（路径行就是边界）；
- 行号不补齐。

**唯一的例外是结构块头 `[位于 起–止] 签名`**，它只出现在块首，也就是路径行或 `--` 之后，归属永远指向下面那块。同一结构被 `--` 切开时，后一块不重复块头。没有大纲的文件不出块头，输出逐字节等于 ripgrep。块头不挂在 `--` 上，因为夹在两块之间分不清它说的是上面还是下面。

**计数按命中行**，与 `grep -c` 一致。命中地图里的「N 行」也是同一口径。限幅（`MaxMatches`）仍按引擎的条目计，它是内部预算，不对外宣称。

**规模说明放在正文前面**，空一行后接正文，正文和说明之间不再用 `---`。模型先知道搜到多少，再读命中。命中地图本来就是先声明再给分布，不变。

**Read 行号前缀从 `82→` 改为 `82\t`**，即 `cat -n` 的样子，也是训练语料里最常见的读文件格式。不用 `82:`，因为会和 Grep 的命中行同形。剥前缀的正则同时认 `\t` 和 `→`，旧会话照样剥得动。Edit 仍是先按原样匹配、找不到才剥，以「数字+制表符」开头的原文（比如 TSV）不会被误伤。

## 不做

- 命中词高亮、`↑ 命中` 标注、「省略 N 行」：读者是模型，它知道检索词，`--` 已经表达了断开，这些只会多花 token。
- 整个换成结构化卡片：模型对 grep 的形状最熟，照抄比另起一套更省力。

## 同批补的（群聊「文件工具检验」反馈）

- **简写写进 glob**：Glob 的 `pattern` 或 Grep 的 `fileGlobs` 以 `$DRAFT`、绝对路径或 `~` 开头时，把通配符之前的目录前缀拆出来当搜索根，和 `path` 同一套规则（`SearchRoot.TrySplitRoot`）。之前 `$DRAFT/*` 在 Glob 里静默 0 命中；在 Grep 里被剥成 `*` 后在整个工作区搜，范围错了却不报。同时传了 `path` 时报错，不替模型挑。
- **搜索输出同一排布（`ToolResultText.Compose`）**：Grep 的正文、只列文件、分布地图，与 Glob 的列表、目录统计，都是规模说明在前，正文居中，收窄建议殿后，`---` 全部去掉。退成地图时，若传了 `contextLines`，明说上下文行也一并略去了。
- **`fileGlobs` 整个转义成 JSON 字符串**（`"[\"*.cs\"]"`）时按数组解析；解析不成 JSON 的（如 glob 字符类 `[ab]`）原样保留。
