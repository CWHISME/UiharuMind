# 文件记忆退役，记忆改为工作区目录由模型自管

框架的 `FileMemoryProvider`（`file_memory_*` 一组工具 + `## File Based Memory` 系统提示段 +
`memories.md` 索引）整体退役。记忆改成「工作区记忆」：落在工作区家目录的 `Memory/` 子目录，
模型用普通文件工具（Read/Write/Edit/Glob/Grep/shell）自管，不设应用侧索引或注入。

## 为什么

### 框架侧四个硬伤（1.20.0 读源码 + 实测）

1. **段措辞改不了。** `HarnessAgentOptions` 不暴露 `FileMemoryProviderOptions`，
   `## File Based Memory` 段是框架硬编码，要改措辞只能自建 provider（ADR 0002 已记账）。
   我们自己的纪律散文走中文（ADR 0017），这段英文教程是唯一不受控的一块，还永远挂着
   本地模型做不到的承诺。
2. **索引注入已被我们整条过滤。** `InjectedContextRewriter` 把来源为 `FileMemoryProvider` 的
   索引消息滤成 null（ADR 0020）：注入的是可能过期的快照，`file_memory_ls` 返回同一份、还新鲜。
   框架既然已经教模型「主动查」，provider 的存在就只剩「提供工具 + 决定落盘」两件事——而这两件事
   普通文件工具全都能做。
3. **50 条索引上限按文件名字母序截断。** 越过之后靠后的记忆不进索引、模型再想不起去读，
   一角色一目录又只增不减，这是会真实发生的记忆丢失（ADR 0020 已知代价）。
4. **删除要手工补审批。** `file_memory_delete` 裸造函数没审批，靠
   `InjectedContextRewriter.GateTools` 补包。拆掉后删除走 shell `rm`，审批纪律天然覆盖，补丁消失。

### 本地模型现状：工具调用零支持

`LLamaSharpChatClient` 完全忽略 `ChatOptions.Tools`（ADR 0020 原记录）。本地模型调不动
`file_memory_*`，将来也调不动普通编辑工具——对它们 provider 只剩「每会话灌一段用不上的工具
教程」的纯成本。拆掉后不再误导（见已知代价：本地模型没有记忆，与现状一致）。

### 产品判断：全局（按角色）记忆几乎没用，还容易误导

按角色分目录的记忆跨项目共享。实测观察：智能体的笔记几乎都是项目相关的，跨项目那点
「角色人设记忆」既用不上，还容易把 A 项目的上下文带进 B 项目。因此记忆**跟工作区走，不跟角色走**。

- 这**明确修正 ADR 0002 的一条理由**：「角色 A 的笔记漏进角色 B 会污染人格」。那条在
  「默认按角色」的语境下成立，但实际场景里智能体的笔记不承载人格——人格由角色卡定义，
  不由记忆承载。
- 隔离改由新维度承担：**同项目共享、跨项目隔离**。同一项目的多个智能体是同一份工作的不同手，
  共享项目记忆；不同项目天然隔离（家目录名不同）。

## 决定

1. **不再装配 `FileMemoryProvider`，且不保留回退档**：`file_memory_*` 工具、框架记忆段、
   `memories.md` 一起消失，`EnableFileMemory` / `FileMemoryScope` 字段删除。
   最初设想过「保留开关做灰度」，实践推翻：开关默认值翻转只作用于 C# 初始化器，而角色卡从
   JSON 反序列化、旧存档里持久化的 `EnableFileMemory=true` 直接覆盖默认值——「新会话默认新机制」
   根本不会发生。直接移除后，旧存档里残留的字段被反序列化忽略，零迁移。
2. **记忆 = 工作区记忆**：`Data/Agent/Workspaces/{工作区名}_{哈希}/Memory/`，按主题一个 `.md`，
   模型用普通编辑工具自管；不设应用侧索引、不做注入。
3. **没绑工作区的会话走同一约定**：`NoWorkspace/{会话id8}/Memory/`——家目录按会话建，
   这份记忆随会话生灭、不跨会话共享（没绑工作区的本就是一次性草稿会话，统一路径约定优先）。
4. **系统提示只给路径与用法**：绝对路径 + 「需要时先 `Glob` 再 `Read`」，开场是否查看由模型自行
   判断，不进工作循环模板。段落在 `AgentInstructionsComposer` 工作目录段附近，中文纪律段
   （ADR 0017），替代退役的框架英文段。
   **提示词不给模型看「免审批」信息**：草稿目录段不再写「用 `Write`/`Edit` 写这里不需要审批」，
   记忆段也不提审批。审批规则照旧放行（机制不依赖模型知情），但模型不需要、也不该把「免审批」
   当成行动前提——那是给护栏的，不是给模型的。
5. **免审批范围只认 `Memory/` 一格，但任何权限档可写**：写记忆对齐记忆工具时代（`file_memory_write`
   历史上任何档位都不拦）；删除改走 shell，越界写入三档硬规则（ADR 0010）+ shell 审批天然覆盖。
   不给整棵家目录免审批——家目录里住着各会话产出房间，连带放行等于放行别的会话的产物。
6. **存量 `Data/Agent/FileMemory/` 不迁不删，就地封存**：需要时让模型去旧目录看一眼、
   人工触发搬一份；不建一次性迁移设施（符合「全局记忆没啥用」的定位）。
7. **知识库（Knowledge）不动**；用户可见文案「记忆库」统一改「知识库」的机械重命名列入本次收尾
   ——拆掉框架记忆后，「记忆库」这个用户可见词与真正的记忆撞车更严重。
8. **内容边界与并发**：记忆 = 对话沉淀（偏好、决策理由、踩坑、任务状态），不镜像 repo 内容
   （代码/docs/git 以文件为准）；并行会话写同一目录接受「最后写入者胜 + 模型纪律（按主题分文件、
   先读后写）」，不引入应用级锁。

## 取舍

- **为什么砍 index（新会话注入清单）**：① 远程模型自己 `Glob` 就是新鲜清单，注入的是可能过期的
  快照（ADR 0020 老论证仍成立）；② 本地模型读不了文件，index 对它们纯属成本；③ 注入块要对抗
  「被模型误当成用户指令」——`MemoryContextProvider.SnippetHeader` 的七行防御就是为同一个坑写的；
  ④ 更根本的：本仓对「用户说过什么」较真（唤醒轮不伪造 user 消息、插话专门做 `isInterjection`），
  把记忆清单伪装成用户输入注入，是这套纪律反对的方向。
- **为什么开场「先查记忆」不强制**：记忆是「需要时才看」的资源，不是每会话必做步骤。工作循环是
  角色层模板（ADR 0004），记不记忆是工具纪律的事；强制开场查 = 为大概率用不上的场景付固定步骤。
- **为什么概念名与用户可见文案脱钩**：`file_memory_*` 的名字里带 memory，知识库的用户可见文案
  又是旧账「记忆库」——本次把概念分开钉死：「记忆」特指 agent 自写笔记，「知识库」特指用户喂的
  资料，文案错位在收尾时一并修。
- **为什么不留回退档**：灰度期开关实操起来是假的——旧存档角色已被持久化 `EnableFileMemory=true`，
  「默认关」落不到它们头上，用户看到的是「新会话还有框架记忆」；真要逐角色回退还得靠迁移
  区分「旧默认」与「用户显式开过」，为迟早删除的机制引入版本字段不值。直接移除，旧记忆文件仍在
  磁盘上，模型用普通文件工具就能读——回退诉求本身不存在。

## 已知代价

- **模型自律无硬保证**：按主题分文件、先读后写、不镜像 repo，全靠系统提示教；写坏、写散、
  写重复没有应用侧兜底。并行会话写同一目录 = 最后写入者胜（框架时代 `memories.md` 也是
  「每次写入后重建、丢一次下次补回」的同一哲学）。
- **本地模型没有记忆**：与现状一致，但提示词里不再挂做不到的承诺；也不再有注入，本地模型
  连「知道有记忆」都不再保证。
- **无回退档**：想回到框架记忆只能靠旧版本代码。旧的 `file_memory_*` 存档文件仍留在磁盘，
  当前模型用普通文件工具就能读——只是不再有那套 provider 工具与注入段。
