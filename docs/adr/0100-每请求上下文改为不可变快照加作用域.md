# 每请求上下文改为不可变快照加作用域

> **状态**：accepted（2026-10-30）。接 [ADR 0099](0099-OpenAI兼容层按职责分层，协议留出扩展点.md)
> 「没做的事」第一条——那次只把文件摆整齐，隐式输入没动。

## 起因

`LlmRequestContext` 是三个平铺的 `AsyncLocal` 加三个可写静态属性：`ForbidToolCalls`、
`PendingReasoningSource`、`SessionAffinity`。每个字段独立读、独立写、随时可改，于是有四个问题：

1. **漏复位是最难查的一类串号。** 值写进异步流后没有任何作用域约束它什么时候消失。
   上一发请求的「思考正文来源」闭包会一直挂在那条流上，下一次任何一个绕开 `LazyChatClient`
   的调用都会拿到它——把上一轮历史的思考贴进一份毫不相干的请求体，
   而网关报的是「历史对不上」，离真正的原因隔着两层。
2. **手工复位会抹掉外层的值。** `HistoryHandoff` 是这样的：`= true` 发一发，`finally { = false }`。
   它把「进来时是什么」一并写成 false；嵌套一次就把外层禁着的工具悄悄放开。
3. **写入点与读取点都散。** 写有三处（`LazyChatClient` 两处重复、`HistoryHandoff` 一处），
   读有五处（`RequestRewrite` 一处读三个字段、`SessionAffinityHeaders` 两处）。
   想知道「这一发的亲和值从哪来」，得把这条链路走一遍。
4. **测试只能靠摆异步流。** 断言「这种模型要不要回填思考」，得先把 `AsyncLocal` 设好、
   再 `Task.Run` 圈住，还得记得收拾干净。

## 决定

**值与环境载体分开，各自只有一个文件。**

- `LlmRequestContext` 变成**不可变 record**（`AI/LlmRequestContext.cs`）：三个 `init` 属性，
  没有静态可写成员。想改就得拿出完整的一份新快照。
- `LlmRequestScope`（`AI/LlmRequestScope.cs`）是**全仓唯一持有那个 `AsyncLocal` 的地方**，
  对外只有两个入口：`Current` 读、`Push` 在 `using` 作用域内写。作用域释放时还原成
  **挂之前的那整份引用**（含「之前没有」），不是逐字段还原。

由此得到三条硬语义，都有测试钉着（`LlmRequestScopeTests`）：

| 语义 | 保证了什么 |
|---|---|
| 退出即还原 | 「设了忘记复位」在类型层面写不出来 |
| 还原整份引用 | 嵌套时回到外层，而不是被内层的某个字段覆盖掉 |
| 内层用 `Current with { … }` | 只叠加自己关心的字段，外层设的不会被抹掉 |

**写入点收敛到两处**，都用作用域：

- `LazyChatClient`（两处，流式与非流式）：`Current with { PendingReasoningSource, SessionAffinity }`。
  它因此会自动保住外层设的 `ForbidToolCalls`——写交接文档那一发正靠这个。
- `HistoryHandoff`：`using (Push(Current with { ForbidToolCalls = true }))` 只在那一发上禁工具，
  删掉原来的 `finally` 手工复位。

**读取点收敛**：

- `RequestRewrite.For(model)` 仍是生产入口（读 `Current` 一次），新增
  `For(model, context)` **纯函数**——清单不再依赖异步流，测试直接给上下文。
- `SessionAffinityHeaders.Apply/Describe` 改成**收值**，不再读环境；
  HTTP 处理器在 `SendAsync` 里取一次，写头与写日志用的是同一份值。

## 取舍

- **仍然是环境传递，这是被 SDK 逼的。** `ChatOptions` 到 `PipelineMessage` 之间没有可插入的通道，
  改写发生在管道最里层、拿不到调用栈上的局部变量。所以改的不是「用不用 AsyncLocal」，
  而是「把它关进一个文件、只留一个有作用域的入口」。
- **异步迭代器里的边界，写进注释免得下次误判。** 流式请求的作用域在迭代器体内挂上，
  覆盖整段枚举（含中途重发），但**调用方看不到内层设的值**——这与改造前一致，
  不是这次引入的；谁想跨层读都会读到自己那份。
- **每次 push 的代价**：一份 record + 一个作用域对象，一个请求两三次，与一次 HTTP 相比可忽略。
- **没做的事**：
  - 把上下文一路显式传到 `PipelinePolicy`。那要求每请求建客户端（连接池与序列化开销全重来），
    或者改 SDK 的管道模型，两者都不划算。
  - Chat / Responses 协议抽象。仍是 [ADR 0099](0099-OpenAI兼容层按职责分层，协议留出扩展点.md) 留的那件。

## 验证

- `UiharuMind.Core.Tests`：**3336 条 / 0 失败**（新增 `LlmRequestScopeTests` 6 条）
- `UiharuMind.App.Tests`：**1253 条 / 0 失败**
- `HttpAllocBench` 编译通过（基准项目绕开 `LazyChatClient`、自己建客户端，改为自己挂作用域）
- 测试改动只有两处性质变化：`ReasoningSource_IsCollected…` 改用纯函数入口；
  `LlmRequestScopeTests.Client_KeepsTheContextItWasCalledFrom` 把「客户端不抹掉外层」
  从**碰巧成立**（三个独立字段）变成**明确保证**（`with` 合并）。
