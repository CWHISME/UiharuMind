# 浏览器工具：PuppeteerSharp 驱动本机 Chrome，快照带编号

> **状态**：accepted，原型已实现（2026-10-08）。

`WebFetch` 读得了网页，做不了有状态的事：登录、填表、多步流程。智能体新增一档能力「使用浏览器」
（`AgentToolConfig.EnableBrowser`，默认关），三把工具按风险分而不按 DOM 动作分：

| 工具 | 做什么 | 审批 |
|---|---|---|
| `BrowserSnapshot` | 重拍当前页（可带 `find` 只回命中的行） | 不问 |
| `BrowserNavigate` | 打开地址 | 与 Shell 同一列：只读/自动编辑问，完全自动放行 |
| `BrowserAct` | click / fill / select / check / uncheck / press / hover / scroll / back | 同上 |

**贯穿三档的硬规则**：导航到本机、内网与非 http(s) 地址（`BrowserRisk`），完全自动档也要用户点一次——
浏览器版的「越界写入」，它们够得着用户网络里本不对外的东西。只看地址字面、不解析 DNS，
与越界写入不解析软链同一个取舍。

## 引擎：PuppeteerSharp，不带 Node

- 驱动用户已装的 Chrome（`Channel = Stable`），专用档案在 `Data/Browser`：用户在里面登录过的站点跨会话、跨重启保留。
  起浏览器、开页面都排队。
- **一个会话一个窗口，不是标签页**（`CreatePageType.Window`）。Chrome 只给前台标签页跑渲染帧，
  后台标签页里 Locator 等「位置稳定」永远等不到——并行的子代理实测连填输入框都超时。各开一个窗口，每个都是前台。
  浏览器起来时自带的空白页留给头一个会话，免得多一个空窗口。
- **否决 Playwright .NET**：它是薄客户端，干活的是 Node 写的驱动。1.63 的包按 RID 发布要多带 Node
  （macOS arm64 实测 116.5MB）加 12.8MB 的 JS。它的 AI 快照最成熟，代价是快照器得自己写——
  Playwright 只拿来当对照的尺子，不跑模型。
- **走管道不走调试端口**（`Pipe = true`）。冒烟末步 `quit` 是强杀，`ProcessExit` 不跑，
  走端口时三轮冒烟各留下一个孤儿 Chrome 占着档案；走管道后父进程一死管道就断，Chrome 跟着退（实测 `kill -9`）。
- 不连用户日常的 Chrome：Chrome 136 起默认档案不接受调试端口。要用日常浏览器的登录态，
  正路是 Chrome 144 起的 `chrome://inspect` 授权（每次连接用户点允许），留作以后的第二种宿主。

## 给模型看什么：无障碍快照 + 编号

不用截图：非视觉的本地模型也得能用，而且截图每轮重发太贵。快照器（`AxSnapshotWriter`）把无障碍树写成
`- 角色 "名称" [状态] [ref=eN]: 值` 的缩进文本，形状仿 Playwright 的 AI 快照：

- **只给能操作的元素编号**。没编号的（div 做的按钮）按看得见的文字找（`AxSnapshotSearch.FindByText`）。
- **编号按「模型写这条回复时看到的那份」对账**（`AxRefReconciler`）。同一条回复里的调用并行发出、抢同一把锁，
  前一步动手就重拍重编，后一步的 e21 可能已是别的元素，审批卡翻的也还是旧的。每轮（框架同一份历史 + 同一迭代号）
  谁先进锁谁记下开局编号表：结构没变照用；变了只认回同角色同名、前后都独一份的元素，认不准就拒、让模型重拍。
  不按 DOM 节点做稳定编号：PuppeteerSharp 的无障碍快照不给 `backendDOMNodeId`，要自己改读 CDP 的整棵树，代价不值。
- 无名容器不成行；只装一段字的段落、列表项收成一行；表单标签紧挨同名输入框时只留输入框。
- 收起的原生下拉框里的选项列出来但不编号；点它或对它 `select` 一律改成在所属下拉框上选这一项——
  弱模型会反复去点 `<option>`（没有位置，点不着），实测一次能耗掉七十万 token。
- 同几页对照 Playwright：httpbin 表单 635 对 1601 字符、中文维基首页约 1.1 万对 6.1 万，板块一个不少；
  省在不列链接 URL、不给容器编号、不保留层层 generic。

**每一步都回快照、都进历史**，所以结果怎么写（`BrowserResultFormatter`）决定了长任务的成本：

- 超出预算（12KB）时完整版落进会话草稿目录，内联的是精简版：导航、侧栏、页脚各收成一行，编号与完整版一致。
  不给头尾骨架——长页面的开头本是导航。
- 动作后只有少数几行原地变了（填字、勾选）就只给这几行；行数变了就整页重给，免得编号错位。
- 主动重拍时页面与上一份一字不差、且就在十秒内（同一批并行调用），只说「没变」。
  隔久了不这么做：上一份可能已被压缩折叠，「没变」就没了参照。

## 动作的细节

- 只等 `DOMContentLoaded` 再等网络静下来至多 3 秒，不等 `load`：慢资源会把 `load` 拖过超时。
  导航仍超时就交回此刻已有的内容并注明，报错只会让模型从头再开一次。
- 动作前挂上导航等待：动作后 0.7 秒内主框架起跳了就等新页面就绪，否则拍到的是半路上的空页。
- 弱模型常把值写进以动作命名的参数（`{"press":"Tab"}`），照收；按键为空当场拦下，不把 PuppeteerSharp 的内部异常透给模型。
  组合键（`Control+A`）按住修饰键再按，常见别名（Ctrl、Cmd、Esc）统一成 Puppeteer 的键名，认不出的键如实说该怎么写。
- 页面弹窗一律关掉、内容随下一次结果交给模型；离开页面的确认放行。
- 动作前也挂上文件选择框等待：点「上传」弹的系统选择框模型看不见、关不掉，框里是用户的整个主目录（实测）。
  动作里弹的当场关掉，并告诉模型这一步要交给用户；没挂等待时 PuppeteerSharp 交还系统（`Fallback`），接管时用户自己能传。
  代价是动作后约 10 秒等待还挂着，这期间用户亲手点上传会被吞掉一次。
- 下载不落 Chrome 默认的 `~/Downloads`（工作区外写盘、不经审批，模型也不知道存哪了）：`Browser.setDownloadBehavior`
  以 `allowAndName` 先按 guid 落进中转目录，下完按事件里的 frameId 认出会话、挪进它草稿目录的 `browser/downloads/`，
  路径写进结果。认不出框架（新开标签页里点出来的）归最近动过手的会话。动作或导航里开始的下载等至多 15 秒再交结果，
  大的下完随下一次结果说；直接导航到文件地址时导航中止（`ERR_ABORTED`），按下载报而不是报错。
  只作用于自动化用的独立档案，用户自己的 Chrome 不受影响；接管时用户亲手下的也进草稿目录。
  PDF 默认在 Chrome 的阅读器里打开、不触发下载，要读正文走 WebFetch 或 text 视图。
- 上传（`upload` 动作）：点目标弹出文件选择框，从拦下的框里把文件交进去；没弹框就报错让模型换目标（上传按钮或文件框本身）。
  文件只取工作区与草稿目录里已有的（`BrowserUploadFiles`），软链按真实位置判；工具层先解析成绝对路径再交给宿主。
  三档都问、不给「本会话允许」（`BrowserRisk`）：把本机文件交给第三方送出去就收不回，卡上写全路径与网站。

## 已知代价

- ~~**子代理不挂**~~：已由 [ADR 0075](0075-工具装配收成一处：能力与场合取交集.md) 解决，主子代理共用一个工具装配器，子代理各开各的标签页。
- ~~审批卡显示的是原始参数~~：已由 [ADR 0078](0078-浏览器：接管交给用户，审批卡说人话，读正文与截图.md) 解决，卡上按快照写「点击按钮『提交订单』」。
- ~~往密码框输入~~：已由 ADR 0078 解决，工具当场拒、改走接管。上传本地文件仍没有（原型没有上传动作）。
- ~~接管界面没做~~：已由 ADR 0078 解决，`BrowserHandoff` 借审批卡等用户做完交回。
- 档案目录有进程锁，同一档案开两个实例（ADR 0064）时第二个实例起不了浏览器。
- ~~标签页没有闲置回收~~：已加（ADR 0075），十分钟没被调用的标签页关掉，一个不剩时浏览器也关。
- 无头只能靠环境变量 `UIHARU_BROWSER_HEADLESS=1`（冒烟用），设置页没有开关。

## 冒烟

`browser-basic`：自带一张只开浏览器与文件工具的测试卡，三件事——表单填完提交并核对回显、中文维基查三个事实、
选下拉框再登录。Agnes-2.5-Flash-无思考下三轮，修完后三项全对，输入分别约 1.7 万、10.5 万、4 万 token。
