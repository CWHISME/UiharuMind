# 对话模板退役，旧值不迁移

`CharacterData.DialogTemplate` 连同它在系统提示里的那一段全部删除：

- `CharacterPromptBuilder` 不再拼 `Dialog Template:` 那一节，角色段变成「角色 Template → 用户卡」两段；
- 编辑页高级选项里那张「对话模板」卡删除；
- 角色卡导入时的 `mes_example` 改为**拼进 `Template` 末尾**（带 `Dialog Template:` 小标题）；
- **旧存档里已有的 `DialogTemplate` 值不迁移**，反序列化时静默丢弃。

## 为什么

1. **它是提示词的第二个抽屉。** 两个字段做同一件事：往系统提示里塞一段文本。区别只有一个
   小标题和一个折叠层级。
2. **它折在高级选项里，实际等于看不见。** 这与 ADR 0004（工作循环从框架默认搬进角色提示词）
   和挂载退役是同一条理由：**编辑页里看不到的东西不该悄悄进提示词**。对话模板是这条理由下
   最后一处还立着的字段。
3. **导入路径不能跟着一起丢。** 酒馆卡的示例对话往往是定调的大头（语气、格式），
   丢了导进来的角色会明显变味，而用户不会知道丢了什么。拼进提示词之后它照常生效，
   而且**在编辑页里看得见、改得动、不想要就删** ——与「片段插入后就是自己的文本」同一套口径。

## 取舍

- **不迁移旧值，是明知代价的选择。** 保留一个 `[JsonPropertyName]` 的遗物字段 + 一段只跑一次的
  加载期迁移，可以做到一字不丢；但那意味着为一个个人项目里屈指可数的存档长期背一段兼容代码。
  代价明说：**升级前在对话模板里填过内容的角色，升级后那段话不再发给模型，且查不出原因。**
  已知只影响本机存档，接受。
- **导入的提示词会变长。** 示例对话动辄几百字，拼进去之后新导入角色的提示词框第一眼会显得很满。
  这正是想要的——那些字本来每轮就在发，只是以前藏着。
- **ADR 0005 里的顺序少了一段。** 那份记录不改正文（它是当时的决策），末尾加了一条后续注；
  `docs/CONTEXT.md` 里的顺序直接改成四段——术语表只反映当下。
