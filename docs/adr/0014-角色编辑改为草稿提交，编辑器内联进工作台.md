# 角色编辑改为草稿提交，编辑器内联进工作台

角色域的编辑语义与界面层级一起改了，两件事的取舍互相锁死，因此写在一处。

## 编辑语义：草稿 + 显式提交

角色编辑从「直接改活实例」改成「改一份深拷贝，提交时往活实例上盖」：

- `CharacterInfoViewData` 瘦成**只读展示项**：名字、头像、描述、档位、`SearchText`，
  外加开始对话 / 复制 / 删除三个命令。它挂的是角色库里那个活实例。
- 新增 `CharacterDraft`：所有可写字段、能力面板、子智能体名单都归它，内部
  `_draft = origin.DeepCopy()`。`TryCommit()` 校验名字、补正参数写法，然后
  `origin.CopyFrom(_draft)` + 落盘 + `CharacterManager.NotifyCharacterUpdated`。
  取消就是把草稿丢掉，什么也不用撤。
- 提交是**就地覆盖而不是换实例**（`CharacterData.CopyFrom`）：`ChatSession` 会把角色引用
  缓存在 `_characterData` 上，换实例会让正在进行的会话继续用着旧对象。
- 脏检查取整份序列化结果比对（`SaveUtility.SaveToString`），只在切换/关闭这种低频时刻算一次。

## 界面层级：内联为主，弹窗保留给对话侧

角色工作台从「列表 → 只读预览卡 → 再开一个编辑窗」三层压成两栏：

- 左栏收窄成导航列表（默认 280px，可拖 220~420），一行一个角色。
- 右主区 = 身份条（小头像 + 名字 + 档位徽章 | 开始对话、重置/取消、保存/创建、溢出菜单）+ 整份
  `CharacterEditView`。**预览卡与那个可折叠的第三栏退役。**
- `CharacterEditWindow` **保留**，只服务对话页右栏「改当前角色」与会话列表右键两个入口。
- 「新建」不再弹窗：头部 `[+]` 选完档位，右主区当场变成新草稿，左栏顶上一条还没入库的占位项，
  取消即撤。
- 草稿没提交却要切走时弹三态：保存 / 放弃 / 继续编辑（`IMessageService.ConfirmWithCancelAsync`，
  为此新增，原先只有两态的 `ConfirmAsync`）。

## 为什么

1. **「没点保存却已经改完了」是个真 bug。** 旧的 `CharacterInfoViewData` 每个 setter 都直接写
   `_characterData`——那正是 `CharacterManager.CharacterDataDictionary` 里、会话也在引用的同一个
   对象。`SaveCharacter()` 只是落盘。于是关掉编辑窗再打开，看到的还是改过的样子；更糟的是
   正在对话的那个角色也当场被改了，而用户以为自己「没保存」。
2. **一个类同时当列表项和当表单，就不可能既有草稿又有正确的列表。** 草稿要藏起来，列表要显示
   已提交态——同一个实例做不到。拆两个类型之后，两边各自完整，325 行的肥类也顺带拆开了。
3. **三层导航里，中间那层不产生信息。** 预览卡显示的名字/头像/描述，编辑表单的基础信息区
   原样再显示一遍；要改还得再点一次「编辑角色」。合并之后一屏就是「看到的即能改的」。
4. **对话侧不能跳页。** 那两个入口是在对话进行中调角色的工具开关与提示词，跳到角色页会打断
   上下文；`EditActiveCharacter` 还要把 `CurrentRunner.GetCapabilities()` 这份运行期快照交给
   编辑页标「关掉这一档能省多少 token」，跳页意味着角色工作台得知道正在跑的那一轮——
   一条不该有的耦合。所以窗口壳留着，视图只有一份，两个宿主各摆各的按钮条。

## 取舍

- **`CopyFrom` 是逐字段写的，漏一个不会有编译错误。** 代价明说：新增可持久化字段必须跟着加一行。
  兜底是 `CharacterDataCopyFromTests`——判据是**整份序列化结果相等**，因此新字段自动纳入，
  漏抄当场红。选逐字段而非反射，是因为字段少且读起来直白。
- **脏切换弹窗而不是静默丢弃。** 内联布局下「手滑点到列表另一行」比弹窗年代容易得多，
  而写了半小时的提示词没有任何拦截就消失是不可接受的。代价是多一个三态弹窗，以及一个
  `DrivingSelection` 守卫——**选中项不只用户会改**：回滚、撤占位项都会改它，而从集合里摘掉
  正被选中的那一项时 `ListBox` 会先往 `SelectedCharacter` 回写一次 **null**。那几次跳动
  既不该问去留，也不该重建草稿。`SelectedCharacter` 因此是可空的，「没有选中项」是一等状态
  （右主区显示空态），不再拿一个不在列表里的空角色顶着。
- **没入库的新角色是编辑器的临时状态，不是能导航回去的列表条目。** 一旦切走就撤掉占位项
  （改过东西的先问）。留着它的话，切回来会拿它开一份「编辑已有角色」的草稿——`IsNew` 变 false，
  于是一个还没存过的角色上会出现「开始对话」。
- **「重置 / 取消」按钮不按脏与否置灰，改成点击时问一句。** 能力面板与参数面板都是直写草稿对象、
  不经草稿的属性通知，「有没有改」做不成可靠的实时量；灰着的按钮挡住一次合法的重置，
  比一个总是可点、点了才问的按钮更糟。点击时现算的脏检查不论改动来自哪里都准。
- **新建走「占位项」而不是「先建一个空角色再改」。** 后者代码最简，但随手点几下就会多出几个
  垃圾角色文件，也与刚定的「草稿 + 显式提交」自相矛盾。代价是列表要容纳一个还不在
  `CharacterManager` 里的临时项——`BeginPending` / `CancelPending` 那两个方法就是它。
- **照片墙退役，连同 `Setting.IsCharacterPhotoListView`。** 左栏收窄到 280px 之后画廊每行只放得下
  一张卡；一个默认状态就很难看的模式不值得留着。大头像在右主区身份条与表单基础信息区都看得到。
- **左栏头部收进溢出菜单，换来一个搜索框。** 筛选从「一眼可见的四个胶囊」变成「一次点击」，
  这是明知的退步；换来的是角色多起来之后真正好使的过滤方式，以及窄栏里放得下的头部。
- **列表右键菜单里没有「编辑」。** 选中即在右边编辑，再放一项只是重复。
- **改完之后不再符合筛选的项会当场从列表消失**（`OnCharacterUpdated` 里判 `Matches`）。
  不这么做的话，那一行会顶着一个与当前筛选自相矛盾的徽章赖着不走。

## 代价（明说）

- **角色页没有页面标题了。** 原来那条「角色工作台 / 管理角色扮演、工具人与智能体」占一行，
  而左侧导航已经说明了你在哪一页。相关的四个 Lang 键一并删除。
- **`ImportCharacterWindow` 不再复用编辑视图数据。** 它改为直接产出 `CharacterData` 并入库；
  「重名了要不要改」那一步随之消失——标识是 GUID，本来就撞不上。
- **用户卡编辑窗也改走草稿。** 它此前同样是直接改活实例，且点保存不关窗。现在与角色编辑一致。
