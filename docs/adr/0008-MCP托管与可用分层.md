# MCP 的「托管」降级为连接层，「可用」按角色配

`AgentToolConfig` 新增 `DisabledMcpServers`（黑名单，与 `DisabledSkills` 同形，
子代理 `Intersect` 取并集）。同时 `McpServerConfig.IsEnabled` 的语义**降级**：
它不再表示「这个 server 的工具生效」，只表示「要不要为它拉起进程 / 建立连接」。

运行期判断一个智能体能用哪些 MCP 工具，**只读角色那份黑名单**。

同一轮里，配置的磁盘形态换成生态标准的 `mcpServers` 形状（旧格式不做兼容），
`Arguments` 由空格分隔字符串改为 `List<string>`，HTTP 传输补 `Headers`，
连接失败改指数退避并留下错误原文，`ServerInstructions` 开始被消费。

## 为什么

MCP 工具此前是**全局无差别下发**的：只要 server 启用着，每个 agent 档角色都吃下它的全部工具。
这是 ADR 0003 那条「能力按角色配」下唯一的例外，而它带来的后果不止是"不够精细"：

1. **一个只读的调研智能体会拿到能改东西的 MCP 工具。** 别的工具都能逐项关，唯独这一批不能。
2. **token 成本无处收窄。** 工具定义每一轮完整重发，用不用都付。本地 GGUF 的上下文常常只有
   8K–32K，接两三个 server 就可能吃掉一大半，`HistoryCompaction` 因此更早开始压缩历史。
   云端模型是花钱，本地模型是直接失能。
3. **子代理没法收窄。** `Intersect` 管得住 shell、文件、搜索，管不住 MCP——
   挂一个子智能体就等于给父代理开了一条绕过口。

## 取舍

- **为什么不是「`IsEnabled` 与角色名单两层 AND」。** ADR 0003 明文反对两层 AND：
  「角色开了却没挂上」要查两处。所以这里不是加一层，而是把原来那一层**挪到另一个问题上**：
  `IsEnabled` 回答的是资源问题（stdio server 意味着一个常驻子进程，HTTP 意味着一条连接），
  角色黑名单回答的是能力问题。两者不再是同一个问题的两个闸，因此「为什么没挂上」始终只有
  一个去处：角色。

  代价是 `IsEnabled` 的含义变了而名字没变，单看字段名会误读。这条靠 `McpServerConfig` 的
  类注释、`CONTEXT.md` 的对照表和设置页的 tooltip 兜住。

- **为什么是黑名单不是白名单。** 与 `DisabledSkills` 同形，空名单即全给，零迁移。
  代价明确且被接受：**新配的 server 依旧自动下发给所有智能体**。选它是因为白名单会让
  「每新建一个智能体都要手勾一遍」成为常态，而这个项目里 server 的数量远小于智能体的数量。
  真正的成本控制交给右栏那份可见的 token 账，而不是交给默认拒绝。

- **为什么 `InjectInstructions` 留在 server 上而不是角色上。** 它不是能力闸门——
  关掉它，工具照挂，只是不再把 server 那段自述拼进提示词。它不决定「谁能用」，
  所以不构成上面反对的那种两层 AND。放在 server 上是因为「这个 server 的说明太长」
  是 server 的属性，不是某个角色的偏好。

- **为什么撞名才改名。** 无条件加前缀确定性最好，但工具名变长，本地小模型更容易拼错，
  且每个工具多占几个 token。而归属本来就靠 `McpToolSet.Groups` 记账，不靠名字，
  所以不撞名时改名没有任何收益。撞名时**双方**都加前缀——只改一边的话，
  "哪一边被改"取决于遍历顺序，等于把不确定性藏得更深。

- **为什么旧配置不做迁移。** 个人项目，MCP server 数量是个位数，重加一次的成本低于
  维护一段只跑一次的迁移代码。旧文件反序列化失败即按空列表处理，不报错、不阻塞启动。

- **为什么不做延迟加载（tool search）。** 那是省 token 最狠的一招（业界实测可达一个数量级），
  但要求模型可靠地「先搜再调」，本地弱模型未必做得到，反而可能整体变笨。
  本轮先靠黑名单降量、靠右栏把成本摆到明面上，观察之后再定。

## 后果

- `AgentAssemblyFacts` 多一个 `DisabledMcpServers` 字段。**没有**为 server 自述另加字段——
  自述随工具在同一次刷新里取回、同一次自增 `McpRevision`，已被覆盖。
  这与 `WorkspaceInstructions` 必须入账不同：那个是磁盘文件，没有修订号可依。
- `McpManager.Resolve` 收角色黑名单作参数，返回 `McpToolSet`（工具 + 分组 + 自述三样同出一刻）。
  分开取会让右栏展示的与实际挂上的对不上号。
- 装配产物挂在 `AgentHandle.Mcp` 上，右栏「能力」面板据此展示**真相**而非二次推导。
- 并集与改名的规则提到纯函数 `McpToolSetBuilder` 里，可单测。
