# 视觉模型经 Read 看图，ViewImage 退役

> **状态**：accepted，已实现（2026-10-08）。修订 [ADR 0053](0053-ViewImage发送时投影，历史只存路径.md) 的「挂载」一节，投影本身不变。

视觉模型原先要用单独的 `ViewImage` 看图。文件本该一把 `Read` 读完，模型也普遍习惯拿 `Read` 打开图片；
多一把工具，只是多一份每轮重发的定义、多一次选择。

决定：**视觉模型经 `Read` 看图，`ViewImage` 退役**，非视觉模型仍走 `AnalyzeImage`。`Read` 读到图片时怎么办随装配定（`EReadImageMode`）：

- 视觉模型且识图开关开着：缩成预览副本，结果给路径，图由投影带上（ADR 0053 原样）。
- 非视觉模型且 `AnalyzeImage` 挂着：说清是张什么图（格式、尺寸、大小），指向 `AnalyzeImage`。
- 都不成立：如实说这次会话看不了图，不指名任何工具。

`Read` 的描述只在第一种装配里提图片。

**哪次 `Read` 算看图只看调用参数里的路径**（`ImagePreview.IsImageRead`，按扩展名），投影、压缩估算、工具卡缩略图都用它。
`Read` 自己也只按扩展名分流：图片扩展名一律走看图，内容不是图片就报错，永远不当文本读出来，两边因此不会对不上。
若按结果文本里的 `Preview:` 行来判，读一份恰好写着这种行的文档，就会把本地任意文件当成图发出去；
那个文件不是图片的话，此后每次请求都会被服务端拒绝。

## 后果

- 不兼容旧数据：历史里的 `ViewImage` 调用不再投影，工具卡也不再显示缩略图，只剩结果里的路径文本。
- 多张图对比改成同一条回复里并行发几次 `Read`，投影本就把同一串工具结果的图合成一条 user 消息。
  原先「一次最多 4 张」的上限没有了，它从来也限不住总量。
- 探索档子代理也能看图：看图只是读，投影本来就随子会话的模型挂着。`AnalyzeImage` 仍只在可变更的档位挂（它要另调一个模型）。
- 类名随之改为 `ImagePreview`（预览副本与结果格式）与 `ImagePreviewProjection`（投影）。
