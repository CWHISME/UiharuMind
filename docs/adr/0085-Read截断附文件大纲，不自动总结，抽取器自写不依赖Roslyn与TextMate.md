# Read 截断附文件大纲，不自动总结；抽取器自写，不依赖 Roslyn 与 TextMate

> **状态**：accepted（2026-10-12）。与 [ADR 0083](0083-搜索工具结果改纯文本.md) §六「过宽时给分布，不给半截」同一思路，
> 落在 Read 上；整份理解的去处是 [ADR 0082](0082-Brain工具：同步、有界、只读的小模型助手.md) 的脑工具（现名 `Summary`）。

## 背景

Read 读大文件被截断时，模型只拿到开头一页和一句「续读传 offset=N」。它不知道后面有什么，只能一页页往下翻，
或者换 Grep 盲搜。本地小模型的上下文经不起前者，后者又常搜偏。

讨论过「超上限就交给附属模型整理一份总结」，否决，见下。

## 决定

1. **Read 从头读（offset=1）且被截断时，在截断附注后附一份确定性大纲**：
   每行 `[起–止] 结构`，按嵌套缩进，模型据起止行算出 offset 与 head，只读那一段。
   - 行号套方括号、范围用 en dash（与截断附注同），不写成 `行号:` `行号-`——那是 Grep 命中行与上下文行的形状，
     同一会话里两种格式并存，小模型会错认。
   - 带 offset 翻页时不附：第一页已经给过。没截断不附。
   - 自己传了 head 的，文件至少是所读的两倍长才附：翻一页就完的不值约 1k token；
     但冒烟实测模型常用 head=80 浅读一个上千行的文件就停，这时正需要大纲（起初「传 head 就不附」，因此改回）。
   - 8MB 以上走流式读的文件不附：多是日志与生成物，为它多扫一遍不值；支持的类型只提示一句「可传 outline=true」。
   - Read 另有 `outline=true`：只返回大纲（上限 200 条），不管文件多大；此时忽略 offset 与 head 并注明。
   - 整段落在已显示正文里的结构不再列出，预算留给模型还没看到的部分。
   - 大纲最多 60 条；超了先整层裁掉最深的结构（保住骨架）并注明，仍超才截尾，并指向 `outline=true`。
     顶层只有一个结构（一个文件一个类）时裁不掉它下面那层：冒烟实测裁到只剩类本身，大纲就只有一行，等于没给。
2. **Grep 命中前标出所在结构**：所在的最内层结构变了就插一行 `[位于 起–止] 签名`，方括号开头，
   不与 `行号:` 命中行、`行号-` 上下文行混淆。命中落在声明行本身（查定义）时标外层，否则只是把下一行重复一遍。
   - 只在返回正文时标：走不走命中地图只看不带标注的正文；补了标注超预算就整段不补，标注不能把正文挤成地图。
   - 整份文件只有一个顶层结构时不为它标（几乎每处命中都在它里面，标了是噪音）；声明行已作为命中或上下文显示时不再标。
   - 命中超过 30 个文件或文件大于 1MB 不标：每个文件要读一遍抽大纲。
   - Grep 之后、读大纲之前文件被改，标注会错位且不报错。概率低，不为它做版本校验。
   - 为此大纲条目带结束行 `OutlineEntry.EndLine`：大括号闭合处、Markdown 下一个同级或更高级标题前、Python 按缩进。
3. **截断附注后指一条去处**：脑工具挂载时追加「要整体理解这份文件，可交给 `Summary`，task 里写清要什么」。
   没挂（含脑自己的子会话）不提。模型自己传了 head 也不提：那是在按段读，没读完不等于需要整体理解。
4. **抽取器结构**（`Tools/Files/Outline/`）：
   - `OutlineEntry(Line, Depth, Text, EndLine)` + `IOutlineExtractor`（扩展名 → 单遍抽取）；`FileOutline` 按扩展名分派，
     预算、裁剪、渲染统一在这里。新增文件类型 = 实现抽取器 + 注册一行。
   - 大括号语言共用 `BraceOutlineExtractor`（模板方法）：`CLikeCodeScanner` 剥注释与字符串，基类维护大括号栈、
     攒「声明头」，子类只回答「这段头是什么、它的大括号里装什么」。进了方法体只数括号不认结构，局部函数与 lambda 不混进来。
     各语言字面量差异由 `ELiteralSyntax` 位标志描述（逐字/原始/反引号字符串、字符字面量、C++ 数字分隔符、
     JS 正则字面量、Rust 生命周期）。不写分号的语言（Go、JS/TS）换行即结束语句，行尾是运算符、括号没配平、
     或是类型声明头还在等大括号时除外。括号里的 `{ }`（JS 解构参数、C# 对象初始化器）算声明头，不开块。
   - 已支持：C#、C/C++、Java、JS/TS、Go、Rust（大括号基类）；Python（按缩进，单独实现）；Markdown（`#` 标题，跳过围栏与缩进代码块）。
     各语言只列类型与函数，不列字段与局部函数。在本机约 8.6k 个这些语言的真实文件上跑过，无异常。

## 为什么不自动总结

- **Read 是 Edit 的原文来源。** Edit 要逐字匹配 oldString、靠行号定位；总结是有损的，模型会拿总结里的字去 Edit。
- **Read 不知道模型为什么读。** 不带意图的总结大概率答非所问；脑工具带 `task`，形状才对。
- **已有工具做这件事。** 脑工具就是为「大文件要总结」设计的，再在 Read 里做一套是重复造轮子。
- **会让便宜的工具变贵、变不确定。** Read 毫秒级、结果可复现；塞进模型调用后一次 Read 可能等几十秒，
  小模型总结代码还会编。

## 为什么抽取器自写

- **Roslyn**：C# 上最准、写起来最省（语法树取声明），但只认 C#/VB，以后的 C++、Python 用不上；
  多约 10MB 依赖。真正让多语言统一的是 `IOutlineExtractor` 这层，不是某个解析库。
- **TextMate**（界面高亮在用，文法覆盖面广）：作用域不是语法树。实测 C# 文法把方法声明 `Render` 与调用
  `GroupBy`/`ToList` 都标成 `entity.name.function.cs`，类型声明与类型引用也只差后缀，且没有 `meta.*` 嵌套；
  Python 文法则干净。各语言文法质量参差，要认「声明」仍得自己按位置判断，省不了事。
- **自写的代价**是启发式：插值字符串洞里再套引号、宏这类写法会认错，括号不配对时忍着不作废。
  在本仓 1853 个 .cs 文件上跑过，无异常，13 个文件抽不出结构（多为只含全局 using 的文件）。

## 界面

全文窗给 Read 结果编行号时，截断附注及其后的大纲、提示不编号（`LineNumbering(First, Count)`：
首行对应原文件第几行、前几行是原文），免得附注冒充文件内容。

## Read 正文带行号（后补）

冒烟让模型研究一个陌生项目：整份读完的文件没有任何行号参照，模型只能自己数，报出的行号偏十几行。
与 Claude Code、OpenCode、deepseek-harness 一致，Read 正文改为每行带前缀 `  82→`（右对齐），读到末尾附「已到文件末尾，共 N 行」。

- 用 `→` 不用 OpenCode 等的 `82: `：那与 Grep 命中行 `行号:` 同形。
- Edit 兜底剥前缀（那三家只靠工具说明）：**先按原样匹配**，找不到、且 oldString 每行都带前缀、行号逐行加一时，
  才剥掉再找；剥过之后 newString 里带前缀的行逐行剥（新写的行常不带或乱编行号），回执里说一声。
  文件里真有「数字→」开头的内容时原样就能命中，不会被剥。
- 界面（卡片、全文窗）剥掉前缀显示，行号栏直接用前缀里的行号；加前缀之前存下的旧会话仍按 offset 与截断附注推算。
