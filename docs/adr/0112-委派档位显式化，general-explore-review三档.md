# 委派档位显式化：general / explore / review

新开子代理的那个参数从 `isExplore: bool` 换成 `mode: string`，取值 `general` / `explore` / `review`
（中文 `通用` / `探索` / `评审` 也认）。`review` 是新增的**评审档**。

**三档挂同一份工具集**，能不能改东西只由**权限档**回答——档位只决定产出纪律、身份卡与模型
（修订见文末）。

## 为什么不是一个 bool

`isExplore` 只放得下两档。加第三档时它立刻不够用：要么再塞一个 `isReview`（组合出「既探索又评审」
这种没有意义的状态），要么让模型在参数里拼字符串，而它拼错了没人会知道——静默落进通用档，
表现是「以为派了评审，实际派了个通用档」。

档位名直接给模型看也更省事：`general` / `explore` / `review` 是它训练里见过的词形，
比「把某个布尔置真」更容易用对。

## 为什么评审是独立的一档，而不是探索档的一个模式

先看三档**相同**的部分：工具集逐字相同（见文末修订），轮次上限都沿用委派上限，右栏都照常列条目。
所以工具表里它们**共用一个场合**（`EAgentToolScope.SubAgent`），不为评审再抄一份工具清单；
抄一份的下场是以后加能力时只改一边。

不同的那三处正好是「一档」该有的差别：

1. **产出形状**。探索交的是「我翻到了什么、结论是什么」；评审交的是「能不能合 → 问题清单
   （位置 → 是什么 → 为什么 → 建议改法），按严重度排」。这两句话在提示词里没法合并：
   合起来会写出一段谁都不照做的套话。
2. **身份卡**。`ReviewAgent`（左栏与右栏显示的名字、头像）——用户得一眼看出这次派的是谁。
3. **模型**。设置页多一行「评审模型」：评审常常值得比探索更贵的模型（它要挑毛病，
   而探索只是翻材料），这两件事该能分开配。

## 形状

- `ESubAgentType` 加 `Reviewer`；`SubAgentProfile.Reviewer`。
- **类型 → 档案只有一处映射**（`SubAgentProfile.Of(type)`）。装配、右栏标记、身份卡都走它：
  各写一份 `switch` 的下场是新增档位时漏一个分支，而漏进 `default` 不会报错——
  表现是新档悄悄按通用档装配，能改文件。
- `SubAgentMode` 管字面量与解析（含中文别名、大小写与空白容错），空白 = 默认 `general`。
  **认不出来就当场回绝**（工具结果里列出可选值），不静默降级：降级会把只读请求变成可写请求。
- 脑**不在**档位表里：委派不该能派出一个脑，脑有自己那把工具、语义（同步、有界、不反问）也不同。
- 工具参数的说明是 `[Description]` 的实参，只能是常量，没法从 `SubAgentMode.All` 拼出来；
  两边的一致性由测试钉（漏写一个值，模型就不会用它，而这种漏不会报错）。

## 已知代价

- **参数说明变长了**（从一句变成三行）。它随工具定义每轮重发，是实打实的固定开销；
  换来的是模型能把「调研」和「评审」分开派——之前这两件事都被它丢进通用档。
- **`mode` 与 `agent`（点名）正交**：点名决定人格，`mode` 决定分工与模型。会不会出现
  「点名了一个能干活的子智能体，却又说 review」？会，语义是「让这个人去做评审」——
  他怎么说话归角色卡，做什么活归 `mode`，能改不能改归权限档，三者互不覆盖。
- 旧会话里那张委派卡片仍原样显示它当时的 `isExplore` 参数——历史是历史，不改写；
  新委派显示 `mode`。两者对已经发生的事没有影响（工具不会重放）。

## 修订（同日）：档位不再自带只读边界

第一版让探索与评审「恒定只读」（装配期挂不上写工具，`EAgentToolScope.ReadOnlySubAgent`）。
改掉了：**三档挂同一份工具集，能不能改东西只由权限档回答**，档次只回答「干什么活」。

理由是这个区分不成立：档位讲的是分工（实现 / 调研 / 评审），权限讲的是边界（能不能动手），
两件事本来就该分开。把它们绑在一起，用户想要的组合根本表达不出来——「派个评审去看看，
顺手把明显的错改了」在完全自动档下是很自然的要求，旧设计只能回绝它；反过来，想让探索别乱改，
它靠的也是权限档，而不是档位这个名字。

代价要说清：**「调研 / 评审不会顺手改东西」这条不再由装配保证**。剩下的只有权限档与提示词里的分工句，
而**默认权限档是「自动编辑」**（`FactoryDefaultPermissionModeIndex = 1`）——那一档的规则是
「工作区内写工具直接放行、不弹卡」（`ApprovalModeMapper`）。也就是说对大部分用户：
派出去做调研或评审的子代理，在工作区内改文件是**零摩擦、无提示**的。

两种极端也要知道：只读档下写调用会变成「等一张看不见的审批卡」，到点按拒绝收口
（子会话窗口里能点，右栏也会挂「等审批」）；完全自动档下越界写入才要一次确认。

所以这一版的口径是：

- 提示词里不能再写「你改不了东西」（假的），`mode` 参数说明也不能再写「review 是只读」；
  评审纪律只能说「你的活是评，不是改」——那是分工。
- 右栏那句「只读」标记改成看**会话自己的权限档**（外加脑：它恒只读，权限档是继承来的），
  否则它会对一个完全自动档的评审说谎。
- 这条修订推翻了 ADR 0021 / 0030 / 0044 / 0075 里「探索档恒定只读」的产品决定；
  那几篇保留原样作为当时的记录，当前口径看本篇与 `CONTEXT.md`。
- 真要「这次委派不许动任何东西」，位置在权限档（或将来一个独立的只读开关），不在档位名上。
