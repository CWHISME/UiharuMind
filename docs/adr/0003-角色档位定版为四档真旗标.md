# 角色档位定版为四档真旗标，工具开关下沉到角色

`ECharacterKind` 从两档（`Roleplay` / `Agent`）改为四档真旗标：
**角色扮演 / 工具人 / 智能体 / 用户卡**。派生标记 `IsPurePromptCharacter`（以及 UI 侧的 `IsRole`）
退役，`IsHide` + `IsHideDefault` 收敛为单一的可见性标记 `IsInternal`。
扮演脚手架降级为「插入预设文本」，用户卡降级为 `InjectUserCard` 开关，
**`MountPrompts`（运行期内联挂载）整体退役**，`MountAgents` 复活为智能体的
「可委派子智能体名单」。

同一轮里，Agent 的工具开关与技能禁用清单从全局 `AgentSettingConfig` **下沉到角色**，
全局那批 `Enable*` 与四段工具提示词覆盖一并退役（分阶段落地，见文末）。

## 为什么

原先「扮演 vs 工具人」是从挂载列表**派生**的：`IsPurePromptCharacter => MountPrompts.Count == 0`。
这套派生有三处塌方：

1. **它与新加的真旗标并存，必然产出脏组合。** `CharacterPromptBuilder` 不看 `Kind`，
   所以一个 agent 档角色照样能有挂载，于是徽章会给智能体贴上「角色」。
2. **它没有可操作的界面。** 用户不能直接翻这个轴（要增删挂载项），于是编辑页只能摆一个
   **禁用的开关**——展示一个坏了的控件。
3. **脚手架一旦不再走挂载，派生就没有依据了。** 而脚手架确实该退出挂载：挂载的本质缺陷是
   **不可见**，编辑页的提示词框里看不到脚手架的一个字，模型却先收到它。

`IsHide` / `IsHideDefault` 这对旗标同时在表达四件不同的事——可对话角色、只有被挂载才有意义的
提示词片段、程序点名取用的技能内部角色、以及单例用户卡。因此「谁能被挂载」根本无从判断：
内联选择器一律排除 `IsHideDefault` 时，连一个内置脚手架都挑不到（内置 `UiharuKazari` 挂的正是
`Roleplay_ThirdPerson` + `UserCard`，用户没法通过界面复刻它）；放开 `IsHideDefault` 时，
候选里立刻混进 8 个技能内部角色。这道题最后是靠**取消挂载**解掉的（见下），
但即便保留挂载，可挂载性也必须是独立判据，不能从可见性反推。

## 取舍

- **为什么工具人不是「零工具的智能体」。** 这是本轮最要紧的一条。`BuildRoleplayOptions` 对框架是
  一串显式关闭：`HarnessInstructions = string.Empty`、`DisableWebSearch`、`DisableFileMemory`、
  `DisableTodoProvider`、`DisableAgentModeProvider`、`DisableAgentSkillsProvider`、
  `DisableCompaction`、`DisableToolAutoApproval`、`DisableOpenTelemetry`。所以工具全关的智能体
  仍然会吃下框架那一大段平台指令、技能目录 provider、上下文自动压缩与审批机制，还带着工作目录
  与权限档。**分岔点是「要不要 agent 平台那一套」，不是工具数量。** 让翻译、OCR 这类一次性
  提示词角色跑成「零工具智能体」是实打实的 token 与行为代价。
- **为什么挂载整体退役，而不是留给「把我自己的角色挂给另一个角色」。** 收窄之后它只剩这一个
  用途，而这个用途与「插入片段」重叠：后者在编辑期把文本拼进去，所见即所得；前者在装配期偷偷拼，
  编辑页看不到。唯一真正需要运行期活引用（改一处、所有引用者跟着变）的是**用户卡**，而它已经有
  专门的开关。留着挂载就是留着一条能产生"我明明没写这句话，模型却收到了"的通路。
  `MountPrompts` 字段一并删除——它只有三个使用者（数据、拼接环、编辑页那张卡）。
- **提示词片段不是角色。** 片段只有名字与正文两个字段，整库一个 json，首次运行播下两条内置预设
  （第一/第三人称脚手架），此后与用户自建的片段没有区别；插入面板底部可把当前提示词**存为片段**，
  于是"新增片段"不需要另一个编辑窗。曾让两个 `IsInternal` 内置角色充当脚手架文本来源，那是角色卡
  （二十多个字段、存档目录、档位、图标）在给一段纯文本当容器——正是这轮要拆掉的兼职。
  `Roleplay_FirstPerson` / `Roleplay_ThirdPerson` 因此退出 `DefaultCharacter` 枚举。
- **`MountAgents` 复活为子智能体名单。** 现有 `run_subagent` 的子代理是**匿名**的：提示词由
  `BuildSubAgentInstructions` 现场生成（身份 + 权限边界 + 报告体例 + 工作区规矩），`Name = "SubAgent"`，
  只从父代理继承工具集与权限档，不继承人格。名单让每一项都是一个真的智能体档角色（人格取其
  `Template`，工具取其自己那份配置），空名单退回匿名通用子代理。三条不变量：**权限取父会话档位与
  子角色的交集**（否则挂一个"完全自动"的子智能体等于绕过当前会话的只读档）；子智能体自己不能再有
  子代理；装配时按 `Kind == Agent` 过滤名单而不信任存档（旧存档里这里可能躺着 `Vision` 这类工具人）。
- **为什么不给「提示词片段」单独一档。** 真正的片段只有 `Roleplay_FirstPerson` /
  `Roleplay_ThirdPerson` 两个文件（第三个 `SystemLanguage` 是死的：全仓无引用，其 `{{$lang}}`
  早由 `BuildPromptArguments` 无条件注入，已删）。而这两个是**互斥单选**——没人会同时挂第一人称
  和第三人称。互斥单选是角色身上的一个属性，不是一个可挂载的对象，所以它降级成「插入预设文本」，
  多一个档位换来的只是一个目前没人用的扩展点。
- **为什么用户卡单独成档而不是继续用 `IsHide`。** 它是单例、有专属编辑窗、语义是「我是谁」，
  且必须**保持活引用**（改了用户卡，所有开着开关的角色下一轮跟着变）——这一点决定它不能像
  脚手架那样内联成死文本。给它一个档位，`IsHide` 就没有第二个用户了。
- **`Empty` 哨兵仍靠标识点名排除。** 它是「没有角色」的占位（聊天页无会话时的默认角色），
  既不该进角色库也不值得为它开一档，因此 `CharacterManager` 里按 `DefaultCharacter.Empty`
  显式跳过。这是本次唯一保留的按标识特判。
- **为什么去掉全局工具开关而不是留一层总闸。** 两层 AND 意味着排查「角色开了却没挂上」要看两处。
  执行安全实际由**权限档**（只读/自动编辑/完全自动）兜，不是由这些开关兜，所以总闸并没有它看上去
  那么值钱。新建智能体的默认值由代码里的字段初始值给。
- **子代理继承父角色的工具配置。** 否则 `run_subagent` 会凭空拿到比父角色更大的权限。
- **工具提示词覆盖直接删掉。** 它调的是「模型怎么用工具」而非角色人格，四段自定义文本换来的
  是 `AgentAssemblySnapshot.ToolPromptOverrides` 这一整个字段（它存在的唯一理由就是"改了覆盖
  文本要重建装配"）。

## 代价（明说）

- **老存档的工具人会被读成扮演档。** 现有用户角色一律是 `Roleplay`（界面此前根本没有改 `Kind` 的
  地方），改档后 `Roleplay` 专指扮演。没挂载过东西的老角色需要手动改成「工具人」。
  不写迁移代码：个人项目量级，且靠"有没有挂载"猜档位正是本次要拆掉的那套派生。
- **内置角色覆盖文件可能带着退役旗标。** `SaveDefaultCharacterDataPath` 下你改过的内置角色副本里
  还有 `IsHide` / `IsHideDefault`，反序列化时会被忽略（因而落到默认可见）。清空该目录即恢复出厂。
- **老存档里挂载过的角色会丢掉那部分提示词。** `MountPrompts` 字段删除后，反序列化直接忽略它，
  那些角色的系统提示会变短——需要把被挂载的文本用「插入片段」重新拼回去。受影响的只有手动挂载过
  东西的角色（界面上此前也只有那一张卡能做这件事）。
- **`UiharuKazari` 的 Template 变长了。** 第三人称脚手架的正文被内联进去。这是"所见即所得"的
  必然代价，换来的是编辑页里看到的就是模型收到的。

## 分阶段

1. **模型定版**（本 ADR 落地的部分）：四档、派生退役、`IsInternal`、挂载退役、
   片段库（`PromptSnippetManager` + 插入/存为片段面板）、用户卡开关、14 张内置角色卡定档、
   术语表与本文件。
2. **工具开关下沉 + 子智能体名单**：`AgentToolConfig` 挂到角色，全局 `Enable*` 与提示词覆盖退役，
   `AgentAssemblySnapshot` 改读角色那份，`run_subagent` 加"派给谁"与名单，不变量测试跟着改造。
   名单排在这一阶段是因为子智能体的工具集要等工具下沉落地才有来源。
3. **页面重构**：编辑窗瘦成单列（去分区导航与窗内预览），角色页右侧只读预览换成紧凑信息卡，
   「看渲染后的提示词」变成提示词框上的展开项，侧边栏「主页」改名「智能体」。
