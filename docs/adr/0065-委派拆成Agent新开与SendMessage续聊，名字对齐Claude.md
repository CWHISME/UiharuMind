# 委派拆成 Agent 新开与 SendMessage 续聊，名字对齐 Claude

> **状态**：accepted，**已实现**（2026-10-05）。
> 修订 [ADR 0044](0044-委派门面统一为SendMessage，子会话骨架不动.md) 决策 1（命名）与决策 3（删 `ContinueAgent`）；
> 0044 的对话语义（对方能反问、回信以来信交回）与子会话骨架不动。
>
> **补注（2026-10-05）：新开那把改名 `CreateAgent`**——动宾式，与 `SendMessage`、`StartBackgroundTask` 同一套，
> 「这一下是新开」写在名字上。下文的实验数据是叫 `Agent` 时测的，`CreateAgent` 的触发率待测；退化就改回 `Agent`。
> 同时回信末尾加了一句附言「接着谈同类主题就用 `SendMessage`，to 填 xxxx」，针对 Agnes 不续聊（见下）。

## 背景

`## 委派` 纪律段按 [ADR 0054](0054-工具纪律段按需写，不再挂了工具就得有.md) 并进工具说明后，冒烟（`subagent-continue`，Agnes-2.5-Flash 无思考）里
用户说「先找个人审一下」，模型 **0/3** 委派，全部自己读完 README 给结论；旧版（中文纪律段在）是 3/3。
`subagent-interject` 里模型翻了工作区里的 ADR 0044 才「发现」自己能用 `SendMessage`。

中文纪律段里那句「找个人聊」恰好接住了用户的说法；去掉之后，一把叫 `SendMessage`、描述写「给某个人发消息」的英文工具，
弱模型联系不到「委派」上。训练语料里这件事的写法是 Claude Code 的 `Agent`（新开）+ `SendMessage`（续聊）。

另一处老毛病同源：`to` 一个参数兼三义——留空新开、人名点名、编号续聊。弱模型往里编名字
（`reviewer`、`default`、`open-source-readme-reviewer`），该续聊时又留空新开。

## 决定

1. **拆成两把，名字对齐 Claude Code。**
   - `CreateAgent(prompt, subagent_type?, role?, model?)`：只管新开（起初叫 `Agent`，见文首补注）。
   - `SendMessage(to, message)`：只管给开过的那位续发，对方还在干活时就是插话。`to` 只收 `[sub-session: …]` 编号，
     留空或认不出时报错，把「用 `Agent` 新开」与「聊过的人」两条路一起给。
2. **`subagent_type` 只在挂了子角色时才进 schema。** 没挂就没有可填名字的地方，编名字无从发生。
   名单列在它的参数说明里（装配时拼，0044 决策 5 补注的口径不变）。
3. **「同一主题回到同一个人」写在 `Agent` 的描述里**，指名 `SendMessage`：该续不续的那一刻，模型正打算调的是 `Agent`。
4. **对话语义保留。** 描述明说「they can ask you back」；回信、插话、回执的形态（ADR 0062）不变。
5. **`model` 保留。** 本机 190 次委派调用里一次没用过，但它只在用户点名模型时才用（ADR 0031），也没被误用过。
   不加 Claude 那个必填的 `description` 短标签：与 `role` 重叠，`role` 已经是会话标题。
6. **与群发言同名不冲突。** 群发言工具也叫 `SendMessage`（ADR 0060 有意为之）；群成员装配时去掉委派，两者从不同场，
   「同一次装配工具名不重复」由 `GroupSceneTests` 钉住。
7. **系统提示里没有委派段**（0054 补注）。

## 实验数据（2026-10-05，`subagent-continue` 第一轮「找个人审」是否委派）

| 版本 | Agnes-2.5-Flash 无思考 | sensenova-6.8-flash-lite |
|---|---|---|
| 旧版：中文 `## 委派` 整段 + `SendMessage` | 3/3 | 2/2 |
| 纪律段并入英文 `SendMessage` 说明 | 0/3 | — |
| 一行中文钩子 + `SendMessage` | 3/3 | 3/3 |
| 改名 `Agent` + sub-agent 措辞，无钩子 | 3/3 | 3/3 |

钩子与改名都补回了触发；选改名，是因为它不靠系统提示，且与其它工具（`Read`/`Edit`/`Shell`…）同一套训练里见惯的命名。
第二轮「再审一下」各版参差（Agnes 多半自己审，sensenova 有续有新开）——那句话本来就是对主代理说的，测不出续聊，
场景改为「再找人审一下」另测。

改名落地后再对比一轮（第二轮改为「再找人审一下」，两版都带 `session.wait` 竞态修复）：

| 版本 × 模型 | 第一轮委派 | 第二轮回到同一个人 | interject 转给同一个人 |
|---|---|---|---|
| 旧版 × Agnes | 3/3 | 0/3（全新开，2 次往 `to` 编名字） | 1/1 |
| 新版 × Agnes | 2/3 | 0/3（2 新开、1 自己审） | 1/1 |
| 旧版 × sensenova | 3/3 | 3/3 | 1/1 |
| 新版 × sensenova | 3/3 | 3/3 | 1/1 |

改名没有退化；`to` 里编名字的毛病随拆分消失。「回到同一个人」看模型：sensenova 两版都对，Agnes 两版都不续，
`Agent` 描述里那句对它不起作用。新版里见过一次往 `model` 填 `code-review`（当成了 Claude 的 `subagent_type`），回退默认并在回执说明。

## 后果

- 旧会话历史里委派调用的名字是 `SendMessage`（带 `content`/`to`/`role`），与现在的续聊工具同名不同参。
  模型照旧历史调用会撞上参数校验或编号报错，一次后自行改正；不为此挂别名——多注册一把工具，前缀与工具清单都变。
- 界面按工具名认委派卡的图标，`Agent` 与 `SendMessage` 都认（群发言本来也叫 `SendMessage`，同用机器人图标）。
- 「查看过程」入口靠结果末行 `[sub-session: …]` 认，与工具名无关，不受影响。

## 待议：要不要给模型一把 `TaskStop`

Claude Code 用一把 `TaskStop(id)` 同时停后台命令与子代理；我们两样都没有给模型（界面上有停止按钮）。
2026-10-05 议过，**先不做**，理由与再议的条件都记在这：

- **后台任务**：模型会自己停——「推进计划」那个单聊里一晚上停了 4 次，都是 `ps aux | grep … | xargs kill`。
  杀掉任务的根进程后登记表照常收尾，「已结束，退出码 143」很快送回，模型也认得出是自己杀的。能用。
  代价是每次多一两次调用找 pid，以及**按模式杀可能误伤**——另一个会话或另一个实例（ADR 0064）挂着同样命令时会被一并杀掉。
- **子代理**：见过要叫停的情况，但很少。
- **再议的条件**：出现一次误杀，或子代理叫停的需求多起来。
- **做的时候别忘了**：现有的停止口径默认是用户叫停——子代理回信写「The USER stopped them on purpose… ask what they want next」，
  后台任务报告写「被用户叫停」。模型自己叫停时要换措辞，否则它会转头去问用户；叫停后的回信写进历史但不唤醒。
