# 会话形态存储，智能体卡可开成普通对话

需求：**普通对话也要能选智能体卡，纯聊时不背工具。** 用户原话：「主要目的就是想用在纯聊天的
场景，此时装备一大堆工具其实是浪费」。

现状下这件事做不到干净：会话不存类型，归普通对话还是智能体由角色 `IsAgent` 实时派生
（[0043](0043-角色档位从四档枚举改为一轴派生.md)），而 `IsAgent` 是「开不开 harness」的身份轴。
于是「用白露纯聊」只有两条路：整卡降级成普通角色（放弃她在 agent 侧的全部用途），或做一张分身
聊天卡（人格双份、必然漂移）。两个都不可接受。本 ADR 新增一根**会话形态**轴，把「卡身份」与
「这个会话怎么跑」解耦。

## 决策

1. **会话形态成为会话的存储属性。** `EConversationType`（普通对话 `Chat` / 智能体 `Agent`）
   升级为 `ChatSession` / `ChatSessionMeta` 上的字段，不再由角色身份实时派生。建会话时
   **默认跟角色身份**，但从普通对话侧发起可以显式定为 `Chat` 形态。
2. **agent 卡可开成普通对话会话 = 走 prompt-only 管线。** `AgentAssembler` 的分叉判据从
   「角色身份」改成「会话形态」：`Chat` 形态一律 `BuildPromptOnlyOptions`——无 harness、
   无工具、无工作区、不注入基座 / 工作循环 / 工具纪律 / 委派，右栏就是会话详情。
   **卡身份（`IsAgent`）不变**：这张卡还是智能体，只是这个会话没让它开 harness。
3. **普通群收人放开。** `GroupChatSessions.CanJoin` 统一为「所有非用户卡都能进」：
   agent 卡进普通群 = 以 `Chat` 形态加入，不写文件。
   [0042](0042-对话页合并为单页，类型由左栏切换器唯一决定.md)「已定」里普通群只收普通角色的
   理由（agent 进去没工作区，文件没处落）在 `Chat` 形态下失效；群类型回归它唯一机械含义：
   **绑不绑工作区**。智能体群可混装的现状不变（agent 成员跑 agent 形态、普通成员跑 chat 形态）。
4. **存量会话定格。** 迁移时把每个现有会话按「当前派生结果」写入形态。之后身份翻转
   （普通 → 智能体）**不再挪已有会话**，只改变新会话的默认形态——这推翻了
   [0043](0043-角色档位从四档枚举改为一轴派生.md)「已定」里「翻开关，名下老会话整体换侧」的行为。
   群里成员会话同样定格：建群时定形态，成员身份翻转不影响它。
5. **单向锁改数 agent 形态会话。** 智能体 → 普通角色翻转的解锁条件从「名下没有任何会话」放宽为
   「名下没有 agent 形态会话」——白露名下全是纯聊会话时，她仍可翻成普通角色；翻完她的纯聊会话
   本来就在普通对话侧，不受影响。

## 取舍

- **为什么不是卡身份降级（M1）。** 改动近乎为零，但让这批卡永远失去 agent 侧用途。项目已在
  agent 侧投了基座层、群聊骨架、Hello World（初春 / 一方通行那批就是 agent 卡）；让白露退化成
  聊天卡，等于把已经铺好的路砍掉一半。
- **为什么不是分身卡（M1.5）。** 同文本两份必然漂移（改一处忘另一处）。AGENTS.md 第一条就是
  「优先复用已有代码或组件，避免重复造轮子」。
- **为什么纯聊走 prompt-only，而不是「空工具 agent」。** [0043](0043-角色档位从四档枚举改为一轴派生.md)
  与术语表都写明了：工具全关的智能体仍然是智能体——**贵的是 harness**（工作循环、工具纪律、
  委派名单、基座段都要模型消化，还带工作目录与权限档）。用户要省的就是这一层，空工具省不到。
- **为什么让会话存形态，而不是继续派生。** 派生做不到「同一张卡两种跑法」——同一角色（白露）
  的两个会话要能一个 `Chat` 一个 `Agent`，会话就必须自己记得。这是给
  [0043](0043-角色档位从四档枚举改为一轴派生.md)「会话不另存类型」的**有条件的让步**：
  身份仍是角色自己的属性（编辑页开关、徽章、筛选不变），但会话的运行方式从身份解耦。
- **为什么不给「混合群」留概念。** 智能体群天然混装，普通群放开后也混装——「群里成员形态不同」
  是常态不是一类新群，不进术语表。

## 代价（明说）

- **约十处「读角色身份 → 读会话形态」**：`ChatSession` / `ChatSessionMeta` 新字段 + 存量迁移；
  `SessionManager.IsAgentSide` / `IsChatSide`；`AgentAssembler` 两处分叉 + `MemoryContextProvider`；
  `ConversationSessionBinder.CreateAsync` 开场白判据；`ConversationViewModel.IsAgentSession` 及
  派生可见性（模式切换、任务清单、发送身份、发图退路）；角色选择器过滤（Chat 形态 → 所有非用户卡，
  Agent 形态 → agent 卡）；`InheritCharacterId` 继承判据；基座 / 工作循环 / 工具纪律注入判据
  （`AgentInstructionsComposer`）；`GroupChatSessions.CanJoin`；单向锁判据。
- **行为变化**：身份翻转不再挪已有会话（今天会挪）。编辑页与文案若提到「翻完老会话换侧」，要同步改口。
- **半逆转 0043 的一条不变量**：归类从「实时派生、不会过期」变成「创建时定格」。归档一致性靠
  创建时刻的正确性，不再靠恒真推导——用测试钉住创建与迁移两头即可。

## 已定（不另开决策）

- **单聊入口**：空态右栏预选 + 会话中换角色都放开（同一道谓词）；角色库页「开始对话」对 agent 卡
  保持现状（跳智能体侧 = 默认 agent 形态），以后有需要再给形态选项。
- **换角色的形态边界**：Chat 形态会话内换角色只换人格、形态不变；Agent 形态会话仍只收 agent 卡
  （反向维持现状禁止——普通卡没有 harness 可开，选了只会得到「没工具却带扮演脚手架」的东西）。
- **开场白**：agent 卡没有 FirstGreeting，Chat 形态下也不补——与内置内容卡现状一致。

## 未决

- **角色库页要不要给形态选项**（「以普通对话开始」vs「以智能体开始」）。等有需要再开。
