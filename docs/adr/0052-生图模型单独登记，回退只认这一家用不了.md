# 生图模型单独登记，回退只认「这一家用不了」

agent 经 `GenerateImage` 出图、改图，背后是一张**单独登记**的生图模型列表：列表顺序即回退顺序，全局一份。
每个生图模型带一个**接口格式**，由对应适配器翻成各家的请求。适配器接口是我们自己的窄接口，
失败结构化分三类，**只有第一类换家**。

## 为什么不放进对话模型那张表

最初的设想是给 `BaseRemoteModelConfig` 加一根类型轴（对话 / 生图），复用添加窗口与服务商预设。否决：

1. **消费者太多。** `LlmManager.CacheModelDictionary` 是对话模型的统一命名空间——顶栏下拉、会话模型面板、
   子代理模型、快捷工具默认模型、`GetPreferredModelName`、ADR 0031 的 `model` 参数都从它取。混进去每处都得记得滤，
   漏一处就是一个选得中、跑起来才报错的模型。分开放，对话侧一行都不必知道生图存在。
2. **字段不合身。** `ContextLength` / `ThinkingMode` / `IsVision` / `GetExtraParams` 对生图无意义；
   生图要的分辨率档、水印、超时，对话侧也没有。
3. **传输本就不能共用。** `OpenAICompatibleHttpHandler` 把每个请求的 URI 改写成 chat-completions 端点、
   往 POST 正文注入思考参数，生图请求无论如何要另一条 HTTP 通道。

代价是同一家的密钥填两次。新建时从同家对话模型**复制**预填，不引用——引用会让删掉对话模型时生图模型莫名坏掉。
界面放模型区而非 Agent 设置页：这是一张模型清单，以后独立的生图窗口也要用它；Agent 设置页只留一行摘要与跳转。
排序用上移 / 下移而不是拖拽。列表改动一律**写时复制**（`ImageModelSettingConfig.ReplaceModels`）：
出图在线程池上遍历旧的那份，就地改会撞上「集合已修改」。

## 为什么回退不照搬 websearch

websearch 出错、空结果都换家：搜索结果近乎可互换，单次又便宜。生图两条都不成立——内容审核拒了换一家多半也拒，
白扣一次；一次 60–360 秒，超时再换家等待翻倍，而头一家可能已经扣费。于是分三类：

| 类 | 例 | 处理 |
|---|---|---|
| 这一家现在用不了 | 没配、熔断、连不上、5xx（504 除外）、429、401/402/403、404、408 | 换下一个 |
| 请求本身不行 | 内容审核、参数非法、输入图读不了 | 停下交还模型，它能换说法重试 |
| 可能已扣费 | 超时、504、响应半截断开 | 停下并如实说明 |

分不清的一律归「请求本身不行」：SenseNova 的 `400 failed_precondition_error` 同时覆盖「引擎不可用」与
「安全检查未通过」——宁可少换家，不重复扣费。带输入图时只走支持编辑的模型，不支持的跳过、不算失败。
熔断复用 `WebServiceCircuit`，只记第一类。真回退了在工具结果里说出来（跳过了谁、为什么），同 ADR 0031。

## 为什么适配器不直接用 `IImageGenerator`

M.E.AI 10.10.0 的 `IImageGenerator` 标着 `[Experimental("MEAI001")]`；尺寸只有像素 `Size`，没有比例与分辨率档
（Agnes 的档位 + 比例只能塞 `AdditionalProperties`）；失败只能抛异常。三类失败是这套设计的核心契约
（失败结构化，同 ADR 0017），不压在实验性接口加异常上。

起初打算让 OpenAI 标准格式在适配器内部借 `AsIImageGenerator`，落地时也放弃了：反编译 10.10.0 的
`OpenAIImageGenerator`，编辑时**只取第一张输入图**（`OriginalImages.FirstOrDefault()`），参考图被静默丢掉；
还固定带上 `response_format`，而 gpt-image 会拒收这个参数。三种格式于是共用一个模板方法基类
（`ImageDialectBase`：发送、超时、失败分类、响应解析），各自只回答「请求长什么样」。

## 工具与输入

一个 `GenerateImage(prompt, images?, aspectRatio?)`：带 `images` 即编辑（第 1 张为主图，至多 5 张），不带即生成；
比例取各家交集。分辨率档、水印、提示词润色是生图模型的设置，不给模型——决定价钱的事模型无从判断；
不给 `model` 参数，理由同 ADR 0031。

角色上的能力开关（`EnableImageGeneration`）**默认关**：每次出图都可能花钱，内置卡里只有 OP-01 在卡上打开。
开着也要配了生图模型才挂工具，所以没配的用户不付工具定义的钱。

不审批：`AnalyzeImage` 同样把本地图发给远程，WebSearch 同样是付费外呼，三者都没包审批，口径一致；写入只落 `$DRAFT`。

agent 形态会话的图片附件一律附带路径引用：此前视觉模型只拿到内联字节，没法把用户发来的图交给编辑。
普通对话不加——没有工具，路径只是噪音。

## 产出

返回即下载进会话房间：SenseNova 的 URL 24 小时失效，历史里的链接要长期有效（同 ADR 0026）。
工具卡直接显示缩略图；工具结果只给模型名、`$DRAFT` 路径与 `revised_prompt`，**不交回图片本身**——
Chat Completions 的 tool 消息只收文本，`Microsoft.Extensions.AI.OpenAI` 把非字符串结果整个 JSON 序列化，
交回 `DataContent` 等于塞给模型一串 base64。迭代靠把上一张的路径当 `images[0]` 再调一次。

## 已知代价

- **agent 看不到自己画了什么**，好坏靠用户说。真要看见得让图片以 user 消息进上下文（`ViewImage`），
  牵动历史边界、折叠与渲染，留作后续单独设计。（已定：发送时投影，见 ADR 0053）
- 用量 v1 只记日志，不进 `TurnUsageLedger`，免得污染「报告占用」。
- Agnes 文档要求 `response_format` 放 `extra_body`，那是 Python SDK 的写法，直发 HTTP 该怎么放不清楚——
  干脆不传，取缺省的 URL 再下载。2026-10-01 实测生成与编辑都通（编辑时比例按主图推出、尺寸不变）。
- SenseNova 一张 2K PNG 约 5MB，全进会话房间；房间随会话删，没有单独的配额。
