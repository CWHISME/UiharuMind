# agent 产物按工作区组织，落地 Data/Agent/Workspaces

产出目录从「按会话平铺的 python 输出」改成「按工作区 × 会话组织的 agent 产物之家」，
根目录从 `Data/Agent/Outputs` 迁到 `Data/Agent/Workspaces`，同时接管临时脚本与下载物，
并补上空目录的清扫。

## 背景

现状：`Data/Agent/Outputs/{会话标题}_{会话id前8位}` 按会话分目录，目录在**装配时**由
`EnsureDirectory` 创建，全仓没有任何空目录清扫（ADR 0019 明写「不自动清理」）——于是
「建了但没写」的空目录越积越多。目录名带标题，会话改名就会再建一个新目录、旧目录留在原地。
临时脚本与下载物没有归属：全局共享的 `Cache/Scratch` 跨会话互相覆盖是已知欠账
（ADR 0019），而「项目数据目录」并不存在。

## 决策

1. **根目录改名 `Data/Agent/Workspaces`**（`AppPaths.Data.AgentWorkspaces`）。语义从
   「python 产出」升级为「agent 一切产物的家」。
2. **按工作区 × 会话两级组织**：
   - 绑了工作区的会话 → `<工作区段>/<会话id8>/`；
   - 没绑工作区的会话 → `NoWorkspace/<会话id8>/`；
   - 能力预览（无会话，本就不跑轮次）→ 退化到 `Workspaces/` 根，不单独建目录。
3. **房间名只认 id8，不带标题**。会话改名既不搬目录也不换目录；装配指纹里少一项标题因子，
   改名不再触发重建。
4. **一个工作区一个家，家里按会话分房间**，防止跨会话同名文件（`result.csv`、`plot.png`）
   静默覆盖——产出路径写进历史，覆盖就是历史坏图。子会话沿用派活者的房间，不另建。
5. **空目录治理**：装配时照建（提示词里要有确定路径）；**启动时、任何会话装配之前清扫**
   `Workspaces/` 与旧 `Outputs/` 的空目录；删除会话时整间删除并顺带收掉空的工作区家目录。
   边界：只删空目录，不碰任何有内容的数据——这是对 ADR 0019「不自动清理」的补丁而不是
   推翻，那条针对的是「不删用户数据」。
6. **工作区段命名复用 `FileMemoryLayout.GetWorkspaceSegment`**（`{目录名}_{全路径哈希}`），
   提成共享 helper，两处同构。
7. **旧 `Data/Agent/Outputs` 不迁移**：历史 `file://` 链接指着它们，一搬就是坏图；
   沿用 ADR 0013「旧布局就地废弃」先例。有内容的留下，空的被第 5 条收掉。
8. **临时脚本与下载物先进 Data（房间）**，不单独分流到 Cache；真出现大件再单独指 Cache。

## 为什么

- **为什么不按会话平铺**：会话太多太碎 → 空目录泛滥；同工作区的多个会话在磁盘上互不相认；
  脚本与产出隔着 Data/Cache 两棵树。
- **为什么「都放一块」而不是 Data/Cache 性质分层**：用户要的就是好组织——一个工作区一个家。
  产物普遍很小，混装的风险低于多一个目录多一层路径记忆的负担。代价明说：真出现大下载物时，
  用户清理要另想办法；届时再指 Cache 不迟。
- **为什么不用 `Projects` 命名、不做工作区本地 `.claude/` 层**：`Workspaces` 钉死
  「工作区是路径字符串、不是实体」；产物写进历史，放进用户仓库内目录（`.uiharumind/`）
  被挪一下/删一下就是坏图，且「本地配置层」`AGENTS.md` 已存在。
- **为什么 `NoWorkspace` 而不是 Empty / Scratch**：`Empty` 语义反了（桶不空）；
  `Scratch` 与 `Cache/Scratch` 撞名且性质相反——一个删了坏历史、一个删了没事。

## 取舍

- **房间名失去自解释性**：id8 只有维护者认得，用户看磁盘认不出是哪个会话。换取的是
  「改名不搬、不重复目录、不触发重建」。目录名曾经带标题，那是空目录与重名覆盖问题的源头之一。
- **删除遍历深一层**：`AgentOutputLayout.DeleteAll` 从扫 `Outputs/` 一层变成扫
  `Workspaces/` 两层（工作区 → 房间），成本很小。
- **会话中途改工作区会换房间**：旧房间留着（历史链接仍有效），这与「改名不搬」同一原则。
