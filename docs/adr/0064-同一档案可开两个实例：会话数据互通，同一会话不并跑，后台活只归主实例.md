# 同一档案可开两个实例：会话数据互通，同一会话不并跑，后台活只归主实例

> **状态**：accepted，**已实现**（2026-10-05）。

## 背景

调试版常与日常用的那份同时开着、指向同一个 `~/.uiharu`。想要的是：调试版里新建或推进的会话，日常那份也看得到。

此前两份同开是「能起来、但互相踩」：

- `index.json` 各自读进内存、各自整份写回，谁后写谁赢，对方新建的会话从索引里消失；
- 驻留卸载（ADR 0036）卸历史前会先把内存那份写回盘。另一份推进过这个会话，这一写就把它的新消息抹掉——不用两边同时跑，只要一边内存里留着旧历史；
- 后起的实例启动时 `ForceClearAllProcesses` 杀掉不是自己起的 llama-server，先起那份的本地模型断掉；
- 定时任务后端构造时把遗留的「运行中」改成失败并整份写回，再开一个轮询循环：后起的会把先起那份正在跑的任务标成失败，两边还会各跑一次。

## 决定

**一、盘上的历史是权威，内存那份记着「我最后见到的盘」**

- 每个会话记一份历史文件（`.history.jsonl`）的盘上指纹（修改时间 + 长度），读入与自己写完时更新。
  盘上指纹对不上，就是别的实例写过：这份内存是**旧的**。不往会话里加字段，单实例零额外开销。
- **只看历史，不看会话头**。起初看的是会话头，实机当场踩到：另一边只是打开看看，切走时写了一次草稿（会话头），
  这边正等子代理交回的主会话就被判旧——报告写不进、唤醒轮被拒，整个会话停住。
  会话头的字段（标题、草稿、用量、设置）因此按「后写的赢」，与设置、记忆同一口径。
- 卸载前的回写与盘上一字不差就不写：原样重写也会换指纹，正跑着这个会话的那一侧就会被判旧。
- 写盘前一律过同一道拦截，三种情形都不写（记一条警告）：本体已旧；本体已**退役**
  （被盘上新读的那份顶替时恰好有人攥着它，或会话已删、收尾中的子代理还攥着它）；这个会话正在别的实例里跑（租约被别人持着，见四）。
  问「能不能跑」时先看租约再看旧不旧：对方正跑着时这边多半也已判旧，该提示的是「等那边结束」。
  宁可丢这一侧的改动，也不拿旧内容覆盖别人的新内容。
- 旧会话没被界面钉住、也没在跑：直接从缓存摘掉，下次取用重新读盘（换实例；ADR 0036 「本体实例永不换」只对**被持有**的会话成立，钉住就是持有的声明）。
  钉住着的（正打开着）：**不刷新视图**，只标旧；切走再切回来时重新读盘。这是刻意取的最省一档：只有两边恰好在看同一个会话、对方又在推进时才有感，刷新整张会话视图（ADR 0041，无虚拟化）的代价留到用户自己切换时付。
- 「切回来」要绕过视图缓存：页面会留着上次选中那个会话的视图（`LastSelectedSessionIds`），切回去命中的是同一个钉着旧本体的视图。
  所以切换时发现缓存视图的会话已旧、且它没在跑，就弃掉重建，新视图读到盘上那份。

**二、索引是缓存，合并着写**

- 写 `index.json` 前若发现盘上那份不是自己上次写的，先读进来合并：盘上有、自己没有的，会话头文件还在就收下（别人新建的）；
  自己有、盘上没有的，会话头文件已不在就丢掉（别人删的）；两边都有取 `UpdatedAt` 较新的。
- 读-并-写整段持跨进程文件锁（`Sessions/index.lock`）。单实例时盘上那份永远是自己写的，不多读一次。
- 写索引持着进程内的会话锁，等跨进程锁最多 2 秒：只在两个实例恰好同时写索引时才等得到，接受。
- 等锁超过 2 秒就不等了、照写并记警告：索引只是缓存，被覆盖掉的条目会在下一次写索引的合并里回来，会话头文件也还在，
  比卡住会话的保存划算。

**三、发现别人的改动：监视会话头文件**

- 监视 `Sessions/*.meta.json` 的增、改、删，攒 300ms 一批处理；指纹与自己记的一致就是自己写的，跳过。
- 处理只动内存：更新元数据、摘掉或标旧本体，然后发 `OnSessionsChangedExternally`，列表据此全量对帐。不为别人的改动写索引。

**四、同一个会话同一时刻只在一个实例里跑**

- 一轮开跑前取会话租约：`run/leases/<会话>.lock`，独占打开持到这一轮（含交接压缩）结束。进程死了系统自动放锁，不会有残留卡死。
- 会话名下还有未了结的后台工作（后台子代理、后台任务，即 `PendingWork`）时，所在实例**也一直持着租约**，了结了才放。
  派出子代理之后主会话这一轮就结束了，但它还在等报告：只在轮内持租约的话，另一边能在这段空档里开跑，
  一写盘这边就判旧，报告写不进、唤醒轮被拒（实机踩到）。
- 装载时的崩溃修复（给末尾没结果的工具调用补「已中断」）只在租约**没被别人持着**时做：
  别人正跑着的会话，末尾那些调用的结果还在路上，不是残局。对方真崩了，系统放锁，下次装载照常修。
- 手动 `/compact` 与开跑同一道认领；删除**全程持着**租约（只查不占的话，查完到删完之间对方开跑，它的追加会把刚删的历史文件又建出来），
  别的实例正跑着的会话删不了（界面提示）。级联要删的子会话、群成员先整体查一遍，有一个在别处跑就整个不删，免得删到一半留下孤儿。
- 「探一下租约」也是真的取一下锁，对方恰好此刻取锁会撞上：取锁与探测都容 100ms 再下结论。
- 驱动里被拒发的是单独的 `Refused` 通知，带原因（`ETurnBlock`），措辞由界面本地化；无头调用方（定时任务、群成员轮）按失败算。
- 开跑前也核一次指纹：旧会话不开跑。两种都以本轮失败收口，**不写任何东西**——失败路径的「补齐中断」此时写盘就是覆盖。
- 界面在**发送前**先问一次（只问不占）：不能跑就不画气泡，字还给输入框，弹一条提示。
  画了气泡再在驱动里被拒是不行的：用户消息没进历史，会话一空闲，尾部对帐按历史重放，气泡连同错误一起被抹掉，看上去就是点了没反应（实机踩到）。
  驱动里那道拒绝留着，兜无头轮次与「问过之后、开跑之前」那一瞬的竞态。

**五、主实例：先起的那个**

- 启动时独占打开 `run/primary.lock`，拿到的是主实例，持到进程结束。
  认领要早于任何按「是不是主实例」分叉的组件（调度后端在构造时就分叉）；认领前就有人问过，记一条警告。
- 定时任务只归主实例：非主实例的后端只读入任务清单，不做启动修正、不写盘、不开轮询；
  从模型那边新建任务直接报错，界面上的取消/立即执行/改权限是空操作并记一条警告。
- 主实例死了，非主实例**不接管**（不轮询抢锁）。重启谁，谁就是新的主实例。
- 残留 llama-server 的清理只在**没有别的活实例**时做（看 `run/instances/` 下的进程标记，与异常退出检测同一份）。

## 不做

- 非主实例的定时任务清单只在启动时读一次，之后主实例新建的任务它看不到（只读、不跑，看不到不出错）。

- 设置、记忆、角色卡等其余数据仍是「后写的赢」。它们改得少，两边同时改的概率低；真要互通再单独做。
- 打开着的会话不自动刷新；以后觉得不顺手，可以加一条「已在别处更新，点击刷新」提示，独立的小改动。
- 群聊离席不落盘、由人手动开，天然只在开它的那个实例里跑，不需要归属。

## 已知缺口

- 互通的粒度是**一轮**：会话一轮跑完才落盘，对方正在跑的那一轮（含停在那里等子代理交回）在另一边看不到，
  切进切出读到的都是上一轮落盘时的样子。要看进行中的内容得改成轮内逐段落盘，另议。

- 报告全部交回、后台工作了结的那一刻放锁，到唤醒轮开跑重新取锁之间有毫秒级空档，另一边恰好此刻发送仍能抢到。
- 两边都闲着时，同一毫秒各自改了同一个会话（问过「旧不旧」之后、写盘之前对方写了），仍是后写的赢。
  正在跑的那一侧持着租约，别人的写入已被拦下，所以只剩两边都是手动编辑撞在一起这一种。
- 指纹靠「自己写完立刻取一次」：自己写完与取指纹之间别的实例恰好也写了，会把别人的改动当成自己的，漏报这一次（毫秒级窗口，下一次写盘会对上）。
- 别的实例删掉了这边正打开着的会话：列表里会消失，打开着的视图不会自己关。
