# 群发言一种形态一条通道：智能体只经工具，对话只经回复，化身没有沉默

> **状态**：accepted，**已实现**（2026-10-03）。修订 ADR 0046「群成员不委派，中途发群换成专用工具」与 ADR 0055 决策 4。
> 起因见 [2026-10-02 真实档案五段长跑实测](../perf/2026-10-02-真实档案五段长跑实测.md)段 25「群发言的两种用法混着」。

智能体形态的成员原先有两条发言通道：回复正文说完即进群，`PostToGroup` 在一轮中途先说一句，工具回执还写着「你说完的回复照常进群」。
段 25 翻成员会话，两种别扭的收尾都有：先回「[沉默]」、再调工具说正事、再回「[沉默]」；或者工具说一段、回复再补一段，一轮出两条。
模型没做错——两条并开时，工具说过之后的回复只剩「[沉默]」或补一段两种收法；系统这头则为此攒了一串补丁
（剥正文开头的「[沉默]」、认几种沉默写法）。藏起来或再剥一层只是把隐患盖住，要改的是流程。

## 决策

1. **按成员会话的形态分，一人一条通道**，同一个群里可以混着：

   | | 智能体形态 | 对话形态 |
   |---|---|---|
   | 怎么说话 | 只经群发言工具（`SendMessage`，只收正文），一轮可以说几次 | 回复正文说完即进群（插话拆出的几段各算一条） |
   | 回复正文 | 只留在他自己的会话里，群里看不到 | 就是发言 |
   | 不接话 | 不调工具，直接结束这一轮 | 只回「[沉默]」（它只有这一条通道，不矛盾） |

   形态看会话不看卡（ADR 0050），判据 `GroupSceneSource.PostsThroughTool`，与装配挂不挂群发言工具同一个。
   群发言工具改叫 `SendMessage`（原 `PostToGroup`）：模型对这个名字更熟、更愿意调。与委派工具同名不冲突——群成员装配时去掉了委派，
   一个成员会话里只有这一把；它只收正文、没有收件人，0046 修订防的「收件人填错静默派出子代理」仍然防得住。
2. **场景段、补位提示、工具说明只讲这位成员那一条通道**。智能体形态的场景段不再出现「[沉默]」，对话形态的不出现工具。
   工具回执只说「已发到群」，不再提回复。
3. **违反流程的不替它圆**：工具收到「[沉默]」当场回错，告诉它不接话就别调；剥正文开头「[沉默]」的那段删掉，对话形态回了
   「[沉默] 正文」就照原样进群，看得见才查得出。智能体形态一轮没调工具却留了回复正文，不代发（那就又成了两条通道），记一条调试日志，
   查会话时对得上。
   群发言交给成员时打头一行「来自群聊：」（投递与插话都带，界面不画）：投递在成员会话里是 user 消息，光看「[名字]: 内容」，
   模型会当成用户单独发给他的——冒烟里用户在群里 @ 一位成员，他就在回复里直接作答，群里没人看见。
4. **化身没有「不接话」**。它说的就是用户说的，离席中只有「说一句能推进的话」与「调用结束离席」两种结局（ADR 0055）：
   卡上不再提「[沉默]」，回复写了什么就以用户的名义进群，「[沉默]」也不例外；一个字没写才算没进展。

## 代价

- 每轮开口的智能体成员多一次模型调用（工具回执之后还要收尾一次），按段 25 约多 15%。
- 不常调工具的模型在群里会变哑。上长跑前先冒烟看各模型是否照做；哑了是卡、提示或模型选择的问题，在那里改。
