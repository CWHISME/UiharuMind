# 扩展：不常用的能力与 MCP 收进一对元工具，先查后调、逐条审批

> **状态**：accepted（2026-10-09）。替代 [ADR 0051](0051-MCP送达方式分直挂与按需，默认按需.md) 的元工具与直挂部分、
> [ADR 0075](0075-工具装配收成一处：能力与场合取交集.md) 里浏览器、生图、配音、转写四档的装配；放行矩阵（ADR 0010）多出一类调用。

浏览器、生图、配音、转写这几样，绝大多数会话一次都用不上，却要么常驻工具列表，要么默认关着、用的时候再去角色编辑页开——
用户的原话是「九成情况用不上，用的时候现开关也麻烦」。省多少 token 不是主要问题。
MCP 那边已经是「先查后调」（`McpHelp` / `McpCall`），形状正合适，只是只装 MCP，而且调用在任何权限档下都不审批。

## 决定

**扩展** = 不在工具列表里、先查后调的能力。两把恒定的元工具：

- `ExtensionHelp(extension?, command?)`：不带参数列出全部扩展与此刻的状态；带扩展名列出它的命令；再带命令名给完整参数。
- `ExtensionCall(extension, command, arguments?)`：调用。参数是结构化的对象，不是命令行字符串。

扩展有两类来源，对模型一视同仁：

| 内置扩展 | 命令 |
|---|---|
| `browser` | `snapshot` / `navigate` / `act` / `handoff` |
| `image` | `generate` |
| `audio` | `synthesize`（配音成文件）/ `transcribe`（转写） |

外加每个 MCP server 各是一个扩展，命令就是它的工具。

- **命令就是原来那把工具**：内置扩展的每条命令背后是原有的 `AIFunction`，描述与参数 schema 原样拿来渲染帮助、绑定参数——
  `BrowserTools`、`ImageGenerationTool` 等一行不用改。帮助的渲染与 MCP 共用 `McpHelpFormatter`。
- **名字叫扩展，不叫 SuperTool、ToolHelp**：`Tool` 在模型那边已有固定含义（工具列表、tool call 协议），
  「Super」又暗示更强、更万能，模型可能拿它绕路。要它明白的是「列表之外、先查再用」。
- **两把，不并成一把带 action 的**：帮助永远不审批，单独一把就不必经审批中间件；名字本身也说了先查后调。
- **系统提示里只留一行名字**：「可用扩展：browser、image、audio、unity、github」，按配置算（角色没禁、server 已授权），
  不写状态、不写工具数——跟 ADR 0051 同一个缓存理由。说明与状态都在 `ExtensionHelp()` 的结果里。
  不全删，是怕模型不知道有 unity 这个 server，碰到「改一下场景里的物体」想不到去查。
  **修订（2026-10-14）**：名单每个扩展带一句简介；`ExCall` 描述里那份内置命令速查删掉，内置与 MCP 一律经 `ExHelp` 现查
  （速查与名单是同一份信息的两处，按角色过滤后还对不上；也省掉每轮约 840 字）。MCP 自带「列出工具」不可信那句挪进 `ExHelp` 查 server 的结果里。
  调用形状改为两个参数：`ExCall {name: "browser.snapshot", args: {…}}`，`ExHelp {name?}`（扩展名或扩展名.命令名）。
  全名按第一个点号切开，命令名里可再有点号；MCP server 名里的点号对模型一律写成下划线，切分因此确定，审批与执行同一份解析。
  旧字段名（`extension`、`command`、`arguments`）照认，旧会话也画得出卡；整个调用套进参数对象的写法拆开照做，结果里提醒写法。
- **工具描述写明扩展是动态的**：应用后来才开的 MCP server，下一次调用就连得上（模型主动调用本就无视重连退避）。

### 什么留在工具列表里

识图（`AnalyzeImage`，配 `Read` 用、只在非视觉模型下挂）、朗读（`Speak`，角色扮演里高频、会出声，开关照旧）、
联网、文件、shell、委派、知识库、定时任务都不动。进扩展的标准是**多数会话用不上**，不是「危险」。

## 审批：逐条按风险，完全自动档也问

`ExtensionCall` 一律经审批中间件；档位规则（含完全自动的全放行）**不放行它**，放不放只看这一条调用的风险：

| 风险 | 哪些 | 怎么问 |
|---|---|---|
| 只读 | `browser.snapshot`；MCP 工具自己声明了 `readOnlyHint` 的 | 三档都不问 |
| 一般 | 其余全部 | 三档都问；本会话放行过就不问 |
| 硬问 | `browser.handoff`；`browser.navigate` 去本机或内网地址 | 永远问，本会话放行也不算 |

- **本会话放行按扩展记**：卡片上「本会话允许 browser」，此后这个会话里 browser 的一般命令不再问；
  输入框设置里勾「本会话扩展不再询问」，等于全部扩展。记在会话上（`SessionApprovedExtensions`，随会话存盘），
  与「记住同类命令」的 shell 模式同一个形状：规则每次现取，不用重建装配。
- **卡片上不给框架的「本会话允许」**：框架按工具名记，点一次就把 `ExtensionCall` 整个放行，连接管一起。
  扩展卡上那个按钮换成上面这个按扩展记的。
- **MCP 的 `readOnlyHint` 只在连上以后才知道**：还没连过的 server，第一次调用按一般处理。
  server 按发起会话的工作区认（项目级同名胜出），全局那个声明的只读不能拿来放行项目里另一个同名 server。
- **审批与执行认同一个命令名**：内置命令只认命令名与原工具名（不分大小写），不做模糊匹配。
  执行若比审批宽容（`hand_off` 落到 `handoff`），审批按「没这条命令」判成一般级，硬问就被绕过了。
- **别的放行规则不碰扩展调用**：记忆目录那条只认写工具——它是「或」语义，调用里顺手带一个指向记忆目录的
  `filePath` 就能整条放过（审查时发现，shell 同样受影响，一并修了）。
- **群**：成员跟群走（与权限档同一口径），群视图里勾的对全体成员生效；成员视图里不出这个勾选框。
- **定时运行**：一般命令放行，它派出的子代理同样放行。任务是用户自己排的，无人值守时问了也没人点；硬问的照旧拒。
- **离席**：一般命令照旧交给化身判断，硬问的直接拒（没人能接手浏览器、不替用户开本机地址）。
- **子代理**：完全自动档原本一律自动批嵌套审批，扩展调用除外——与主会话完全自动档同一口径；
  本会话放行沿用派活者那个会话的。

这改了 ADR 0051 的一句话：从前 MCP 调用**任何档位都不审批**，现在只读的不问、其余要问。
重度用 Unity MCP 的会话，第一次点「本会话允许 unity」或在输入框里勾一次即可。

## 能力开关

浏览器、生图、配音、转写四个 `Enable*` 开关退役，换成一份**禁用名单** `DisabledExtensions`，与原来的
`DisabledMcpServers` 合成一份：默认全给，角色要禁哪个扩展就把名字写进去。

- 理由：默认关是因为「常驻工具列表」和「会替用户做事、会花钱」，前者没了，后者由逐条审批兜住。
- 旧档案里的 `DisabledMcpServers` 读进来并进新名单；四个旧开关的值丢弃（关着的扩展现在默认可用，但每次要批）。
- 内置扩展缺前提时照样列出，状态写明原因（「没配生图模型」「这个角色没设声音」），模型据此告诉用户去哪儿配。

## MCP 直挂退役

送达方式只剩按需，`EMcpMountMode`、预连（`WarmupAsync`、`ETurnBusy.ConnectingMcp`）、server 自述进系统提示一并删除：

- 不预连之后，直挂 server 第一轮没有工具、中途连上又打破缓存，两头不讨好；而按需本来就是默认，用户主要用云端强模型。
- server 自述照旧在帮助里给（`ExtensionHelp(unity)` 的开头）。
- 设置页去掉送达方式与「自述进系统提示」两项；MCP 侧的修订号只剩配置变化一个来源。

## 界面

界面上内置扩展叫「浏览器 / 生图 / 音频」，模型那边始终是 `browser` 这样的标识。

工具卡与审批卡按**拆开的调用**画：`ExtensionCall` 拆成内层工具名与参数（同一个 CallId）。
内置命令的内层名就是原工具名（`GenerateImage`、`BrowserAct`），所以生图缩略图、配音播放、
浏览器审批卡的人话描述都不用改；旧会话里直接调这些工具的历史也照样显示。MCP 调用的内层名写成 `server.tool`。

## 后果

- 工具列表里固定多两把元工具（约 400 token），少掉四把浏览器、生图、配音、转写的定义。
- 浏览器的工具纪律原来写在四把工具的描述里，现在由 `ExtensionHelp(browser)` 给出；模型要先查一次才会用，
  强模型没问题，本地小模型更吃力（用户主要用云端模型，接受）。
- 冒烟 `browser-basic` 的期望改成经 `ExtensionCall`，且要点掉（或预先勾掉）一般命令的审批。
- 角色编辑页不再给这四档标占用；右栏能力面板的 MCP 分组只剩名单与连接状态。

## 补记（2026-10-10）：内置命令不必先查

「先查后调」实测的代价比预想的大：弱模型不查就照常识猜（`open`、`goto`、`act {ref, text}`），
查的话每用一次浏览器先多三轮整段上下文。`browser-basic` 用 Agnes-2.5-Flash 各跑两轮：

| | 扩展调用 | 参数报错 | 查帮助 |
|---|---|---|---|
| 只靠帮助 | 102 | 17（16.7%） | 13 |
| 描述里带速查 | 65 | 3（4.6%） | 4 |

于是：

- `ExtensionCall` 的描述带一份内置命令速查（签名加一条完整示例，`BuiltinExtensions.CallUsage`）。
  它是常量，缓存前缀照旧稳定；角色禁了的扩展也列着，调用时如实说关了。速查与各工具 schema 的一致性由测试对照。
- `ExtensionHelp(扩展)` 的命令清单每行带参数签名（`act {action, target?, value?}`），MCP 一并受益。
- 参数错时报错给出能照抄的写法：缺了什么、哪些参数名不认识、正确签名；把 `command` 塞进 `arguments` 时指出放错了层。
- 考虑过内置扩展改成命令行字符串（`browser act click e5`）。速查之后剩下的报错它也免不掉
  （漏写命令、漏写 action），还要另付自由文本转义、审批按字符串解析、与 MCP 两套形状并存的代价，没做。

## 补记（2026-11-04）：界内本地页面不再硬问；群壳名单不依赖本体在内存里

两处实测出来的毛病。群里让成员看自己工作区里生成的页面（拾取器、报告）时，「本会话扩展不再询问」勾了也没用：
`navigate` 去 `file://` 一律判硬问，而这类页面正是我们让模型自己写出来给用户看的东西。

- **界内 `file://` 降为一般级**：文件落在工作区、草稿房间、登记且同工作区的 worktree 里时，与「界内写入」
  同一份判据（`ApprovalModeMapper.InScopePredicate`，越界写入、风险分级、离席化身三处共用）；
  界外的本地文件、`data:`、`localhost`/内网 IP、上传、接管照旧硬问。判据经 `ExtensionRiskContext` 递进分级，
  避免「规则放行了、卡上却写着每次都问」。
- **群壳那份名单读索引**：成员继承群壳的放行名单原先只认 `SessionManager.GetLoaded`，而群壳刚启动没加载过、
  跑一阵也可能被冷历史卸载请出内存——那时名单读成空的，勾了等于没勾。现在本体不在内存就读 `ChatSessionMeta`
  里那份冗余（`ToMeta` 顺带写），纯内存读，不进审批热路径的读盘。

## 补记（2026-11-04 之二）：「扩展不再询问」放到本机服务与界外本地文件

用户的原话是「主动勾选了不询问之后，是否应该放开一点？每次都问真的很烦」。于是把原先一律硬问的两类改成一档新风险：

| 风险 | 哪些 | 怎么问 |
|---|---|---|
| 只认全局那一格（`SessionWideOnly`） | `navigate` 去本机服务（`localhost`、回环、`*.local`）与工作区之外的 `file://` | 勾「本会话扩展不再询问」才放行；点单个扩展的「本会话允许」不算 |
| 硬问（`AlwaysAsk`） | 接管、上传、内网段（`10/172.16~31/192.168/169.254/100.64~127`）、`data:` 等非 http(s) | 永远问 |

- **为什么只认全局那一格**：读遍本机（任意本地文件、本机管理后台）是用户该亲手拍板的事，
  点一次「本会话允许 browser」的本意是「普通网页操作别烦我」，不该顺带把 `.ssh` 与路由器后台一起放开。
- **无人在场一律拒**：定时运行（`ExtensionRiskContext.Unattended`）与离席化身都把这一档当硬问处理——
  那时没人能去勾，默认放行比停下来更糟。同意必须是人亲手勾的那一下。
- **界内页面仍是一般级**：工作区/草稿房间里的 `file://`（我们自己生成的拾取器、报告）不用勾也不会问。
- **看得见的窗口期**：勾着时工具行的设置图标变红（与权限档同一套 Tag 配色），悬停说明放开了什么、点开可关掉；
  审批卡上这类调用另给一句「要勾全局那一格才放行，这里的按钮只顶这一次」。

代价说在前面：勾选到去勾之间，模型能读本机任意文件、能操作本机端口上的服务；已经读进上下文的内容收不回来。
所以它是本会话级、可见、一键可关的开关，而不是一个藏在设置页里的默认值。

### 评审后的收口（同日）

外部评审（Crouton Alpha）在合入前挑出两处会真的越权放行，已修：

- **地址归一化与协议识别**：`BrowserRisk` 先把 Chrome 会自己抹平的东西抹平（Tab/换行、反斜杠当斜杠），
  再按「已知协议前缀 + `://` + 盘符路径」判 `file:`；`http:/host`、`http:host` 这类少斜杠写法归一成标准形。
  补协议这份逻辑与执行层 `BrowserTools.WithScheme` **共用同一函数**（从前两边各写一份，
  模型写 `fi\nle:///C:/secret` 时 .NET 建不出 Uri、判成公网，Chrome 却剥掉换行打开本地文件）。
  建不出来的地址一律按非 http(s) 恒问——判成公网是 fail-open。
- **子代理继承无人值守**：`AgentBuildProfile.Unattended` 把「派活者是定时运行」也算进去，
  并经 `SubAgentAssemblyInput` 透传到子代理的 `BuildRules`。此前定时会话派出的子代理会拿着 `[*]`
  把本机服务与界外文件静默放行。

其余按「已知取舍」保留并写进注释：界内判定是字面比（不解析软链，与写入侧同一取舍）、
索引名单在多实例共享档案时不做文件戳比对（索引本就是缓存）、`InScopePredicate` 入口统一
`GetFullPath` 后再比（防「..」跳出工作区）。

### 第二轮评审后的收口（同日）

- **离席也要现问**：`ExtensionRiskContext.Unattended` 从装配期布尔改成动态来源（`IsUnattended`），
  由 `AgentBuildProfile.UnattendedSource` 现问三件事：定时运行、被定时派出的子代理、`GroupAwayController`
  接上的离席探针（`AwayProbe`）。此前离席时用户勾过的 `*` 会在规则层直接放行本机/界外文件，
  化身的「一律拒」根本轮不到判。
- **斜杠写法**：`https:///host`、`http:/host`、`http:host`、协议相对的 `//host` 都归一成标准形再判
  （此前落到「建不出来 → 恒问」，安全但过问）。
- **带 query 的界内页面**：界内判定先截 `?#` 再规范化，`file:///…/x.html?from=1` 不再被误判界外。
  进程内的 `LocalPath` 会把 query 带进路径，`GetFullPath` 遇到 Windows 上非法的 `?` 就抛。
- **索引补 `IsScheduledRun`**：派活者被释放后，续跑的子代理仍能从索引认出「被定时派出」。
- **目标模式**仍是「一律同意」的产品取舍（`GoalModeApproval` 的注释一直这么写），
  这次把危险确认文案点名为「本机服务、工作区外的本地文件或内网地址」，与实现对齐。

### 唤醒轮的口径（终轮评审拍板）

`UnattendedSource` 覆盖定时、被定时派出、群离席，**刻意不含唤醒轮**（`SendMessage` 投递目标会话的那一轮）。
唤醒轮是用户主动发起的，且本就为「没开着这个会话也要干活」设计：里面把本机服务/界外文件拒掉，
结果是那一轮什么都干不成（不是「多问一次」）。离席不同——那是用户离开了、会话自己继续跑，
勾选可能是很久以前的事，所以离席照拒。这条差异写在 `AgentBuildProfile.UnattendedSource` 的注释里。
