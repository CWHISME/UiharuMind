# MCP 常驻名单：`mcp` 扩展常驻，`mcp.list` / `mcp.connect` 让模型现连

> **状态**：accepted（2026-10-29）。补 [ADR 0079](0079-扩展：不常用的能力与MCP收进一对元工具，先查后调、逐条审批.md) 的名单口径，
> 不动其审批矩阵。

## 起因

一台**可用**的 MCP server 都没有时（没配、或全被托管/授权挡着），`ExHelp` 的清单里 MCP 整个消失：

```
扩展（用 ExHelp 传 `name` 查看其命令）：
- browser（内置）：…
- desktop（内置）：…
…
MCP server 是用户运行的应用；离线的那台可能稍后会再起来，所以再查一次，别以为它没了。
```

名单只剩内置那几行，末尾却还在讲「离线的那台」——说的东西清单里根本看不见。
模型这时的结论只会是「这台机器没有 MCP」，既不会想到去查，也不会想到「用户那台只是还没起来」。
更硬的一处：`Resolve` 在可用的 server 为 0 时返回 `McpToolSet.Empty`，桥接为 `null`，
**这一路彻底没有 MCP**——用户后来才打开的 server，在这次装配里连按名查都查不到。

## 决定

1. **`mcp` 成为常驻内置扩展**（`Catalog` 第七个可见项）。它不代理任何 server，只回答
   「配了什么、各自被哪道闸挡着、现在要连哪一台」。系统提示名单与 `ExHelp` 清单里因此始终有它一行。
2. **两条命令，都只读**：
   - `mcp.list`：**全部**已配置的 server（含托管没开、待授权、被本角色禁用、此刻离线），
     每台一句话说明；一台都没配时如实说「还没配，去设置 → MCP 加」。
   - `mcp.connect {server}`：无视重连退避当场连一次，回报命令数或失败原因。
3. **名单与桥接分开**：`McpToolSet.Servers` 仍只装这一轮**可用**的（系统提示那行因此仍随配置而非连接变化，
   缓存前缀照旧稳定——ADR 0051/0079 同一个理由）；`Resolve` 改成**恒给桥接**，
   于是一台可用的都没有时，模型仍能 `mcp.list` 看配置、`mcp.connect` 现连。
4. **三层闸门一处判定**：`McpServerFinder.BlockedBy`（托管 → 角色 → 授权）同时供
   `IsUsable`、`Find`、新的 `IMcpServerHost.Overview` 使用——「能不能用」与「为什么不能用」不会各算一遍。
5. **状态文案共用一处**：`McpHelpFormatter.DescribeServer`，`ExHelp` 清单与 `mcp.list` 说的是同一件事。

## 取舍

- **为什么不把不可用的 server 写进系统提示名单**：连接起落、授权、托管开关都是**运行期**信息，
  写进提示就等于每变一次重建一次缓存前缀（ADR 0079 已经从「工具列表」上付过一次这个代价）。
  常驻的只有 `mcp` 这一行（常量），状态一律现查。
- **为什么 `mcp.connect` 不问审批**：它做的正是 `ExHelp(名字)` 本来就会做的事（建立连接、取回命令清单），
  而后者按只读放行。为一件一模一样的事弹卡，只会教模型改走 `ExHelp` 绕开它——那种审批挡不住任何东西。
  真正会「拉起一个进程」的两道闸在 `McpManager` 里：托管开关是用户在设置里的决定，授权是用户点过的那一次，
  扩展碰不到它们，`Refusal` 也只把用户指回设置页。
- **为什么是扩展而不是第三把元工具**：ADR 0079 的两把元工具定义恒定，是缓存前缀的一部分；
  多一把就得重新掂量审批中间件与工具卡的下钻形状。扩展这条路只是「加一个类 + 登记一行」。
- **为什么列出「托管没开」的**：ADR 0008 特意把它从**能力面板**里藏起来（那是全局资源设置，
  不该在每个会话里重看一遍）。模型这里要的恰恰是这条——它得说得出「配了，但你在设置里关着」，
  否则只能回一句「没有这个扩展」。界面那一侧的取舍不变。
- **名字占位**：`mcp` 从此是保留名。用户真有一台同名的 server 时，按既有撞名规则被隐藏并在清单里说明
  （原来 `browser`、`image` 就是这样）；改名即可恢复。

## 后果

- 系统提示的扩展段多一行（约 20 token，常量），`ExHelp` 清单多一行；用不上的 server 仍不进提示。
- 新增两条内置命令名（`mcp.list`、`mcp.connect`）与一个可见扩展，角色能力面板多一个「MCP」勾选项——
  关掉它，模型就只能按名碰运气，`ExHelp` 清单末尾那句 `mcp.connect` 的提示也一并消失。
- `Resolve` 恒给桥接：一台 server 都没配时，扩展元工具也挂着（此前要靠内置扩展撑住）。
  代价是「角色把内置扩展全禁掉」时，`ExHelp`/`ExCall` 仍会挂上——与「有 server 时」原本的口径一致。
- 冒烟与集成测试：`McpOnDemandIntegrationTests` 里「唯一 server 被禁用 → 名单空、也没有桥接」
  改成「名单空、桥接在」，并断言 `ExHelp` 说出了「都用不上」。

## 本期不做

- `mcp.add` / `mcp.remove`：改的是用户配置（还可能要密钥与环境变量），交给设置页，不交给模型。
- `mcp.disconnect`：空闲回收已经在做，多一条命令只是多一个能把自己弄坏的口子。
- 把不可用的 server 也写进系统提示：见上面第一条取舍。
