# 子代理默认后台化，报告由唤醒轮交回

**取代 [ADR 0022](0022-子代理仍同步阻塞，原理由已失效.md)。** 那篇自称「带保质期」，
正文结构是「为什么仍然不做」——门槛跨过之后整篇论证反过来了，就地修订会把它改得面目全非。
它的「本期预付的四笔钱」与「解锁门槛是轮次归属」正是本篇的起点，两篇连起来才是完整的因果链，
所以保留全文、只标 superseded。

决定：

1. `RunSubAgent` / `RunReadOnlySubAgent` / `ContinueSubAgent` **一律立即返回**
   「已派出，子会话 id = X，**尚无任何结果**」，主代理那一轮继续往下干。
2. 子代理跑完，报告作为一条带注记的真消息落进父会话历史（ADR 0021 那条后续报告通道）。
3. 落盘之后**自动起一轮不带用户消息的轮次**（下称**唤醒轮**）让主代理处理它。
4. 没有 `background` 参数，没有同步档——**不给模型这个判断题**。
5. 「忙」拆成两个词：`IsGenerating`（轮次在跑）不动，新增「未了结的工作」只驱动指示器。
6. 连续无用户参与的唤醒轮封顶 12 轮，用户说一句话即清零。

## 门槛是怎么跨过去的

ADR 0022 把门槛定在**轮次归属**，不是并发能力：「非阻塞意味着主代理那一轮结束并存档了，
却还挂着一个未了结的副作用」。答案有两半，都不用撑开「一轮」：

**副作用其实当场就了结了。** 框架不存在「挂起的工具结果」——`FunctionInvokingChatClient`
调完函数在同一次循环迭代里 `await` 完并立刻产出 `FunctionResultContent`，
搜遍 Pending / Deferred / LongRunning / Resumable 零命中。所以「立即返回一句已派出」
不是折中，是**唯一可行形态**；而它本身就是一条**合法且已配对**的工具结果。
派出的那一轮因此照常自洽地封存，历史里不留孤儿——那正是最近几个 commit 反复在修的东西。

**报告不属于那一轮，它属于新的一轮。** 这也不是我们发明的：框架自己对「结果晚一步到」
的唯一答案就是**结束这一次调用、下一次带着对得上的内容重新进来**（审批流的
`ToolApprovalRequestContent` → `ToolApprovalResponseContent` 就是这个形状，
`ShouldTerminateLoopBasedOnHandleableFunctions` 让外层循环直接 `break`，
什么都不调、也不在进程内 await 等外部信号）。

于是 ADR 0021 那句「交回之后不起新轮」在本篇被推翻，但推翻的只是结论不是理由：
它当初拒绝的是**用户手动交回后**擅自起轮（「那一轮的用户消息是什么」答不出）。
本篇给出的答案是**承认有一类轮次没有用户消息**，并把它立成词，而不是伪造一条用户消息去凑。
伪造那条路（以 user 身份写「[系统] 子代理已完成」）被否掉，理由是本仓对「用户说过什么」
一向较真——插话都专门做了 `UserMessageContent(isInterjection)` 去区分。

## 为什么是默认，而不是 ADR 0022 设想的「逃生舱」

0022 倾向「默认仍阻塞，用户或模型可主动转后台」，并反对模型自主，理由是
「本仓对本地模型的自主判断有实证的低评价」。**这条理由与它自己宣告作废的「本地单 slot」
是同一个前提**（主力已转远程），不能只挑一条翻案，故一并作废。

但真正定案的是数据，不是推理。本机 `Data/Sessions/` 下 172 个会话中有 44 个真实子会话，
按首尾时间戳实测：

| 区间 | 个数 |
|---|---|
| <10s | 5（含 2 个 0 消息的废弃会话） |
| 10–30s | 6 |
| 30–60s | 4 |
| 1–5min | 10 |
| 5–30min | 17 |
| >30min | 2 |

中位数 **185 秒**，均值 7.9 分钟，最长 62.7 分钟。

曾认真考虑过**乐观同步**（N 秒内跑完就直接返回结果，超过才转后台，模型零判断）。
60 秒窗口只接得住 **34%**，代价是对另外 66% 每次都要先白等满 60 秒——而那 60 秒
正是要消灭的东西；把 N 缩到 10 秒只剩 11% 命中，撑不起「工具有两种返回形态」
那套机械（提示词讲两种、模型读两种、测试覆盖两条路）。**故不做。**

阻塞的真实代价 0022 已经记过，这里只补一条实证：`MessageInjectingChatClient`
只在每次模型请求**之前**排空注入队列，且响应里一有可执行的函数调用就立即返回、不排空。
所以「主代理一边等子代理一边听用户说话」在框架层**做不到**——那个聋只能靠真正的非阻塞解决。
反过来，工具一返回、主代理发下一次请求时队列就排空了：**不聋是后台化白送的副产品**，
不需要为它单独做任何事。

## 取舍

- **落盘与唤醒是两件事。** 报告落盘**不可失败**；唤醒可以排队（父会话正忙时）、可以合并
  （排队期间到达的多份报告一轮交完）、最坏可以降级为「不唤醒，模型下一轮自然读到」。
  把它们缠成一件事，就会出现「唤醒没成功于是结论丢了」。**报告不走注入队列**，
  理由同 ADR 0021（不落盘、拿不到 `MessageInjector` 时静默返回 false）。
- **自激封顶 12 轮。** 主代理被唤醒 → 唤醒轮里又派后台子代理 → 又被唤醒，用户一句话没说
  它自己转起来了。中位 3 分钟意味着这是主路径而非边界情况。封顶形状学
  `MaxDeniedApprovalRounds`：只在**连续无用户参与**的唤醒轮上累加，用户说一句即清零——
  按总次数掐会把老老实实跑的长链路掐死。合并唤醒让轮数回到与委派批次同量级，12 很宽。
- **跨轮次的顺序依赖只写提示词。** 同步档下「查 A → 据 A 改 B」天然安全（拿到 A 才派 B），
  后台化之后这条安全性没了。`AgentToolPrompts.ConcurrentCalls` 当初只管「同一条回复内」，
  现在扩到「后台委派未回时不要动依赖它的东西」。**不做 `WaitForSubAgent` 工具**——
  一个会阻塞的 Wait 等于把刚拆掉的墙原地砌回来，还把判断题还给了模型。
- **返回串必须写死「尚无任何结果，不要据此作答」。** 中位 3 分钟意味着用户**必然**先看到
  一条过场话，而模型最容易犯的错是把「已派出」读成「已完成」然后编一份结论。
  这是纯后台最贵的一笔隐性成本，配套纪律段与 `ConcurrentCalls` 同位。
- **后台档的嵌套审批跳过派活者回应口。** `NestedApprovalResolver` 原本「先递给派活者
  这一轮的回应口，接不住才登记」，而后台化之后派活者那一轮已结束，**第一条路恒定接不通**，
  直接登记 `SubSessionApprovalRegistry` 即可。
- **`NestedApprovalTimeout` 维持 5 分钟。** 曾提议加长到 30 分钟（后台档下用户未必在看），
  否决。**代价要认清**：它使那条审批通知变成**承重的**——5 分钟没人点就按拒绝收口、
  报告里点名哪些活没干成，通知弹不出来等于那次委派白跑。通知因此不是锦上添花。
- **审批通知统一，父会话那一路一并补上。** 现状是父会话自己那一轮要审批时也只有对话流里
  那张卡片，切走就不知道。「需要用户行动」这条判据与它发生在哪一层无关，做成两套会出现
  「嵌套的有提示、父的没有」这种解释不清的不对称。唯一漏斗是 `TurnDriver.BeginApprovalWait`。
  **`IMessageService` 在 App 项目而 `SubAgentTool` 在 Core**，故走 `LaunchContext` 回调注入，
  无人值守传空——同 ADR 0021「为什么 Core 建 driver，不是 UI」的处理。
- **进程退出时启动扫描收口。** 父会话那一轮早已自洽（「已派出」那条结果配对落盘了），
  但那条**永远没有下文**。启动时找出「后台派出、报告未交回」的子会话，往父会话落一条
  「因退出而中止」。不做自动续跑：用户回来时未必还想要那件事。
- **`MaxIterations` 与 `Timeout` 数值不动，改为表现上加强提示。** 这两个值的论证
  （「交互场景下用户看得见、也按得动停止」）被后台化削弱了——有人在应用里 ≠ 有人在看
  这个子代理。但把判据改成「此刻有没有界面在观察」会让上限随开不开窗口而变
  （开着窗跑 24 小时、关掉窗 30 分钟被掐），这种「行为取决于你有没有在看」最难解释也最难复现。
  于是选择不动数值，靠右栏面板的警告态与一条 `Warning` 通知把长跑的委派顶到用户眼前。

## 「忙」为什么必须拆成两个词

`IsGenerating` 现在同时决定三件事：出不出停止按钮、用户打的字**走插话还是走发送**、忙碌指示。
后台子代理在跑时主代理那一轮**已经结束，没有轮次可插**。若直接让父会话 `IsGenerating = true`
去显示忙碌，用户打的字会进注入队列，**一直等到下一轮（可能几分钟后的唤醒轮）才被消费**——
按了发送、界面说「等待插话」、然后什么都不发生。这比不显示忙碌更糟，
而且它正是 ADR 0021 记过的那个坑的镜像。

所以新增的「未了结的工作」**只驱动指示器**，输入框行为完全不受它影响。
判定是「本会话 + 它名下未交回的后台子会话，有没有在跑的」，`SessionRunRegistry` 已有的
按 sessionId 忙碌判定够用。

## 「有子代理在等审批」放在哪儿

这条提醒是承重的（5 分钟到期按拒绝收口），所以它的载体经过一次返工，结论值得写下来。

**从工具卡上删掉了。** 那句提示原先挂在父会话流里那张委派卡上（ADR 0021 说「界面按
`SubSessionId` 取状态即可」）。它的注释写着「**跑圈照转**，另挂这一句」——整个设计前提是
卡片还在转圈。后台化之后工具当场返回，卡片一秒内变成「成功」，提示挂在一张看起来已经干完的
卡上；更要命的是跑了几十轮之后那张卡早滚没了。**报警必须找得到人，而会滚走的东西做不到。**

改放四处，各补一块覆盖面：

| 载体 | 补的是 | 缺的是 |
|---|---|---|
| 输入区上方的**常驻横幅** | 位置固定、可点直达、没有在等的就整条消失 | 要在这一页 |
| 右栏「子代理」面板（琥珀点 + 页签计数） | 全会话索引，卡片滚走了也找得到 | 要在智能体页、右栏得开着 |
| 左栏会话行的等待标记 | 跨会话可见（子会话不进左栏，父会话这一行是唯一出口） | 左栏可折叠、点不进去 |
| **菜单栏图标角标**（琥珀＝等审批，蓝＝在跑） | 用户**切走之后**唯一还看得见的 | 说不出是哪个会话 |

浮窗通知仍在，时长从 5 秒提到 20 秒（`IMessageService.ShowNotification` 新增可选时长参数）：
「要你动手」与「出错了」不是一档，后者读完就完了，前者读完还得去点。

**卡片上保留的是另一档**：「已派出 / 结果待回」（ADR 0021 预付的那一档）。它不是报警，
是那张卡**说的是不是实话**——没有它，卡片在派出一秒后显示「成功」，而子代理还要跑三分钟。
两者职责不同，不要因为都长在卡上就一起删。

菜单栏角标是**运行时画的**（底图 + 右下角一个点），不出三份图标资源：换图就要同步维护三份，
而这里要的只是一个点。画不出来时退化成只改 tooltip——菜单栏少个角标，远不如应用起不来严重。

对着 Avalonia 源码核过三件事，其中一件是**顺手修掉的既有隐患**：

- 运行时换图标可行且不闪：`TrayIcon.Icon` 是 `StyledProperty`，每次变化都推给 native
  （`TrayIcon.cs:209-216`），而 macOS 侧只替换 `NSImage`、**从不重建 `NSStatusItem`**
  （`trayicon.mm` 的 `SetIcon`）。`ToolTipText` 也是真的落到 `NSStatusBarButton.toolTip`。
- 图标会被强制缩到 `floor(菜单字号 × 1.333)` ≈ 18px 高，所以角标按**比例**画，且不能画小。
- ⚠️ **`_isTemplateIcon` 在 native 侧是个没有初始化的成员**（`trayicon.h` 声明，
  `AvnTrayIcon()` 不赋值），而每次 `SetIcon` 都执行 `[image setTemplate: _isTemplateIcon]`。
  于是「图标是彩色还是被抹成单色剪影」在没人显式设过时**是不确定的**——这在本篇之前就成立，
  只是没人踩到。现在显式钉住 `MacOSProperties.IsTemplateIcon = false`：底图是彩色 logo，
  开 template 会把它整个抹成剪影，角标的颜色也一起没了。

## 已知代价

- **短任务多一轮往返**：实测 11% 的委派在 10 秒内结束，它们现在也要走「已派出 → 唤醒轮」
  两轮，中间那句过场话没有信息量。这是为 66% 的长委派付的税。
- **报告到达时上下文可能已经变了**（用户在那期间跟主代理聊了别的）。报告文案要说清
  「这是你几轮之前派出的那件事」，否则主代理会把它接到错的话头上。
- **新增一个持久化状态位**（「后台派出、报告未交回」，落在 `ChatSessionMeta`）。
  它同时是启动扫描与唤醒排队的依据，躲不掉。
- **子会话在盘上仍然只增不减**（ADR 0021 已认的欠账，本期不还；后台化会让它增得更快）。
- **`ShowNotification` 是应用内浮窗**，最多同时 6 条、非系统级。上面那张表里的四处载体
  把「你在应用里」这一格补满了，但**用户离开电脑**那一格仍然空着——菜单栏角标要人回头看一眼
  才算数。配合 5 分钟的审批超时，这是本篇最薄的一环，下一期第一个该补的仍是系统级通知。

## 本期不做

- **按 token / 成本封顶**（ADR 0022 就想做）：更贴近真实风险，但要接 `TurnUsageLedger`
  做新判定，而本期已经动了 `TurnDriver` 的签名和一个新持久化状态位。
- **子会话清理**：随时可以单独补，不影响本篇任何结构。
- **系统级通知**：见上。
