# 完全自动档子代理的嵌套审批自动放行

**状态**：已实现（随 0032 配套修改提交）

## 结论

子代理轮次里的嵌套审批，在**有人值守（attended）且会话权限档为完全自动（FullAuto）**时自动放行：
不登记、不等人、不弹提示，审批响应当场给「放行」；同时认账三件事——理由送模型、
`Log.Warning` 记日志、报告里点名（最多列 5 个）动了哪些调用。

无人值守（attended=false）与低档位（AutoEdit/ReadOnly）**不放**，照旧等人点选或按原规则拒绝。

## 为什么

### 那一声「问」在子会话窗口，问的人却看着父会话

嵌套审批的登记处是子会话（`SessionApprovalRegistry`），卡片弹在子会话窗口。子代理默认
后台化（ADR 0025）之后，派活者那一轮早已结束，盯着主会话的用户看不到那张卡——「越界写入
完全自动档也要问一次」（ADR 0010）在子代理场景下变成：**问了，但没人能答**。5 分钟超时按
拒绝收口，那次委派整轮白跑（实机：派到工作区外的活全灭）。

### 放行不等于放开安全，是换一套记账

- **ask → deny**（现状）：用户不知情，活白跑，孤儿工具调用留盘（审批被拒的调用在 MFA
  审批闸上不执行、永远没有结果，见配套的拒绝闭环补写）。
- **ask → allow + 点名**（本次）：动作真做了，但理由送模型、警告进日志、路径点名进报告，
  用户在主会话就能看到「自动放行了哪些越界写入」。

### 为什么无人值守不放

没人看着时静默改盘比停下来更糟。无人值守的上游（定时任务等）本来就按拒绝收口，保持原样。

## 边界与守门

- 判据是会话权限档本身（`ShouldAutoApproveNestedApprovals(attended, modeIndex)`），
  不是某个工具、某个路径——放行语义与权限档一致，不会出现「这个工具放、那个不放」的漂移。
- 父会话（主代理）自己的越界写入**不受影响**：那声「问」弹在父会话窗口，用户看得见，仍要问。
- 自动放行只发生在**审批卡无人可看**的嵌套路径；有守门测试钉住四象限：
  attended×FullAuto 放；unattended×FullAuto 不放；attended×AutoEdit/ReadOnly 不放。

## 配套：拒绝也闭环

自动放行只覆盖「放」的出口；「拒」的出口（无人值守、低档位、用户明确拒绝、超时收口）同样
会留孤儿 tool_call（调用发出、审批不通过、函数不执行、结果永不出现——严格服务端下一条请求
直接 400）。配套在 `TurnDriver` 审批回环处对**明确被拒**的调用补写 `[cancelled]` 结果
（`ToolCallCancellation.CloseDeniedCalls`），历史里调用必有配对结果，卡片显示「被拒」而不是
「没有结果」。

## 涉及的代码

- `SubAgentTool.ShouldAutoApproveNestedApprovals`（判据唯一定义处）
- `NestedApprovalResolver.Create` 的 `autoApprove`/`onAutoApproved` 参数

## 修订：被拒的调用不补写（2026-09-27）

「配套：拒绝也闭环」的前提不成立：「被拒调用永远没有结果」不对。MEAI（10.10 实测）拿到拒绝回应后，
在下一轮开头就地写一条 `Tool call invocation rejected. <原因>` 工具结果，并随本轮落盘
（盘上有 10 个会话只有这条、没有我们的补写）。`CloseDeniedCalls` 再补一条 `[cancelled]`，
就成了同一调用两条结果，严格服务端（实机：群成员被无头审批拒掉 Shell 后，这位成员的会话每次请求都 400）
一律报 `InvalidParameter`。

- 撤掉 `CloseDeniedCalls`。回应口一条回应都不给时（无头审批被拒到上限就收口）没有下一轮，
  那批调用在 `TurnDriver` 里按「审批未决」收（`CloseUnansweredAtTail`）。
- 读会话时 `ToolCallCancellation.DropDuplicateResults` 去掉同一调用的多余结果（有真结果留真结果），
  已经坏掉的会话下次打开就能接着发。
- 框架写的被拒结果也算「没跑」（`IsCancelled` 认它的开头），卡片显示与从前的补写一致。
