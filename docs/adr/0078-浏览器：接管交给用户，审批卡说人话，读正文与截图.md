# 浏览器：接管交给用户，审批卡说人话，读正文与截图

> **状态**：accepted，已实现（2026-10-09）。接着 [ADR 0074](0074-浏览器工具：PuppeteerSharp驱动本机Chrome，快照带编号.md) 的「已知代价」往下做。
> 同日浏览器收进了扩展（[ADR 0079](0079-扩展：不常用的能力与MCP收进一对元工具，先查后调、逐条审批.md)）：四把工具成了 `browser` 扩展的四条命令，经 `ExtensionCall` 调；
> 接管与本机地址的「贯穿三档」改由扩展的风险分级表达（硬问），审批卡上的「本会话允许」改为按扩展记。

原型能用，但有四处不顺：碰到登录、验证码只能卡住；审批卡写的是 `{"action":"click","target":"e21"}`，没人判断得了该不该批；
读长页面贵（维基那次 10.5 万 token，花在被链接切碎的 `- text:` 行上）；画布类页面、要看布局时没有眼睛。

## 接管：单独一把工具，借审批卡等用户

`BrowserHandoff(task)`：模型写明要用户做什么（「登录 GitHub」），卡片换成「请你接手浏览器」，
按钮是「切到浏览器 / 完成了，继续 / 取消」。用户在窗口里做完点「完成了」，工具才执行：重拍整页交回。

- **借审批流程，不另开一条「等用户」的通道**。审批卡本就会停住这一轮，会在子会话窗口和群的待审批条里出现，
  会话列表里会提示「等你处理」，点停止时按拒绝收口，无人值守时一律拒绝——接管要的正是这些。
- **单独一把工具，不做成 `BrowserAct` 的一个动作**：框架的「本会话允许」按工具名记住，
  点过一次 `BrowserAct` 的「本会话允许」，以后的接管就不等人直接过了。接管卡也不给这个按钮。
- **贯穿三档**（`BrowserRisk`）：完全自动档也等用户点。离席时化身一律拒，没人能接手；
  打开本机、内网地址同样留给本人，与越界写入同一个口径。
- **子代理也等**：完全自动档的子代理原本一律自动批嵌套审批（卡只弹在子会话窗口，问了也白问），接管例外——
  自动批了等于替用户谎称「做完了」。打开本机、内网地址仍随越界写入一起让步。
  嵌套审批 5 分钟、群待审批条 10 分钟没人点按拒绝收口，接管也受这两个时限；主会话一直等。
- **切到浏览器只在用户点按钮时做，不自动抢焦点**。`Page.bringToFront` 在 macOS 上会把 Chrome 整个切到前台（实测）；
  会话还没开过页面就先开一个空白窗口——接管可能正是「请你先登录 X」。
- **点了「切到浏览器」，这个标签页就交给用户了，直到智能体再动它**：闲置回收放宽到两小时
  （登录、过二次验证常超过十分钟）；页面弹窗不再替用户点——「确认支付？」得由他自己点，浏览器原样弹出（实测）。
  用户没理的弹窗，智能体再动手前关掉并注明，不然页面一直卡着。
- 无窗口运行（冒烟）时没有窗口可接，交回时如实说没人能接手。

## 密码只经用户的手

- 快照里密码框标 `[password]`，值只给圆点。无障碍树上它只是 textbox，判断看 DOM（并发着问，一个一两毫秒）：
  `type=password`；头一次认出就在元素上做记号，点了「显示密码」切成明文照样认得；
  `autocomplete` 写着 password、或用 CSS 把字遮成圆点的明文框也算。Chrome 本就给圆点，快照器再遮一道，换引擎也不漏长度。
- 往密码框 `fill`、或按会打出字的键，工具当场拒，让模型改用接管；**用户在对话里给过密码也不代填**。
  会不会打字按白名单判，认不出的一律当会打：Puppeteer 的键码名（`KeyA`、`Digit1`）照样打出字来。
  带目标的按键另看一眼真正的焦点（目标是段文字、聚焦不了时，字会打进原来的焦点），焦点顺着 Shadow DOM 与同源 iframe 往里找。
  回车、Tab、清空不算输入密码，放行。
- 堵不住、也不值得堵的：contenteditable、跨源 iframe 与封闭 Shadow DOM 里的焦点。
- **做成工具拒，不做成「贯穿三档要审批」**：审批拦不住点过「本会话允许」的会话；而且密码一旦交给模型，
  就进了历史、发给了服务商。代价是给了测试账号也得自己输一次——登录态存在专用档案里，一个站点一次。

## 审批卡说人话

- 按发起会话最近一份快照把编号翻回元素（`BrowserTools.Preview`，不碰页面），卡上写「点击按钮『提交订单』」，
  第二行是所在网页（只给站点：防钓鱼看的就是这一截）。密码只给圆点；翻不回（编号过期）就照模型写的原样摆，不猜。
- 卡片在请求到达时生成，那一刻的快照就是模型下这一步时看到的那份。会话 id 从转录器、群待审批条往卡片传。
  晚开的子会话窗口补画**早已决出**的卡时退回原始参数：页面早往下走了，按此刻的快照翻会说错。
- 只有浏览器调用才碰浏览器宿主，别的卡不把那套（闲置回收的计时器）拉起来。
- 原有的风险没变：同一条回复里并行的几步，前一步重拍后页面结构变了，编号可能跟着变，卡上翻的还是旧编号。
  卡上的说法是生成时的语言，中途切换语言不跟着变（与收起后那一行同一个口径）。

## 读正文：`view: "text"`

- `BrowserSnapshot` 与 `BrowserNavigate` 加 `view`：`outline`（默认，带编号）或 `text`（正文 Markdown，不编号）。
  抽取复用 WebFetch 那一套（`DirectPageReader.ExtractTextAsync` 加站点清理器），读的是脚本跑完之后的 DOM。
  正文主体先认 `main`；没有时只有一篇 `article` 就是它，好几篇（时间线、论坛）取共同的祖先，不能只给第一条；
  `article` 自己的 `header`（标题、署名）留下，`main` 里的不留——那常是整页的标题栏，维基的语言列表就在里面。
  这几条 WebFetch 一并受益。
- 正文超出预算时内联开头，提示**先指 `find`**，再说全文落在哪、从第几行续读；不附尾巴（多是参考文献、页脚）。
  通用的「用 Read 接着读」实测把模型引去整份读进来，一次多花六万 token。
- 交给模型前再收一道（`ReadableText`）：链接只留字（维基的链接是百分号编码的相对地址，一个几十字节），
  空白行并成段落间距，代码原样（`d[k](x)` 不是链接）。要跟链接就按字点——`BrowserAct` 认看得见的文字。
- `BrowserNavigate` 要正文时也先拍了大纲：按字点链接、审批卡翻编号都查这一份，不拍就会落到上一页的树上。
- 实测同一页 outline 对 text：Hacker News 首页 10.3KB 对 3.9KB，GitHub 文档 15.3KB 对 8.4KB；
  维基角色列表 267KB 对 235KB，大头是正文本身，但正文是成段的：`find` 命中的是整段
  （「白井黑子……大能力者（Level 4），能力是空间移动……常盘台中学一年级生」），不再是碎行。
  正文的 `find` 不捎带前后段，一段本身就是上下文。

## 截图：`view: "screenshot"`

- 截看得见的那一屏（JPEG：视网膜屏上是两倍像素，PNG 动辄几 MB），存进草稿目录的 `browser/`，结果只给路径和怎么看：
  视觉模型 `Read` 它（ADR 0073 的投影），非视觉模型交给 `AnalyzeImage`。看不了图的装配不提供：工具说明和参数说明里都不出现。
- 不把图直接塞进工具结果：投影只认 `Read` 的路径参数（ADR 0073），为截图另开一套口径不值得多省的那一步。

## 后果

- 冒烟 `browser-basic` 第三项把密码直接给了模型：它照填用户名，密码被拒后改走接管。无窗口下交回时页面没变，
  模型如实报告需要用户登录。修完后三项输入约 2 万、1.9 万、3.6 万 token，维基那项从 10.5 万降下来（走了正文视图）。
- 工具从三把变成四把，每轮多一份工具定义；读正文、截图都挂在原有工具的参数上，没再加工具。
