# 工具装配收成一处：能力与场合取交集

> **状态**：accepted，已实现（2026-10-08）。续 [ADR 0066](0066-主子代理装配统一与人格锚段.md)：那一篇把主子代理的提示词基座收成一处，这一篇收工具。
> 浏览器、生图、配音、转写四档后来收进了扩展（[ADR 0079](0079-扩展：不常用的能力与MCP收进一对元工具，先查后调、逐条审批.md)），场合表里只剩一档 `Extensions`。

主代理的工具在 `AgentAssembler.BuildTools` 里挂，子代理的在 `SubAgentAssembly.BuildSubAgentOptions` 里另写一份。
两份名单各自维护，差异不是设计而是漂移：主代理新加的浏览器（ADR 0074）、配音、转写，子代理那份一个都没跟上，
而没有任何地方会报错。

决定：**工具装配只有一个入口 `AgentToolsetBuilder`**，主代理、群成员、化身、定时运行、子代理都从这里拿工具。

- **挂上的工具 = 角色卡 ∩ 派活者（仅子代理）∩ 场合**，全是交集。前两项早已是 `AgentToolConfig.Intersect`；
  「场合」是新的一项，写在场合表 `AgentToolScopes` 里（`EAgentToolScope`）。
- 每档工具怎么造只写一次。各条装配路径只负责把**资源**备齐（`AgentToolResources`：路径口径、shell、MCP 快照、
  模型能不能看图、配没配生图模型、浏览器宿主……），挂不挂由装配器按能力与场合决定，它不碰单例。

## 为什么不是「子代理与主代理取交集」就够

有几样工具与「会什么」无关，取决于「在哪儿」：派活者开着委派，子代理照样不能再往下派（递归）；
群成员要有群发言、化身要有结束离席；跑完要叫醒发起者的后台任务，叫不醒的场合不能给。
这些从前散在 `BuildTools` 的 if 里（`IsGroupMember`、`IsGroupAvatar`、`IsScheduledRun`）和子代理的名单里，
现在都是场合表里的一行，于是仍然是交集：

| 场合 | 比主代理多 | 比主代理少 | 后台任务 |
|---|---|---|---|
| 主代理 | — | — | 有 |
| 群成员 | 群发言 | 朗读（用户看的是群壳） | 有 |
| 化身 | 结束离席 | — | 无（群叫不醒它） |
| 定时运行 | — | — | 无（跑完就收工） |
| 子代理 | — | 委派、技能、定时任务、知识库、朗读 | 无 |
| 旧探索档 | — | 只剩只读的文件工具 | 无 |

子代理少的那几档沿用原有理由：它拿的是一份任务书，不需要自己装载技能、排定时任务，
也没有会话挂载的知识库可检索；用户看的是派活的那个会话，它开口念没人听。

## 顺带修正的两处

1. **能力可不可用，按模型事实与生效能力判，不再看子会话那张卡。** 从前识图、生图「可不可挂」取自子会话自己的角色卡，
   而匿名子代理那张身份卡的 Tools 是默认值（生图默认关）——派活者开着生图，匿名子代理也永远拿不到，
   与「能力直接取派活者那一份」的设计相悖。现在装配器只收两个模型事实（`ModelSupportsVision`、`ImageModelsConfigured`），开关一律看生效能力。
2. **子代理开放浏览器、配音、转写。** 三者都不依赖有没有人看着、谁来叫醒：浏览器每个子会话各开一个标签页，
   共用同一份档案（登录态相通）；配音、转写落进与派活者共用的草稿目录。
   随之给浏览器宿主加了闲置回收：标签页十分钟没被调用就关，一个不剩时连浏览器一起关（登录态在档案里，下次用到再起）——
   否则每派一次子代理就多留一个标签页。

## 取舍

- **群成员去掉委派仍在 `AgentBuildProfile.EffectiveTools` 里**，没有挪进场合表：它改的是配置本身，
  装配快照与编辑页的占用都读它，挪走要动三处，收益只是少一处 if。场合表里群成员照样允许委派，由配置说了算。
- **装配快照（`AgentAssemblyFacts`）里仍有几条镜像场合的判断**（如群成员不入账朗读）。快照只管「什么变了要重建」，
  多入账一项只会多一次重建，不会挂错工具，不为它再引一层。
- **子代理的工具顺序跟着变了**（现与主代理同序）。工具定义在缓存前缀里，已有子会话续跑时会有一次前缀不命中，只此一次。
- 旧探索档留成场合表的一行，只为重建存量子会话；新派的子代理只有一种，能不能改东西由权限档决定。

## 测试

- `SubAgentTools_FollowTheScopeTable`：场合表允许子代理用的每一档，开着、资源备齐时都真的挂上了，不允许的不多挂；
  表里新允许一档却没给代表工具名，测试直接失败——盯的正是「表里允许了，子代理那边没把资源备齐」。
- `AnonymousSubSession_GetsTheParentsBrowserAndImageGeneration`：走重开子会话的真实装配路径，匿名子代理拿到派活者的生图与浏览器。
