# 0001-无头界面测试与像素对齐测量踩坑记录

## 背景

给群右栏成员列表加「名下在跑后台任务」的蓝点标志（`GroupMembersPanel.axaml` + `GroupMembersViewData` + `GroupShellViewData`，
测试 `GroupMemberBackgroundTaskTests`）。功能完成、测试全绿后，反馈「总感觉没对齐？差了一点点，是不是要加个 tweak」。

本文记录「验证到底差没差、差多少、怎么修」这一路的踩坑，以及一条可复用的像素测量方法。
所有数值来自本机（Apple Silicon / macOS / 深色 UI 主题）无头渲染的真实测量。

## 结论先行

- **布局上圆点与名字行盒中心完全重合（0.00px）**，不是布局 bug。
- 「差一点点」的观感来自字形视觉中心天然偏上（ascent > descent）：行盒居中的 8px 圆点，视觉上比名字字形中心**低约 1.1px**。
- 修复：给圆点挂仓库既有的 `icon-tweak`（`RenderTransform Y=-1`，上移 1px）。修后残余偏差 **+0.14px**（亚像素，不可感知）。
- 视觉模型对 151×46 的小截图**判向不可靠**，一度误判成「点偏上」；实际方向相反（点偏下）。像素级事实只能靠渲染 + 直方图。

## 测量方法（可复用）

目标：圆点中心 vs 名字字形视觉中心（不是行盒中心！）。

1. 无头测试里 `RenderTargetBitmap.Save` 整面板 PNG（1x / 96dpi，坐标与逻辑坐标一致）。
2. 在 C# 里打印控件 `TranslatePoint` 到面板的坐标（**必须等布局跑完**，见坑 2）。
3. Python + PIL 按坐标窗口裁剪分析：
   - 先采样确认背景色（无头渲染的主题可能与预期不同，见坑 4）；
   - 字形像素按「深于背景」阈值聚类，圆点按「B 明显大于 R」聚类；
   - 用 y 直方图确认字形簇的真实范围，**排除整行横线噪声**（见坑 5）；
   - 取两簇 y 质心之差。

实测数据（tweak 前 / 后）：

| 量 | 数值 |
|---|---|
| 名字行盒中心 | 235.89px（面板坐标） |
| 字形质心 | ≈234.36px |
| 圆点质心（tweak 前） | 235.50px → 偏差 **+1.14px（点偏低）** |
| 圆点质心（icon-tweak 后） | 234.50px → 偏差 **+0.14px** |

## 踩坑清单

### 无头界面测试

1. **TextLayout 没有 `Bounds`/`Size`**：本仓 Avalonia 版本的 `TextLayout` 只有 `Height`/`Baseline` 等；想量字形紧贴边界没有现成 API，直接走像素法。
2. **绑定翻转后必须重跑布局**：`IsVisible` 由 false→true 发生在初始布局之后时，控件停留在隐藏态的 `DesiredSize=0×0`、`Bounds=0×0`，`TranslatePoint` 返回垃圾值。改完绑定要再 Pump 一轮（`ForceRenderTimerTick` + `RunJobs` + `UpdateLayout`）。这是本次最大的坑：功能代码没问题，是测量代码在错误的布局态上读数。
3. **子控件单独渲染不完整**：`RenderTargetBitmap.Render(memberButton)` 只出了头像、没出文字与圆点；渲染整面板再按 `TranslatePoint` 坐标裁剪才是可靠路径。
4. **无头主题不一致**：无头测试里按钮渲染成深底深字（背景 `(42,42,64)`、字形 `~(27,31,35)`），面板其余区域却是浅色 `(248,240,217)`。扫字形前必须先采样背景色，别假设主题。
5. **整行横线噪声**：按钮顶边框是一条 39 列全深的横线，会被当成字形像素、把质心往上拽。聚类时先看 y 直方图，去掉只占单行、横向铺满的横线。
6. **角色不注册 → 名字显示 "None"**：`GroupChatSessions.Create` 收的内联 `CharacterData` 不进 `CharacterManager` 字典，`SessionManager.CharacterOf` 回退到 `DefaultCharacter.None`。名字变成 "None" 后字形度量（x-height vs cap-height）与真实名字完全不同。要量真实字形，先把角色塞进 `CharacterManager.CharacterDataDictionary`（public 字段，直接塞避免落盘副作用）。
7. **App.Tests 起不了真实 shell 解析**：`ShellExecutorFactory` 是 Core 的 internal，`InternalsVisibleTo` 只给了 `UiharuMind.Core.Tests`；`Microsoft.Agents.AI.Tools.Shell` 在 Core 里是 `PrivateAssets=compile`，App.Tests 编译期拿不到其类型。App.Tests 起真后台任务只能写死 `/bin/bash`（本仓开发/测试机是 macOS）。
8. **`LocalShellExecutor` 是 `IAsyncDisposable`**，不是 `IDisposable`，别写 `using`。
9. **`GroupSchedule` 的 hostIndex 是位置参数**，没有 `hostIndex:` 命名参数（写命名参数直接编译错）。
10. **`BackgroundTaskRegistry.Stop` 是异步摘除**：Stop 只杀进程树，注册表要等进程退出、输出收完（排水上限 2s）才把任务从 `RunningOf` 摘掉。断言「任务没了」要轮询 `RunningOf`，不能 Stop 后立刻断言——这正是新测试第一次跑挂的原因。
11. **`grep -c` 返回 0 匹配时退出码为 1**，会断掉 `&&` 命令链。shell 里「统计无错误」别用 `&&` 续接下一条。
12. **全量偶发失败一次**：某次全量 739 里挂 1 条（当时未捕获是哪条），紧接着重跑 739/739 通过。疑似与「测试起真进程（`sleep 30`）+ 静态 `BackgroundTaskRegistry` 跨测试残留」有关，仅疑似、未复现；后续验证也没再出现。写这类测试务必在 `Dispose` 里 Stop 任务并删会话。

### 对齐感知

13. **「感觉差一点点」多半是 ~1px 光学偏移，不是布局错**。与仓库既有知识完全吻合：`Assets/Themes/CustomFontStyle.axaml` 里
    `title-tweak` / `title-tweak-sm` / `icon-tweak` 的注释描述的就是同一现象（字形视觉中心偏上，盒居中元素看着低 ~1px）。
    13px 名字文本的实际光学偏移约 1.1px，`icon-tweak` 的 1px 正好够用。
14. **别拿低分辨率截图问视觉模型判向**：151×46 的截图两次判断都不可靠。判方向要么放大 4 倍以上且像素清晰，要么直接上像素直方图。

## 建议

- 以后给文字旁加圆点/图标：先按上面的像素法量一次字形视觉中心，别凭感觉；偏差 ≥1px 用 `icon-tweak`，0.5px 以内不动。
- 无头测试凡是「改绑定后再断言布局/坐标」的，记得再跑一轮 Pump（坑 2）。
- 涉及真实进程的测试：清理时 Stop 任务、删会话，并接受注册表摘除的异步窗口（坑 10）。
