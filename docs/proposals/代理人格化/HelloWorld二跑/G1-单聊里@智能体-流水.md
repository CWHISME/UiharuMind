# HW2·单聊里@智能体

## 流水

### 用户

### 婚后光子

看完了。本小姐的倾向很明确：**升级成群**。拒绝和临时答一句都不对。

先说那两个不行的为什么不行。临时拉进来答一句，那是文档里「角色拉人 = 子代理」的形态——服务于发起者的判断、用完即散、不看上下文。可现在是**用户**拉的，用户的语义是「这个人服务于我」，拉完就想让他坐下。答一句人就没影了，比拒绝还让人火大。所以黑猫同学列的三个选项里，前两个都是把用户拉人按角色拉人来处理，本质是同一个错位。

真正要补的规则在这儿，也就是顺序 6 挂着没定的那个坑：普通单聊没有工作区，被拉的却是智能体——智能体要 harness、要工具、要工作区，塞不进普通群。本小姐的意思是：**升级后的群类型跟着被拉者走**。@ 了智能体，单聊就升级成智能体群，工作区走建群流程补选一个；原来那位普通角色不动，照 ADR 0042 智能体群可混装，不用顺带把他翻成智能体。这样跟「群类型建时选定」不冲突，跟 ADR 0043 的单向锁也不冲突——没人被强行改变身份，只是屋里多坐了一个人。

方向先钉在这儿：用户拉 = 升级成群、类型随被拉者。工作区怎么补选、升级时要不要个确认弹窗，那些细枝末节后面再调。@一方通行 你说说看，尤其是「升级成群」这个形态你认不认——你是最反对把人当临时工具使的。

### 一方通行

升级成群。三个里只有这个站得住——拒绝等于把 §6.6b 规则 5 和它自己的结论一起删了；「临时答一句」是子代理语义，那是角色拉人时的待遇，用户拉的人就该坐下看到历史，答完就走的话，用户想追问还得再造一条升级路径，纯两套机制。

前提就一条：升级后的群按 ADR 0042 是智能体群，普通角色当没工具的成员留下，这条已允许，不卡。

真正没定的不是选哪个，是升级后那条广播——ADR 0049 实时广播会连那个陪聊角色一起拽醒，单聊变三人场。默认只叫醒被 @ 的智能体，原角色沉默到被点名，这条得写进升级规则里。

### 一方通行

升级成群我认，前两个确实是把用户拉人按角色拉人的语义处理了，这个错位说得到位。

但「类型随被拉者」只对了一半。你只说了 @ 智能体那半边；反过来——用户正跟智能体单聊，@ 进来个普通角色——按你的规则走，升级成普通群，不绑工作区，原来那智能体的工作区直接没了。屋里已经坐了个智能体，这个群就只能按智能体群建。

所以钉死的规则不是「随被拉者」，是「看屋里有没有智能体」：存量里有一个、或这轮拉进来一个，就是智能体群。被拉的是谁无所谓，不是他一个人说了算。

### 一方通行

「直接套 ADR 0049 就完事」这句站不住，套出来正好是反的。

升级后屋里就俩成员（陪聊 + 智能体），按 ADR 0049 是**小群**——小群规则是「用户发言全员唤醒」，@ 不看，默认还没主持人。所以直接套 = 三个人一起醒，跟我们刚钉的「原角色沉默」正好相反。

结论收口：广播那条**不是**零成本继承，得在升级规则里显式加「升级群按大群边界，用户 @ 谁只醒谁」，覆盖掉小群默认。方向没变，只是「不用另立新规」这句错了。

### 一方通行

有。第三条只盖了「用户 @ 了人」那半边，没盖「升级后用户说话没 @ 任何人」——这情况还常见得很。

0049 原文里无主持人是要**退回全唤醒**的，直接套 = 陪聊又醒了，刚收的「沉默到被点名」破功；反过来按「只醒被 @ 者」，没人被 @ 就谁也不醒，群直接死。

修法：没 @ 任何人时，默认只醒智能体成员，普通角色照旧沉默。把这条并进第三条，它才闭口。

### 一方通行

上一轮补的半句得并进第三条:**没 @ 时默认醒智能体成员,普通角色照旧沉默**。三条变这样才闭口,否则实现的人按字面写,第一句不带 @ 的话就把群打死了。
