# 顺序 6 · 单聊拉人 / 单聊升级成群 —— 讨论结论草稿（待用户拍板）

> 议题来源：方案 v6 §6.6b + 《落地进度与待议》顺序 6。
> 顺序 6 备注里的「普通单聊里 @ 智能体怎么办，见第二轮会审 Q5 的压力场景」——Q5 原文在文档里只有引用、查无正文，本条即现场补上的结论。
> 状态：**草稿**。落《落地进度与待议》前等用户拍板。

## 结论

1. **普通单聊里用户 @ 智能体 → 升级成群**，不拒绝、不临时答一句。
   - 直接拒绝：顶死 §6.6b 规则 5（用户拉 = 参与者）。
   - 临时答一句：是「角色拉 = 子代理」的语义（第三方看不到完整上下文、用完即散），按到用户头上张冠李戴。
2. **群类型跟随原会话形态**：
   - 普通单聊 → 普通群，agent 以 **Chat 形态**入座（ADR 0050 决策 3：不写文件、不欠工作区账）。
   - 反向（智能体单聊 @ 普通角色）→ 智能体群，普通角色本就可混装。
   - 升级那一刻若真图 agent 开 harness 干活落盘，选智能体群即绑工作区；**最小版默认跟随形态**，选项后面再补。
3. **历史怎么进新成员（一方通行补的口子）**：升级那一刻默认 **`summary`**、`full` 显式可选、**`none` 排除**。
   - `none`：等于把口子堵回去——参与者是要看历史的（§6.6b）。
   - `full`：几百条私房话全量灌入，贵且没必要；显式选项留给需要的场合。
   - 默认 `summary` 与 §6.9 / ADR 0046「中途入群」同一套策略，不发明新机制。
4. **B（被拉进来的智能体）不翻原单聊流水**：
   - B 在普通群是 Chat 形态，无工具、无工作区，产物路径对他不可达——「翻」是空话。
   - 用户全知铁律只管用户；B 是成员不是用户，原流水不给他开。与 ADR 0050 不冲突。
   - B 手上只有那条摘要，不够**当面问**（live 问走正文，普通角色本来就走正文，不用新机制）。
5. **摘要由系统自动附（近期摘要 + 相关产物路径），不让 A 转述**（v3 补漏口径）——B 的信息源就这一条，质量要卡死。

## 实现时要注意（与发言引用的两处核对）

- ~~「同 ADR 0048 一个 builder 生成」~~ —— 核对后修正：ADR 0048 的 builder 是 `GroupTranscript.BuildScene`，生成的是**群场景段**（群名 + 名单 + 主持人 + 群协议），不是摘要。摘要的现成机制是**交接文档**（0037/0038：上下文快满时让当前模型把对话写成交接文档），落实现时从交接文档那条线取，别绑到 BuildScene。
- A（原单聊里的普通角色）无工具，转述会渗隐私且质量不可靠，故摘要走系统自动附，不让 A 写。
