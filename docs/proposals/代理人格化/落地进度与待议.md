## 明天第一件事：一个卡住的选择

角色身份轴（`IsAgent`）现在由**编辑页的一个开关**设置。用户的疑问是「这个区分该不该摆在编辑页」，
因为对话页左栏已经有 `普通对话 | 智能体` 切换器。两种读法：

- **A. 开关留在编辑页，只是别摆重** —— 用户平时不碰它，感知类型靠对话页切换器
- **B. 开关从编辑页拿掉**，身份由「在哪一侧新建的角色」决定

**倾向 A**，理由：身份是角色自己的属性，不是它被创建时所处上下文的属性。
B 之下「建错地方了想改成 agent」没有出口，只能删了重建，而角色卡上挂着提示词、开场白、图标一堆东西。

> 顺带一个已核实的事实，可能正是这个疑问的由来：对话页左栏的归属判定走
> `SessionListModel.BelongsHere` → `IsChat()` / `IsAgent()`，**已经完全由 `IsAgent` 这一个 bool 决定**。
> 所以「切换器那侧的区分」本来就是这个开关的下游——两者不是二选一，是同一根轴的两个露头。

### ADR 0044 做了什么

三把工具 `RunAgent` / `RunReadOnlyAgent` / `ContinueAgent` → **一把 `SendMessage(to, content, role?, model?)`**。
`to` 自己分流：人名 → 新开一次；`[sub-session: …]` 编号 → 续上那一次；留空 → 默认对象。
收件人名单从**工具 description** 挪进**系统提示的委派一节**（`ToolDisciplineFacts.DelegationRoster`），
于是工具定义在一次会话内恒定不变。政策正文整段改写成对话心智（不再有 run / task / 派活 / 选哪一档）。

**骨架一行没动**：`ParentSessionId`、后续报告、唤醒轮、`SessionRunRegistry` 原样。

存量按**就地封存**处理（不是退役）：`ESubAgentType`、`SubAgentProfile.Explorer`、
`ExploreSubAgent` 卡、`ExplorerSubAgentModelName` 全部保留并在注释里标明「仅为重建存量」——
真删会让老的只读子会话重建后**变成可写**、或者**打不开**。只真删了设置页那个已经不起作用的选择器。

### ADR 0043 阶段 1 做了什么

`CharacterData` 的存储轴换成 `IsAgent` + `IsUserCard` 两个 bool；
`Kind` 降级为 `[JsonIgnore]` 的**派生只读投影**（永不产出 `Tool`）。

> **这个投影是 churn 小的关键**：约 35 个读取点一行没动，编译器只报出了写入点（生产代码只有 4 处）。

- 扮演与工具人在徽章、筛选、排序、头像、编辑表单五处合并
- 16 张内置卡的 JSON 就地改写
- 翻译下拉判据换成「不是 agent、不是用户卡、**没有开场白**、**没开注入用户卡**」
  ——把档位这个代理指标换成它本来在代理的那个属性
- 迁移靠 `CharacterData.LegacyKind`：`[JsonPropertyName("Kind")]` 的**只写属性**，
  老存档的 `"Kind": "Agent"` 进来即映射到新轴，只有 setter 所以不参与序列化。
  **为什么需要**：`SaveDefaultCharacterDataPath` 下可能有用户改过的内置卡副本，那些文件不在仓库里。
  有测试钉住往返与迁移两头（`IdentityAxis_RoundTrips_AndLegacyKindStillMigrates`）

## 本轮推翻了 v5 的三处结论（都基于事实错误）

会审的价值主要在这里，别把它们当成"又改主意了"：

1. **§2.6③ 删权限档** → **撤销**。两个事实错误：现存权限档不是"预先拦"而是"问一句"
   （`ApprovalModeMapper` 只产出自动放行规则，工具照样挂载）；而它要接手的**撤销栈根本不存在**
   （只有 `FileBackupStore`，无账本、无回滚接口、备份失败不抛异常）。
   净效果是删掉一道在工作的护栏、换上一道不存在的
2. **§6.8 工具全量共享** → **撤销**。论据「增删工具会让所有共享该前缀的会话失效」是事实错误：
   **角色之间本来就不共享前缀**。而且删掉 `AgentToolConfig` 会让陪聊角色挂着 shell
3. **§3.3 隐式 Yield** → **不是待设计项**，现架构已实现（`HasPendingWork` + 唤醒轮），
   而且比方案写得好——方案那句「控制权留调度器」正是术语表警告过的坑

  （群的类型判定：普通群 / 智能体群、能否混装）

**需要用户拍板的**

- `CharacterKindRoleplay` 这个多语言串的值现在是「角色扮演」，用来指代合并后的两类偏窄，
  是否改成「角色」。（`Lang.resx` 两份文件里的一个 value 编辑，不新增 key、不用跑生成器）
- 三个没人引用的多语言键可清：`AgentSettingExplorerSubAgentModel` / `...Desc` / `CharacterKindTool`

**明确搁置的（不是忘了）**

- **`open_issues` 与 §6.2 的两个收敛信号**。重开时**先答「谁产出」再动手**——
  默认最省事的那条路（让初春维护）正是 §2.4 亲手砍掉的控制量
- **群成员开子代理**（v5 §6.4）：群成员是 peer 在第 0 层，他们开的子代理在第 1 层，
  **不撞**现有的"不许递归"不变量。可做，优先级最低
- **`CreateAgent` 原语**：不做。临时职责用 `SendMessage` 的 `role` 参数；持久角色由用户建。
  仓库里有现成证据——`SubAgentTool.Create` 的注释记着「曾经有过自定义子代理提示词参数，
  实测本地模型往里填的是泛泛套话」，那就是 `CreateAgent` 的缩小版实验，结论是删掉

**没写进术语表，是刻意的**

`docs/CONTEXT.md` 本轮**一个字没动**。它通篇是「体现为 `<类型名>`」的代码地图，
而这批新词（黑板、群成员 peer、开场读取）描述的东西还不存在，写进去术语表就开始说谎。
**等实现落地再补**，词条清单在对应 ADR 里。

## 给接手者的几个坑

- **`dotnet test` 在本仓测不出结果**（0 通过不代表测试真过了）。判成败看
  `dotnet msbuild <csproj> -t:Test` 的输出，且要核对「总计」不是 0
- 政策提示词正文里**反引号只能包工具名**，有不变量测试钉着
  （`MainAgentInstructions_BacktickNamesMustBeKnownTools`）。给参数名加反引号会红
- 提交信息**只写一句话**，无正文、无尾注
