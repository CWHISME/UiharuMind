## 问题一：MEAI 逐块序列化 choices（上次「问题五」的根）

分配追踪按「第一个本仓帧」归类，`LazyChatClient.StreamOnceAsync` 582MB、`SseSanitizingStream.ReadAsync` 382MB 排前二，
往下拆是同一条路径（后者是 SDK 的续体同步跑在我们的 `ReadAsync` 帧里，被算到了我们头上）：

```
OpenAIChatClient.FromOpenAIStreamingChatCompletionAsync
  → TryGetReasoningContent → JsonPatch.TryGetJson("$.choices")
  → StreamingChatCompletionUpdate.PropagateGet → TryResolveChoicesArray
  → JsonCollectionWriter.WriteEnumerable → UnsafeBufferSequence.GetMemory   （Byte[] 422MB + ReaderInstance 295MB）
```

`Microsoft.Extensions.AI.OpenAI` 10.10.0 的 `TryGetReasoningContent` 注释写明是 openai-dotnet #1281 的变通：
每个流式块都把 SDK 认识的 `choices` 整个序列化成 JSON 再 `JsonDocument.Parse`，只为读一个 `reasoning_content`。
不管模型带不带思考，每块都付这笔钱，而每次都新借一个缓冲段。

可选的处理（都没做）：
- 先查 MEAI / OpenAI 新版本是否已修 #1281、去掉这层变通；升级是最省的。
- 否则自己接一层流式适配：OpenAI 兼容端点的 SSE 本来就过 `SseSanitizingStream`，`reasoning_content` 可以在那里取出，
  不经 MEAI 的这段转换。改动面大，要单独议。

其余本仓分配都在 75MB 以内：`SaveUtility.Save` 73MB、`OpenAICompatibleRequestRewriter.Rewrite` 73MB（每次调用一次，`7bc91d5b` 之后不再随重试放大）、
`OpenAiCompatibleResponseFixer.FixJson` 43MB、`HistoryJsonl.SerializeLines` 37MB、请求日志的 `Prettify` 36MB。

## 问题二：429 与饥饿

段 3 一次调用连撞 13 次。成员各自退避、互不知情，这正是之前搁置的「共享节流」要解的公平性问题。
上次的判断是「性能上已无必要」，这次的数据仍支持：内存与 GC 暂停都看不出 429 的代价；剩下的是**等待时长不均**。
要做的话，按商定的设计：按端点 + 密钥 + 模型 ID 分组、管发送间隔（撞了翻倍、成功缩短、缩到 0 撤闸）、被打回的回队首。

## 问题三：用户不在时的空转

成员按工作区规矩把「拍板」留给用户。用户不在，每人说一句「等他回来拍，我不催」，就收住这一波。
「继续」本身不空转（没人有新话时一波 6 秒就结束），空转的是那几句「等」。

建议加一个**代拍位**（与 ADR 0049 的主持人并列）：
- 一波跑完、流水里还有留给用户的未决格时才叫醒它。
- 用户事先写一次授权范围（如「设计取舍可代拍、可提交；推送、删文件、改 `RawDoc/` 不行」），超出范围就停下通知用户。
- 拍之前先核实成员报的读数与 diff，⛔ 不按多数意见盖章。这次代拍时，就是自己跑回归才发现注释与谓词自相矛盾。
- 每次代拍都留痕、可推翻。

要动调度与提示词，补一条 ADR 再做。（已做成「离席 / 化身」，见 [ADR 0055](../adr/0055-离席由化身值守，对成员就是用户本人.md)：`6719678f`；授权范围 `329c7382`。）

## 跑测时踩到的事

- 工作区仓库有别人的暂存改动时，成员的 `git commit` 会把它们一起带走。开跑前先把暂存区清掉（这次是先替用户提交成一条）。
- 开发脚本是启动期一次性的，中途插不进话；要分段，每段一个进程。
- `dotnet-script` 在只装了 .NET 10 的机器上要 `DOTNET_ROLL_FORWARD=Major`。
- 启动脚本挂在测试端后台任务下时，后台任务的时长上限就是应用的寿命；离席时限要留出启动与收尾的余量（这次定 ≤ 100 分钟）。
- 关键的改代码块别派给在这类活上读个没完的模型；在离席目标里写一句就够，主持人会照着排。

dotnet-trace collect -p <pid> --providers "Microsoft-Windows-DotNETRuntime:0x8001:5" --duration 00:00:04:00 -o alloc.nettrace
# 按类型、按第一个本仓帧汇总：TraceEvent 的 TraceLog.CreateFromEventPipeDataFile，遍历 GCAllocationTickTraceData 的 CallStack()
