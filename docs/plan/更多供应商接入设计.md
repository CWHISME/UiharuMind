# 「更多供应商」接入设计

> 状态：**已落地**（2026-10-31，数据层 + 界面层）。收尾项见 §七。
> 需求：`CreateRemoteLlmModelWindow` 里，右侧表单顶部加一个「更多供应商」条目——左侧显示供应商名，
> 右侧按钮点开一个**可搜索**的 models.dev 供应商选择器（交互同 `CharacterPickerView`）；
> 选中后该页直接显示这家供应商的信息，表现与点左侧其它供应商一致。
>
> **第二版**：models.dev 数据改为**运行时拉取 + 磁盘缓存 + 按需刷新**，不再往源码里生成表。
> 落地时补 ADR 0103，取代 [ADR 0097](../../Docs/adr/0097-模型能力表扩项：价格与思考档位进表，视觉改推导加覆盖.md)
> 决定 1 里关于 models.dev 的那半（官网抓取那半继续留在构建期）。

## 一、位置：右栏顶部的「供应商身份条」

不是表单里的一个字段，而是贴在滚动区**之上**、不随内容滚动的一条 36px 身份条，**只在「自定义配置」这一档出现**：

```
┌───────────────────────────────────────────────┐
│ ● 自定义配置  [自定义]          更多供应商 ›  │  36px，浅底 + 下边框
├───────────────────────────────────────────────┤
│ 密钥                                          │  ← 表单从这里开始，滚动只滚下面
│ [粘贴你的 API Key]                            │
```

选过一家之后：`● Groq [models.dev] …… 换一家 ›`。预设供应商（Agnes/DeepSeek/…）**不出这条**——
左侧列表已经高亮，再加一条就是同一件事说两遍。

**为什么不做成表单字段**（即直接在那块空白处放一个 ComboBox）：

1. 它会和「密钥」「模型名称」同列同间距，读起来是"先填供应商再填密钥"的流程；实际一改就重置整张表单，填到一半点它全丢。
2. 表单是长滚动区，滚两屏它就没了——"我在配哪家"应该始终可见。
3. 左侧选中态已经是同一个事实，两个控件说一件事。

## 二、数据：运行时快照，三层覆盖

### 实测（2026-10-31）

| 项 | 数字 |
|---|---|
| `https://models.dev/api.json` 原始 | 5.69 MB / 235 家 / 8938 个模型 |
| 只留我们用到的字段（投影） | **1.72 MB**（估算时按短字段名算的 1.0 MB，实际用可读字段名） |
| 过滤 + 补 SDK 默认地址后可用 | **216 家 / 7443 个模型** |
| 投影耗时（读 5.7 MB + 解析 + 建索引） | **约 330 ms**，放后台线程，不挡界面 |
| 传输 | 支持 brotli（线上约 500 KB）；带 `ETag`，可走 304 条件请求 |
| 现有静态表 | 94 KB 源码 / 893 行 / 7 家 |

**一个必须知道的坑**：models.dev 只在「地址由各家自己配」时才写 `api` 字段。地址被编进 SDK 包的
（`@ai-sdk/openai` / `@ai-sdk/groq` / `@ai-sdk/anthropic` / `@ai-sdk/google` / `@ai-sdk/xai` …）
这个字段是空的——按「有 `api` 才收」一刀切，**OpenAI / Anthropic / Google / Groq / xAI / Mistral / Cerebras
会全部消失**，功能看起来就是坏的。所以加一张按 **SDK 包名**（不是按供应商）的小表补默认基址，
11 条，见 `SdkEndpointFallbacks`。Azure / Bedrock / Vertex 这种地址里带账户的一律不收——
猜一个错的地址比不给更糟。

### 三层数据，各管一段

```
ProviderPricingTable.g.cs   构建期抓官网，人工核对，最权威      94 行  → 保留（不运行时抓 HTML）
        ↓ 覆盖
运行时快照（models.dev 最新）  7144 模型 / 205 家，可刷新       Cache/ModelsDev/snapshot.json
        ↓ 兜底
ModelCapabilityTable.g.cs   现有静态表，离线也能判视觉         893 行  → 保留，不再扩
```

**为什么静态表不删**：视觉是 `bool`，没有「未知」这一档。纯动态化后，首次启动且没网时
`ResolveVision` 会一路判 false——这正是 ADR 0097 里「图片发不出去」那个 bug 的成因。
保留 94 KB 换一个离线兜底，比省这 94 KB 划算得多。

**为什么官网那层留在构建期**：ADR 0097 决定 2 的理由仍然成立——运行时抓 HTML，对端一改版就是静默错误；
而 models.dev 是 JSON API，有 ETag、有 schema，风险低一个量级。

### 缓存布局与刷新：按需，不设 TTL

```
<UIHARU_HOME>/Cache/ModelsDev/snapshot.json
  { "schemaVersion": 1, "fetchedAt": "...", "etag": "...", "providers": { ... } }
```

- 放 `Cache` 不放 `Data`：语义就是「可再生、用户可随手删」（与 `ModelCatalogs` 一致），删了下次自动重拉。
- `schemaVersion` 变了直接丢弃旧文件，避免投影字段调整后读到错位的旧结构。

**读缓存与联网是两件事，必须分开**：

| 动作 | 时机 | 联网 |
|---|---|---|
| 读本地快照 | **应用启动时一次**（后台，约 30ms，失败静默） | 否 |
| 联网拉取 | 打开模型窗口且**本地为空**；或用户点「刷新」 | 是 |

为什么读缓存不能也拖到打开窗口时：`ResolveVision` 在**发消息时**也要被调用（决定要不要丢图），
那时用户可能几个月没开过模型窗口。只在窗口里读，运行时就永远拿不到动态数据，
非预设家会一路落到 canonical 兜底。启动只读本地文件，既保住「启动零网络」，又让运行时始终有最新缓存。

**不设 TTL、不做后台定时刷新**：

- 联网只发生在「打开窗口发现本地为空」和「手动刷新」两处，用户点得到、看得见。
- 手动刷新走条件请求（带 `ETag`），`304` 只更新 `fetchedAt`，几乎零成本——所以「多刷几次」不心疼。
- 数据年龄永远显示在弹层底部（`205 家 · 3 天前更新`）；超过 30 天换成提示色文案（`3 个月前更新 · 建议刷新`），
  陈旧是**看得见**的，而不是靠定时器偷偷修。
- 两个窗口同时打开时的拉取做单飞（同一时刻只有一个请求），失败不自动重试，只在弹层给「重试」。

### 快照的内存形态

一次性解析成不可变对象，`volatile` 换引用（读侧无锁，UI 线程直接读）：

- `Providers`：205 条元数据（id / 名称 / 接口地址 / 官网 / npm / 模型数），约 20 KB。
- `Models`：`(providerId, modelId) → Capability`，7144 条，约 1.5 MB。
- `Canonical`：`canonical_model_id → (视觉, 上下文, 输出预算)`。

## 三、决策

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| D1 | models.dev 数据**运行时拉取**，投影后落 `Cache/ModelsDev/snapshot.json`；**按需刷新**（打开窗口发现为空 / 手动点刷新），不设 TTL、不做定时 | 代码量不再随供应商增长；数据随时可新；删除缓存无副作用；启动零网络 | 首次/离线要兜底（D2）；用户不点刷新就会一直是旧数据（见 §九） |
| D2 | **静态表保留**，降级为离线兜底；**不扩**到 7144 个模型 | 视觉是 bool，空表 = 全部误判 false = 丢图（ADR 0097 原案）；94 KB 换这个兜底很值 | 代码量不变小，只是不再变大 |
| D3 | 官网价格表 `ProviderPricingTable.g.cs` 继续构建期生成 | HTML 抓取不适合运行时，ADR 0097 决定 2 仍成立 | 仍需发版前跑一次脚本（只跑官网那支） |
| D4 | **不新增配置类型**，落 `RemoteModelConfig` + 新持久化字段 `CatalogProviderKey` | 任意供应商的差异只有「地址 + 目录 + 官网」，没有家特有 header/思考格式；现有 7 家已是 7 个空壳类。AGENTS 的「继承还是组合」这里选**组合**：供应商是数据，不是类型 | `ProviderId`（票据门禁）对所有自定义配置都叫 `RemoteModelConfig` |
| D5 | providerKey 口径从「类型」改到「实例」：`ProviderKeyOf(config)` = 实例键，空则回落类型映射 | 不改这条，从 models.dev 选的供应商价格/档位永远空白 | 4 个按实例的重载 + 编辑窗口 2 处调用点 |
| D6 | 选到**已有预设**的供应商（deepseek / openrouter / zhipuai …）不建自定义配置，直接把左侧选中切到那家预设行 | 否则同一家出现两条路，预设那份还带家特有逻辑 | 需要反向映射 `providerKey → Type`（从 `RemoteModelConfigRegistry` 现取，不再生成） |
| D7 | 只列能用 HTTP 直接打的家：有 `api`，或 SDK 包名在 `SdkEndpointFallbacks` 里；地址带 `${` 的一律不收。`npm` 含 `anthropic` 按 Messages 线预填，其余 ChatCompletions | 模板地址（按账户拼）填进去必挂；azure / bedrock / vertex 的地址带账户，猜一个错的比不给更糟 | 少数家被滤掉，可手输兜底 |
| D8 | 入口做成**身份条**，不做成表单字段；只出现在「自定义配置」 | 见 §一 | 多 36px 竖向空间；切换会清空表单，见 §八 |
| D9 | 补一张 **11 条**的 SDK 默认地址表（`SdkEndpointFallbacks`），按 npm 包名而不是按供应商 | models.dev 不给 openai / anthropic / google / groq / xai / mistral / cerebras 写 `api`（地址编在 SDK 里），不补就等于把最常用的几家全滤掉 | 唯一一处手写端点数据，需要能说出官方出处；同包的新供应商自动受益 |

**顺带的收益**：现在「加一家供应商」要改三处（`RemoteModelConfigRegistry.Entries`、
生成器的 `PROVIDERS`、生成器的 `PROVIDER_TYPES`）。动态化后只剩 Registry 一处——
providerKey 与配置类型的映射写在 Registry 里，不再是生成物。

**D8 还简化了实现**：左侧列表保持 8 行不动，不在 `ListBox` 项模板里塞按钮、不动态合成/替换列表项，
`Providers.Count == 8` 的既有测试不用改。

## 四、接口

Core 新增（`RemoteOpenAI/ModelCatalog/`）：

```csharp
/// 一家供应商的接入信息
public sealed record RemoteProviderInfo(string Id, string Name, string ApiBaseUrl, string DocUrl, string Npm, int ModelCount)
{
    /// 该家默认走哪条线：anthropic 系走 Messages，其余 ChatCompletions
    public EApiFormat ApiFormat => Npm.Contains("anthropic", StringComparison.OrdinalIgnoreCase)
        ? EApiFormat.Messages : EApiFormat.ChatCompletions;

    /// 模型目录地址（/models）
    public string CatalogUrl => ApiBaseUrl.TrimEnd('/') + "/models";
}

/// 不可变快照：换引用即更新，读侧无锁
public sealed class ModelsDevSnapshot
{
    public IReadOnlyList<RemoteProviderInfo> Providers { get; }
    public bool TryGetCapability(string providerId, string modelId, out ModelCapabilityTable.Capability capability);
    public bool TryGetCanonical(string modelId, out ModelCapabilityTable.Canonical canonical);
    public static ModelsDevSnapshot Empty { get; }
}

/// 运行时数据源：读本地缓存、按需联网、手动刷新
public sealed class ModelsDevCatalog
{
    public static ModelsDevCatalog Instance { get; }
    public ModelsDevSnapshot Current { get; }        // 空快照 = 全未知，不抛异常
    public DateTimeOffset? FetchedAt { get; }
    public event EventHandler? Changed;              // 快照换代（界面据此重查）
    public Task LoadCacheAsync();                    // 启动时一次：只读本地文件，不联网
    public Task<bool> EnsureAsync();                 // 本地为空才联网；有数据直接返回，单飞
    public Task<bool> RefreshAsync();                // 手动刷新：无条件条件请求（带 ETag）
}
```

`BaseRemoteModelConfig` 增加一个序列化字段（`[SettingConfigIgnoreDisplay]`）：

```csharp
/// models.dev 供应商键：经「更多供应商」选中时写入；空表示没有（自定义/预设）
public virtual string CatalogProviderKey { get; set; } = "";
```

查询层保持现有形状，只换数据来源——`ModelCapabilityTable.TryGet/TryGetCanonical` 内部先问快照、再问静态表，
所以 `ModelCapabilityResolver` 与 `ModelCatalogCapabilities` 的调用点一行不用改，只加 `ProviderKeyOf(config)`：

```csharp
public static string ProviderKeyOf(BaseRemoteModelConfig config) =>
    config.CatalogProviderKey.Length > 0 ? config.CatalogProviderKey
        : ModelCapabilityTable.ProviderKeyOf(config.GetType());
```

## 六、交互流程

1. 应用启动 → 后台读一次本地 `snapshot.json`（不联网）。有缓存则 `Current` 立刻可用，运行时能力查询照常。
2. 打开创建/编辑模型窗口 → 若 `Current` 为空，后台 `EnsureAsync()` 拉一次（单飞，失败静默）；表单不等它。
3. 选中「自定义配置」→ 身份条出现：`● 自定义配置 [自定义]` + 右侧「更多供应商 ›」。
4. 点按钮 → 弹层。快照已就绪直接出列表；未就绪则显示加载态（此时 `EnsureAsync` 正在进行或刚失败）。
5. 选中一家：
   - 命中预设（D6）→ 左侧选中切到那家预设行，身份条消失，走原路径；
   - 其余 → `CatalogProvider = 它`，草稿 `ModelPath = ApiBaseUrl`、`ApiFormat = ApiFormat`、
     `CatalogUrlText = CatalogUrl`（顺带触发一次目录拉取，符合 ADR 0092 的「有缓存不拉网络」），
     `CatalogProviderKey = id`。身份条变成 `● Groq [models.dev]` + 「换一家 ›」。
6. 表单其余部分一个字不改：仍是自定义配置的平铺表单，只是接口地址、目录地址、官网按钮已就位。
7. 确认 → `BuildResult` 把 `CatalogProviderKey` 写进 config。
8. 编辑模式：左侧列表禁用，身份条**只读显示**（有 key 就显示那家名 + 徽章，无按钮）。

**一处与原方案不同的实现**：没有改 `ModelCapabilityTable.g.cs`（生成物，下次重新生成就没了），
而是新加 `ModelCapabilitySource` 作为能力查询的唯一入口，由它做「快照 → 静态表」的分层。
`ModelCapabilityResolver` 与 `ModelCatalogCapabilities` 里 7 处调用点改成问它，生成器一行不用动。

**三处与原方案不同的实现**：

1. **选择器不订阅 `Changed`**。选择器一次开窗建一个，订阅进程级单例的事件会把它永久钉住（内存泄漏）。
   别人的刷新不影响这里——下次打开 `BeginAsync` 就重建了。代价：正在编辑的窗口点「刷新」后，
   已经拉出来的模型候选价格不会立刻变，得重开窗口。
2. **换一家的确认放在「选中」而不是「打开弹层」**。`HasProviderSwitchContent`（key / 模型 ID / 地址任一非空）
   为真且选的是另一家时，走 `IMessageService.ConfirmAsync` 问一句再应用——只在真会丢东西时拦。
3. **选中供应商不立刻拉目录**。地址填进去了，但此刻 key 还是空的，多数家 `/models` 要鉴权——
   自动拉必然失败，表单上会当场红一条「拉取失败」，看起来像坏了。改为用户填完 key 点「拉取」。

分三步走，每步都能单独上线：

1. ~~**数据层**：`ModelsDevCatalog` + 快照 + 缓存 + 启动只读缓存~~（已完成）
2. ~~**界面层**：身份条 + 选择器弹层 + `CatalogProviderKey` 持久化 + `ProviderKeyOf(config)`~~（已完成）
3. ~~**收尾**：删生成器里 models.dev 那支的硬编码~~（已完成）。

**刷新入口放哪儿**（定案）：**不放设置页**——那是「改一次就不动」的地方，而模型数据是会变的运行时缓存，
而且藏在二级页里没人找得到。

先分清两个「刷新」，它们刷的不是一回事：

| 入口 | 位置 | 刷什么 |
|---|---|---|
| 「拉取」 | 创建模型窗口 · 模型 ID 那一行 | 这家供应商的 `/v1/models`——**新模型从这儿来**（ADR 0092，一直有） |
| 「刷新」 | 创建模型窗口 · 供应商弹层底部 | models.dev 的能力/价格数据 |
| 刷新图标 | 模型页 · 页签行右端 | 同上，常驻 |

**模型页入口已否决**（2026-10-31，实测后撤回）。先加过「页签行常驻刷新图标 + 过期横幅」，实现完看实际界面：

- 页签行右端本来就压着「整机余量」读数，再塞一个图标，那一行显得挤且空（图标与读数之间留白突兀）。
- 真要用的时候（价格是空的、某家供应商找不到）人在创建模型窗口里，不在模型页——模型页显示的
  视觉徽标与上下文是**现算**的，刷新了已渲染的行也不会重绑，按下去像点了个死按钮。
- 结论：入口就留在**创建模型窗口**（模型 ID 行的「拉取」+ 供应商弹层的「刷新」），模型页保持原样。

**目录拉取失败要说原因**：原实现只显示一句「模型目录拉取失败」，401 与超时在用户眼里没区别，
但处置完全不同（填密钥 vs 重试）。现在带上状态码与下一步：
`模型目录拉取失败，仍可手动输入模型 ID。 401 Unauthorized · 请先填写密钥`
（已填密钥时是「密钥可能无效或无权限」，超时单独一句，连不上则带异常原文）。

## 八、待确认

1. **陈旧提示阈值**：数据年龄超过 30 天换提示色（本文），要不要再加一句「建议刷新」的按钮强调。

## 九、风险

- **首次离线**：静态表兜住 7 家预设的视觉判定；其它家落到 canonical（同样来自静态表）。真·全新安装 + 无网 + 非预设家，视觉会判 false，用户可勾复选框覆盖，联网后自愈。
- **数据陈旧无人管**：不设 TTL 就意味着「用户不点刷新就一直是旧的」。缓解手段是把年龄摆在弹层底部（超过 30 天变色），让陈旧可见——但一个从不打开弹层的用户永远看不到。这是放弃定时刷新换来确定性的代价。
- **快照换代后界面不刷新**：`Changed` 事件要接进编辑窗口与模型列表。按需刷新的好处是换代只发生在用户主动点「刷新」时，触发点少、范围小。
- 切换供应商会重置表单（选中路径本来就这么走）。用「换一家」措辞 + 有内容时的一次确认来兜。
- 部分家的目录不是 `api + /models`（要 key 才 200，或路径不同）：拉取失败亮红字提示，地址可手改。
- 205 家里大量转售商同名不同 id：按 id 认，不按名字认。
- 测试要改：`ModelCapabilityResolverTests` / `ModelCatalogCapabilitiesTests` 现在拿真实模型 ID 当锚点，
  改成注入固定快照（`ModelsDevCatalog` 留一个 `internal Install(snapshot)` 测试钩子）+ 小 fixture，
  否则断言会随 models.dev 数据漂移。
- `CatalogProviderKey` 是新增序列化字段：旧存档读出来是空串，行为与今天一致，不需要迁移。
