# 探针脚本

**探针**是一次性的实测脚本：拿真实请求/响应去量一个说不清的行为，
把结论写进 ADR 或代码注释，然后把脚本留下——下次再遇到同类问题，
跑一遍比重新想一遍快。

它们不是产品代码，不参与构建，不被测试覆盖。

## 与 `perf/` 的区别

`perf/` 是**长期工具**：`cache-audit.py` 每次改动缓存相关代码后都能再跑一遍，
看前缀稳不稳、命中率高不高。它读日志、不发请求、没有参数化的实验设计。

`probe/` 是**一次性实验**：为了回答一个具体问题而写的那几个脚本。
问题答完，结论落进文档，脚本留下备查。

两者常配合：探针先用真实请求体量出「命中形态是什么」，
`cache-audit.py` 再用同一套口径体检全量日志。

## 目录

按**被测对象**分主题，不按时间分：

```
probe/
  cache/       前缀缓存：命中形态、抖动来源、缓存键、TTL、路由
  reasoning/   思考票据：reasoning_details 的形态与回放可行性
```

新主题加新目录。同一个脚本只归一个地方——按它**回答什么问题**分，
不按它顺手用了什么分。

`probe/` 下的脚本共用 `perf/cache-audit.py` 解析日志里的请求体，
从子目录加载时路径是 `../../perf/cache-audit.py`。

## 怎么写

**密钥只从环境变量读，绝不落盘、绝不进日志、绝不写进代码。**

```python
KEY = os.environ.get("CMD_API_KEY")          # 必需
MODEL = os.environ.get("CMD_MODEL", "")       # 模型 id 不给默认值
BASE = os.environ.get("CMD_BASE", "https://…")
```

模型 id **不给默认值**：脚本必须显式传（位置参数或环境变量），
漏传就明确报错，不要静默发一个必然失败的请求。

不要把密钥、账号标识、内部模型 id 写进脚本或文档。探针的结论要能公开，
所以模型用泛称（「某个闭源模型」），不写具体 id。

## 怎么跑

```bash
CMD_API_KEY=... CMD_MODEL=<模型id> python3 src/scripts/probe/cache/ttl-probe.py
CMD_API_KEY=... python3 src/scripts/probe/reasoning/commandcode-reasoning.py <模型id> --only=2,3
```

`--only=<步号>` 可以只跑指定的步骤——其余步骤已量过时不必重复消耗配额。

**探测会花钱。** 贵模型上先跑最小的那几步，别一上来就跑全套。

## 结论要落到哪里

量出来的结论**不能只留在脚本输出里**。要么写进代码注释（行为变了），
要么写进 ADR（设计变了）。脚本是证据，文档才是结论。

`cache/` 这批脚本的结论在 [ADR 0100](../../../docs/adr/0100-加密思考票据按消息各挂各的，随消息落盘，收成协议无关的思考模块.md)
与 [Responses 协议接入计划](../../../docs/plan/Responses协议接入计划.md) 里；
`reasoning/` 那批在同一份 ADR 的背景一节。
